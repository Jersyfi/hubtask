The point is not to restrict use of the software. It is to keep "Hubtask" meaning one thing,
so that a user who downloads something called Hubtask knows where it came from.

## What you may do without asking

* State truthfully that your product works with, integrates with, or is built on Hubtask.
* Use the name in prose to refer to this project — in articles, talks, tutorials, comparisons,
  and academic work.
* Use the name in a package, repository, or account name that clearly identifies a third-party
  addition, in the form `hubtask-<something>` or `<something>-for-hubtask`. For example,
  `hubtask-cli-completions`.
* Reproduce the logo unmodified when referring to the project, at a size and placement that does
  not suggest endorsement.

## What needs written permission

* Using "Hubtask" as the name, or as part of the name, of a **fork** or of a modified
  distribution. Fork the code freely — the licence allows it — but give the result your own name.
* Using the name or logo for a commercial offering, a hosted service, or paid support.
* Using the name or logo in a way that suggests affiliation, sponsorship, or endorsement.
* Registering domain names, social media handles, or trademarks containing "Hubtask".
* Modifying the logo, or using it as part of another mark.

## Container images and releases

Official builds are published only from this project's own registry and release workflow.
Images or binaries from any other source are not official Hubtask releases, regardless of what
they are named.

## Requests

Send requests to licensing@hubtask.eu. Permission for non-commercial and community uses is
generally given, and given quickly.
