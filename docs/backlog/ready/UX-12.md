**Task:** UX-12 · issue #1644 · `docs/backlog/milestone-UX.md`

**Verdict:** ready

The rule is decided (#1619–#1622, #1631; ADR-0087; UC-WRK-25; UC-WRK-23's story: "an entry is a
title and an amount, nothing else is offered"). UX-09 (#1668, merged as `5f2562f02`) left two
questions to this task: where an amount lives, and how a category is carried when *List* offers no
labels (UX-09's record, D9). This record answers both with the least contract change that still
works offline: **an amount is a capability and a field of the entry** (D2), and **a category is a
label the collection names in its own `fields` setting, in order** (D3). Everything else is the
client: the capture line, the *Done* and *Recently* sections, grouping, one tap, a hold and a swipe.
The head's figure (check 7) is UX-24's; this task depends on UX-24 for it (coordinator,
2026-10-21) and proves it last (D9).

## 3. Decisions

- [x] D1 The rule — decided by: owner, #1619–#1622, #1631 → UC-WRK-25, UC-WRK-23 (story), ADR-0087.
- [x] D2 **An amount is the capability `AMOUNT` and a field of the entry**, `amount` (text, trimmed, NFC, 1–40 code points, no control character; `""`, `null` or only spaces is no amount and clears one; no unit parsed or stored separately; never summed). The system matrix offers it to `TASK` only — the one level *List* has; widening it to other types is a later migration when a check asks. It is **opt-in**: Hubtask's default and a type a layer leaves out of `fields` do not carry it ("today's behaviour", UX-09 D6); of Hubtask's presets only *List* names it, and `Presets.go`'s `all` stays without it, so *Project* and *Flow* are "the bound minus the opt-in capabilities". Reasons: a custom field's definition does not reach the replica and cannot be pushed (§ 1), so an amount typed offline into a new list would have no definition to be written under; a definition the *List* preset "brings" would have to be created per collection by every writer of a structure, a hub's and the workspace's included, which none of them does and a member capturing cannot (`STRUCTURE`); a person's own `amount` key of another kind would collide. A capability narrows and hides through the `fields` setting and UX-29's mark with no new mechanism, and `AMOUNT` is already a first-class capture token. Contract cost: one nullable field on three schemas; no enum. Rejected: a custom field definition brought by the preset (above); a `definitions` member inside `fields` (a second source of definitions beside `custom_field_definition`, with no identifier for `custom_field_refs`); keeping the amount in the title (check 2 says "not as part of the title"). — decided by: worker; delegated by UX-09's record (D9) and the coordinator's brief. `docs/architecture/domain-model.md` §2 gains the row and the opt-in rule.
- [x] D3 **A category is a label the collection names, in order, in `fields.<TYPE>.categories`** (label ids, at most 50, unique). Valid only beside `LABELS` in the same object, only on a collection's own layer (labels belong to a collection), and only with live labels of that collection — or ids this layer already stores, so that a label deleted and brought back by an undo (UX-16) keeps its place; checked in `SetContainerStructure` under RLS. The list groups open entries by the first category label each carries, in that order, the uncategorised last; other labels stay labels. A label deleted later leaves its id stored and is skipped by clients. Every builder of `LevelFields` named in § 1 carries `categories` (clone, compare, input, output, document), `Default` and the presets carry none, and `Clip` and `fixCapability` drop them when `LABELS` is clipped or locked away. No operation copies a collection; a moved collection keeps its labels and so its categories, and a restore keeps identifiers; a copy of a collection, when one is built, drops the ids that are not labels of its destination and reports them as I-W6 reports dropped references. Reasons: check 5 says "a label" and its *How to check* is the owner's; labels and containers reach the replica (§ 1); a lock on `fields` is per type and capability, so a workspace locking views does not freeze a shop's aisles. Because *List* offers no labels (UC-WRK-23 check 4), grouping is something a person switches on: one write turns `LABELS` on for the type and names the categories. Rejected: a `SELECT` custom field (not "a label"; definitions not in the replica); an order on the label itself (a new operation on every door and a migration, for an order that means nothing outside categories); `views` (a workspace lock on views would freeze categories). — decided by: worker; the undo and copy rules by the coordinator, 2026-10-21.
- [x] D4 **The *Done* section's name is `levels[].done_name`**: a person's content beside the level's own name, with the same rule (trimmed, NFC, 1–60 code points, hashed in the trail, never logged); without one the client shows its translated *Done*. Rejected: a ninth setting (UC-WRK-23 check 2 says eight); `views` (levels already hold the names a person gives, with their validation and hashing). — decided by: worker.
- [x] D5 **"Most often used" is how often the entry was completed**: `WorkItem.CompletionCount` beside `Completion` (not inside the struct, so `Reopened` keeps it by construction), column `completion_count integer NOT NULL DEFAULT 0`, contract `WorkItem.completion_count` (read-only), incremented by the completing statement on a real transition (the roll-up included), kept by a reopen, unchanged by a repeated completion (UC-WRK-04/5). Existing entries start at 0 (no backfill); ties break by `completed_at`, newest first. A mis-tap ticked and taken back counts once: the count measures ticks, and a tick undone is rare enough not to disturb a ranking. Rejected: counting history entries (the history does not travel, `offline-sync.md` §4.2, so *Recently* could not be ranked offline); a count per device (two phones would disagree). — decided by: worker; placement by the coordinator, 2026-10-21.
- [x] D6 **The simple arrangement** is how `EntryList` draws a list layout of a collection whose levels in force are one (`structure.levels` of length 1).
