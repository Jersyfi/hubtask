**(d)** Standing rules and traps:
- Rule 2: no new authorisation; the notice follows acts already authorised.
- Rule 3: the per-workspace read runs in the workspace's own transaction; the offered provider's
  removal opens one per workspace, never a switch inside one (known trap "a nested scope may not
  switch tenant").
- Rule 5, 7: the sender is a Detached worker with the job's deadline, as the other mail workers.
- Rule 8, 12 (P-12): the mail is message codes rendered in the person's locale.
- Rule 10: no address, provider subject or password in a log; the payload carries ids.
- Known trap "a write on a refusal path is rolled back with the refusal": the notice is queued only
  on the success path, inside the act's transaction — a refused act sends nothing, which is right.
- Known trap "writer copies miss a late field": `PasswordWriter` and `OidcWriter` gain a notifier;
  a wiring test in `cmd/server` proves every copy carries it.
- Known trap "a port can be written and never called": each door is proved through its use case.
- `SECURITY DEFINER` trap: no cross-workspace list is read; each workspace is read in its own scope.

## 3. Decisions

- [x] D1 One job kind, `notification.way_in_changed`, payload `{account_id, event, provider_id?,
  at}`, events `PASSWORD_CHANGED`, `PASSWORD_RESET`, `PROVIDER_CONNECTED`, `PROVIDER_DISCONNECTED`;
  its own kind and not a notification category, so no preference silences it — decided by: worker,
  following the reset and the opening notice (UC-NOT-03 *Where it ends*). Rejected: a new
  notification category (it would be switchable, or a second exception to `Suppressible`).
- [x] D2 Queued at the two choke points: `PasswordWriter.Write` (told which door: reset or change)
  and `OidcWriter.Connect` plus `settleAccount`'s existing-account branch; and in the two removals —
  decided by: worker, § 1.
- [x] D3 No notice for a first way in made by the person themselves on a never-active account
  (invitation redemption, activation by a provider, provisioning) — decided by: worker; ADR-0078 §6
  is about a change "nobody asked for" to an account that had a way in, and here the person is the
  one acting, for the first time. Rejected: mailing at every first credential (noise at every
  invitation).
- [x] D4 Without a mail server nothing is queued (the notifier is wired only when
  `cfg.Mail.Configured()`), as invitation links are — decided by: UC-ID-04 check 9 ("without a mail
  server it is only audited"). The existing reset and opening jobs keep their behaviour; that they
  dead-letter on such an installation is outside this task.
- [x] D5 The undo the mail names is what exists: for a password, *Forgot your password?* (ends every
  session) and telling the administrator; for a connected provider, changing the password and ending
  the sessions under *Profile → Security*, and asking the administrator to remove the connection;
  for a disconnected provider, *Forgot your password?* if it was the only way in — decided by:
  worker; no self-service disconnect exists (SC-37 adds connecting, not disconnecting).
- [x] D6 The offered provider's removal reads each workspace's connections in that workspace's own
  transaction and queues the notices there, then removes; the sender skips when the provider still
  exists, so a removal that failed after queuing sends nothing — decided by: worker; the
  alternative, a `SECURITY DEFINER` list of people across workspaces, is what known-traps.md forbids
  ("a number, never a list").
- [x] D7 The dedupe key is `event:account:at`, so two changes are two mails and a retried enqueue
  is one — decided by: worker.
- [x] D8 identity.md §6 is corrected (the invitation is not a door of `SetPassword`) and gains the
  notices; §21 I-1 is closed — decided by: correction, and the task.
- [x] D9 Out of scope, with the reason: a second factor armed, removed or replaced and recovery codes
  regenerated are not in ADR-0078 §6's list nor in UC-ID-04 check 9 or UC-ID-05 check 6 ("a password
  set through a reset, or a provider connected to or disconnected from the account"; "their password
  changed"); a second factor is a second proof, not a way in on its own, and adding these notices
  would widen what the use cases promise — the owner's to decide, so it stays a possible follow-up.
  A machine-side password reset does not exist (#1396); if it is built as a set-password link it
  goes through `PasswordWriter.Write` and is told like a reset. An administrator's new start password
  for a managed account cannot be mailed (no address): audited only, ADR-0078 §7.
- [x] D10 The offered provider's removal lists workspaces through `ListTenants` (`admin_tenants()`);
  on a managed database that answers none until #1494 is decided, and this task adds no workaround —
  decided by: the coordinator's review, #1494.
- [ ] O1 None for the owner. The UC-ID-10 *Where it ends* line is reported as #1507, not
  changed here.

## 4. Proof and steps

Proof:
- **Service tests** through each use case (not `Handler.Invoke`): change, reset, `PASSWORD_CHANGE`,
  the `LINK` step, the second-factor hand-on, SC-33's link and `settleAccount` each queue exactly one
  job with the right event; a refused act queues none; a managed account queues none; an unwired
  notifier queues none.
- **Sender test** (`SendWayInChanged`): renders the account's locale, names workspace, moment and
  provider, contains no secret (no token, no password, no subject identifier), skips without an
  address, skips a disconnect whose provider still exists.
- **Integration tests** (real PostgreSQL, real transactions): removing a workspace's provider queues
  one job per connected person and none for another workspace (cross-tenant negative); removing an
  offered provider queues them in each workspace's own scope.
- **Locales:** `SignInMail_test.go` holds the new keys in `en` and `de`.
- **Wiring:** a `cmd/server` test that the password and provider writers carry the notifier when mail
  is configured, and none when it is not.

Steps:
1. This record.
2. The notice itself: the job kind, `RecordWayInChanged`, `SendWayInChanged`, the worker, the
   message codes, wiring gated on mail; tests.
3. Passwords: `PasswordWriter.Write` queues the notice for a change and a reset; tests per door.
4. Providers connected: `OidcWriter.Connect` and `settleAccount`; tests per path.
5. Providers disconnected: the read of who holds an identity, the workspace's removal and the
   offered provider's removal; integration tests.
6. Documents and the use cases: identity.md §6 and §21, UC-ID-04 and UC-ID-05 `state`, `checked_by`,
   *Today*; the finding on UC-ID-10.
