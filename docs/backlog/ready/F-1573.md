## 3. Decisions

- [x] D1 The handling — decided by: owner, 2026-10-16, on #1573 → this record; `ai-first.md` §2
  (the paragraph on asks and jobs) gains the outcome sentence.
- [x] D2 How the outcome reaches `GET /jobs/{id}`: a nullable `job.outcome` column, written by
  `CompleteJob` from a new `queue.Result.Outcome` (a message code); answered as
  `Job.outcome_code`, beside `error_code`, absent where a job has none. Message codes rather than a
  bare enum, because the client renders them through the catalogue like every refusal, and two of
  them are the very codes the ask refuses with up front (`ai.nothing_to_work_with`, `ai.kept_out`):
  the person reads the same sentence whether the fact was met before or after queueing. Generic on
  the job, not AI-shaped: another kind may answer one later, additively. No parameters column — no
  outcome has parameters; adding one later is additive — decided by: worker. Rejected: a `result`
  object (a shape for one string); persisting `Counts` (a log-only counter, rule 10 holds it there);
  ending "nothing" outcomes `FAILED` (the owner decided *succeeded with an outcome*, and a
  `FAILED` job reads as a refusal).
- [x] D3 The four values: `ai.proposed`; `ai.nothing_to_change` for an answer that proposes nothing
  *and* for one that is unreadable or empty after the narrowing (a person cannot tell the two apart
  and the honest sentence is the same: "the AI found nothing to propose"); `ai.nothing_to_work_with`;
  the kept-out outcome is the code `KeptOut.Refusal` gives the asker, so `ai.kept_out` or
  `ai.processing_restricted` — the same code the ask would have refused with — decided by: worker.
- [x] D4 The follow follows the job, not a count of reads: it ends on the job's terminal state; after
  the reads add up to about a minute (the present ten) it marks itself `slow` and keeps reading at the
  15 s ceiling until the job ends or the screen is left (the strip unmounts). While the page is hidden
  (`document.visibilityState`) the follow pauses and resumes on return, so a tab left open overnight
  does not read every 15 s. No new hard ceiling: a job always ends
  (deadline, retries, dead letter → `FAILED`), and one read per 15 s per open strip is the cost —
  decided by: worker. Rejected: keep giving up after a minute (the owner asked for "keeps looking").
- [x] D5 A refused ask leaves no asking state: the store removes it and rethrows, and the
  component's existing failure line says the refusal at once — decided by: worker; one place per
  sentence (`problem.ts`).
- [x] D6 P-05 mirror, exactly what `workable` refuses on facts the client holds: `classify` with no
  closed set — the server gains the refusal `ai.nothing_to_choose_from` (422) in `workable`, read
  from the same material it already reads, and `offersFor` disables the operation from the labels,
  the board's columns (entry directly in a collection) and the closed custom fields for its type —
  the three lists the strip already opens; until they are read the item is disabled with the
  pending reason. *Summarise* on a collection the screen lists empty, and the jumble ask on an
  entry with neither subject nor body: disabled with a reason, the server's answer unchanged —
  decided by: worker, the owner's own example (#1573). Rejected: refusing `classify` with
  `ai.nothing_to_work_with` (that sentence says the entry is empty, which it is not).
- [x] D7 One reading of an ended asking for the four screens: a pure `noteOf(asking)` in
  `suggestions.ts` answers the code and parameters to render and whether it is a refusal or a note,
  so the strip, the jumble card, the collection summary and the templates dialog render one answer
  — decided by: worker; it removes four copies of the announcement chain.
