## 3. Decisions

- [x] D1 Name the account on the TERMS challenge at the two sign-ins whose person typed no address
  and saw none — a provider's return and a connect link — through one helper beside `openOrAgree`;
  not in `termsStep` for every way in — decided by: worker. After a password the person typed a
  sign-in name or an address and the card shows what they typed; sending the address there would
  replace a sign-in name with an address the person did not type. Rejected: reading the address in
  the link step (a query change for a line the card already shows).
- [x] D2 Correct `MfaChallenge.email`'s description to say where it is present: with the first
  step a provider's return or a connect link answers, and that a later step of the same sign-in may
  carry none because the card keeps the name — decided by: worker; a correction, no field changes.
- [x] D3 The order lives in the domain: `LegalSettingNames()` draws the version right after the
  terms link — decided by: worker. Every other caller iterates into a map or compares, so the order
  is the form's alone. Rejected: a special case in the projection.
- [x] D4 The version's lock while editing is derived from the draft's link lock in `values.ts`
  (`draftEntry`), the one place the form reads the draft — decided by: worker. The server already
  ignores the version's own lock.
- [x] D5 No date beside the version — decided by: worker. No check asks for one; a date would be new
  data in the contract and in the agreement, and the story's line is an example. Named as open in
  the pull request; an operator may write a date into the version itself.
