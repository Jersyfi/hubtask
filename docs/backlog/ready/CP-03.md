## 3. Decisions

- [x] D1 The rule — decided by: the owner, #1177 → data-protection.md §4, UC-PRV-01 check 2.
- [x] D2 The day of receipt is kept in `received_at`, no new column: a case received today keeps
  the recording instant (as now); one received earlier gets the start of that day in the workspace's
  zone. `DayOf(received_at, zone)` is the day of receipt either way, which is what the extension's
  bound already reads — decided by: worker. Rejected: a `received_on` column (a migration, and two
  readings of "received" that could disagree). The contract answers `received_on` too, so a client
  does not derive it in its own zone.
- [x] D3 "Today" is today in the workspace's zone, for the default and for the refusal of a later
  day — decided by: worker; the deadline ends in that zone, so the day it counts from must be read
  there too.
- [x] D4 A stated deadline earlier than the day of receipt is refused
  (`privacy.deadline_before_receipt`); a stated deadline in the past is accepted (Decision 2) —
  decided by: worker. Rejected: accepting it (a deadline before the request existed is a typing
  mistake, never a period).
- [x] D5 `privacy.deadline_in_past` stays in `locales/en.json` and `de.json` for one release with no
  backend use, because a web app of the previous release may still render it during a rolling
  update; removed at the next cut — decided by: worker. If the message-code gate refuses an unused
  code, it is removed here instead.
- [x] D6 The web app's record form gains *Received on* (a date, default today in the workspace's
  zone, `max` today) above the deadline; the deadline's hint says "one calendar month from the day
  of receipt" — decided by: worker; shown to the owner on the draft (milestone CP, cut checklist 10).
