## 3. Decisions

- [x] D1 A workspace's address is built in one place: a domain function `WorkspaceBase(base, slug,
  multi)`, which answers the base itself in single mode and `scheme://<slug>.<host>[:port]` in
  multi mode. The invitation link uses it for both the answered and the mailed link. — decided by:
  worker; one rule, one place.
- [x] D2 **What a provider's redirect needs: nothing new.** The provider's return stays one address
  per installation, `<base>/auth/callback`, registered once; that is what UC-ID-11 check 6 shows and
  what a provider can hold, because Google and Microsoft accept no wildcard redirect. In multi mode
  the web app at that address asks the API where the flow belongs. `POST /auth/oidc:locate` takes
  the state and answers the workspace's base, computed from the flow's own workspace and the
  configured base. The app then forwards the browser there with the code and state, and the sign-in
  completes on the workspace's host, so the session is the workspace's. The app asks for every
  return that carries a state, a refusal's too, since the manifest that names the mode may not be
  read yet when the callback mounts; it forwards only to a host beneath its own by the same scheme,
  so the single-tenant answer (its own address) finishes in place. A failed lookup finishes in
  place as well, where an expired state meets the existing refusal. The code was bound to the
  installation's one redirect and to the flow's verifier, so it is exchanged as before. identity.md
  §10 says this in a paragraph. — decided by: worker. Rejected: one registered redirect per
  workspace, which needs every provider re-registered for every workspace and is impossible for an
  installation's provider offered to all; a server-side 302 at a new return address, which changes
  every existing registration.
- [x] D3 The lookup answers only for a well-formed state whose flow is live: unexpired, unspent, of any
  kind. It reads in the scope of the workspace the state names, through a new non-spending read
  `OidcFlows.Live`, with a Testcontainers test and a cross-tenant negative test. An unknown,
  expired, spent or malformed state is one answer, `404 auth.oidc_flow_not_found`, revealing no
  slug. The flow is not spent here; it is spent at completion, as today. The route joins the auth
  bucket (`isAuthRoute`). — decided by: worker, the review's conditions.
- [x] D6 The forward keeps every binding (premise rows): no cookie exists to lose. The server-side
  verifier, nonce and session binding are host-free, and the browser-side bearer and markers are
  on the workspace's host where the flow started, which is where the forward lands. Nothing is
  weakened. — decided by: worker, reviewed against the condition.
- [x] D4 Reset, address-confirmation, notification and way-in mails also link to the base in multi
  mode. They are outside check 7, so a `finding` is filed naming them and `WorkspaceBase` as the
  fix. — decided by: worker; the task's scope is the check.
- [x] D5 Nothing waits on the owner.
