## 3. Decisions

- [x] D1 The version lives in a one-row table `instance_level` (`version bigint`), seeded at 1 in
  the migration, `SELECT, UPDATE` granted to the application role, no tenant and no policy — entered
  in `db/schema.sql`, `test/integration/tenant_boundary_test.go`, `cmd/restore-drill/checks.go`
  and multi-tenancy.md §2's table. — decided by: worker. Rejected: a reserved key in
  `instance_setting` (a counter in a table of switches, with a `lock_origin` that means nothing for
  it); a hash of the level as the `ETag` (needs a table lock for the guard, and every other
  resource of the API uses an integer version a client already knows how to send).
- [x] D2 `If-Match` stays optional (the issue proposed requiring it). A missing one is checked
  against the version read in the same transaction, so two saves at once still refuse the second.
  — decided by: worker, api-guidelines.md §5 ("Optimistic locking") and the workspace's `PATCH`. Requiring
  it would refuse every script that writes the level today, a breaking change. Both clients this
  repository ships send it.
- [x] D3 The file wins: `ExecuteAsFile` moves the version without comparing it. — decided by:
  worker. In `enforce` every replica writes at start, and a refusal there would stop a start over
  a race between two copies of the same file.
- [x] D4 In `enforce` mode the refusal stays `admin.instance_enforced_from_file`, checked before
  the version. — decided by: worker. Reading the level again does not help there; changing the file does.
- [x] D5 The screen keeps the operator's unsaved values after the refusal and says somebody else
  saved first. Reading again is the operator's step, so nothing they typed vanishes (P-11).
  — decided by: worker. The owner sees it on the draft.
- [x] D6 Nothing waits on the owner: the check is decided (#1498), and the contract change adds
  and renames nothing.
