## 3. Decisions

- [x] D1 Every request queues one request job; the verification, the trail entry and the mail job
  move into it — decided by: the finding's proposal (#1318), approved for this sweep. Not detached:
  like `InvitationMessage` it records and enqueues in the runner's transaction, so they commit
  together exactly once — the guarantee `h.queue` gave inside the request.
- [x] D2 The lookup stays in the request, read-only; the job carries the account's identifier, or
  an empty one — decided by: worker, after review. Rejected: carrying the address sealed so that the
  lookup could move too (the keyring is empty by default, so a default installation would send no
  reset at all; and the job table has no working purge, so typed addresses of people without an
  account would stay — exactly the list `Reset.go` refuses to keep; keyless sealing would be a
  security decision). Rejected: a decoy write (its cost cannot be made equal with confidence).
  Residual: an index hit and a miss differ in the lookup alone — the walk's medians put an unknown
  and a disabled account (both a lookup without the write) about 0.4 ms apart, against 2.7 ms for
  the write this removes. Named in identity.md as the bound of the guarantee.
- [x] D3 The entry's moment is the request's: the payload carries `requested_at` (from `Clock`) and
  `request_id`, and the job records `OccurredAt` and the request identifier from them — decided by:
  worker. The chain orders by `seq` and accepts an earlier `occurred_at` (`db/queries/Audit.sql`
  comment on `seq`). The entry now lands when the job runs; a worker that is down delays it, a
  dead-lettered job loses it (and its mail) — the mail had the same dependency already.
- [x] D4 The new kind is `identity.password_reset_request`, no dedupe key (an empty account must not
  collapse with another's) — decided by: worker. Rolling update: a process of the previous release
  has no handler for the kind and fails the attempt back to the queue (`queue.handler_missing`, with
  backoff), so a job is delayed during a rollout and dead-lettered only by a rollout longer than its
  attempts.
- [x] D5 The descriptor's audit declaration and the event matrix stay: the use case is still what
  causes the entry, through its job (the matrix is generated from the declaration) — decided by:
  worker.
- [x] D6 Documents: identity.md's reset table, `Reset.go` and `queue.Port` comments. No ADR: ADR-0068
  §6 already decided "a job behind one answer" — decided by: worker.
