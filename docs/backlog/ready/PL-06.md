## 3. Decisions

- [x] D1 The move gains `dry_run`: the same answer, computed in the move's own transaction, which a
  sentinel error ends from the outermost `Within`, so nothing commits; the dry run skips the trail,
  the journal and the platform's event outright and keeps only the plan's assignment its reading of
  the limits needs; it stays free of `persistence.After` work. The dialog asks it with its own key and
  confirms with a fresh one. The descriptor declares the field — decided by: worker; rejected:
  computing it in the client (no admin read answers a workspace's usage or exceptions). Additive: not
  on the owner's list.
- [x] D2 The exception dialog's placeholder resolves plan over installation in the client, from the
  documents it already reads - a second copy of `quota.Levels.planApplies` (the plan where it sets a
  value and the installation does not lock it), named in a comment pointing there and at
  multi-tenancy.md §4.2, and only a hint: nothing is written from it — decided by: worker; rejected:
  a new read of one workspace's limits for a placeholder.
- [x] D3 Plans exist now, so the overview's "later" list drops them, and with the key goes the German
  "Tarife" PL-02's approved preview replaced by "Plan" everywhere else — decided by: worker; a "later"
  line for a built screen says something untrue. `app.instance.later_backup` describes a built screen
  too: a `finding` issue.
- [x] D4 *Plans* is its own screen and route (`/instance/plans`, `/instance/plans/{name}`), the editor
  reusing `InstanceValueField` — decided by: the approved preview.
- [x] D5 `hubctl admin tenant move-plan` gains `--dry-run`: every door can do what one can (P-08) —
  decided by: P-08.
- [x] D6 A key the installation locks is read-only in the editor; a value looser than the
  installation's is refused at its field rather than filtered beforehand: which direction is stricter
  is declared per key in the domain (`Tighten`), and a client copy of it would be a second rule (P-06).
  A plan's own value the installation now locks is shown as not in force with a way to remove it,
  because the server refuses any write that keeps it (multi-tenancy.md §4.2) — decided by: worker.
- [x] D7 At a plan, the lock column keeps the installation's words ("Workspaces may"): it says what
  the plan leaves its workspaces; for a limit the operator's exception stays the last word, which the
  limits group says in one line — decided by: worker, P-07.
