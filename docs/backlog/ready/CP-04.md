## 3. Decisions

- [x] D1 The filter is a boolean CEL condition over a webhook environment: `event` (id, type,
  subject, moments, as rules see it), `data` (the CloudEvent's `data`, which is what a receiver
  reads), `actor` and `now` — decided by: worker; the dispatcher may not read the work context
  (`condition/Values.go:42-44`), so `item` and `parent` are not offered, and a declared name that
  resolves to nothing would make a condition silently false.
- [x] D2 Compiled at create and update with the rules' bounds; refused `webhooks.filter_invalid` with
  the expression code at `/filter` — decided by: milestone CP's task text, automation.md §2.2's
  pattern.
- [x] D3 A filter that fails to evaluate delivers nothing for that event - and says so where the
  subscription's owner looks: a delivery row with status `FILTER_FAILED`, no attempt, the expression's
  own code (and `kind` from `evaluation_failed`'s closed list) as `error_code`, never the filter's
  text; not replayable, and kept and removed with the delivery log's thirty days — decided by:
  worker after review finding 1; failing open would deliver what the subscriber narrowed away,
  failing the batch would stop every subscriber, and failing silently would hide it. Rejected: a
  counter on the subscription (it says that something failed, not which event).
- [x] D4 The scope is the rules' shape and meaning: a hub covers its collections; an item's event is
  judged by its collection, a container's by itself and its parent; `work.item.moved` by the
  destination; an event about no container reaches no scoped subscription — decided by: worker,
  automation.md §1 and `MatchRules`, whose matching moves to `condition` to be shared.
- [x] D5 Writing a scoped subscription asks the automation permission at the scope, after checking
  the container exists in this workspace and is of the named type; reading asks it at the
  subscription's scope and the list answers what the caller may read — decided by: worker, the
  rules' `authorize` and `permitsRead`.
- [x] D6 The audit records `filter_set` and the scope, not the filter's text — decided by: rule 10.
- [x] D7 The web app's form and hubctl gain the two fields — decided by: worker, P-08; the n8n and
  Zapier connectors stay as they are (additive).
- [x] D8 Nothing waits on the owner.
