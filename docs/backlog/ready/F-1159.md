## 3. Decisions

- [x] D1 A data kind `IDEMPOTENCY_KEY`, anchor `created_at`, default one day, lower bound one day,
  hard delete only, no marking phase — decided by: the finding's proposal and data-retention.md §3
  (every period is a kind). One day because the catalogue says 24 hours and the kinds count in
  days; the floor because api-guidelines.md §5 promises a replay for at least 24 h. A workspace may
  keep keys longer, never shorter.
- [x] D2 The read keeps no age filter — decided by: worker. The promise is a replay for *at least*
  24 h; a row past its period that the next pass has not reached yet is still a correct replay.
  Rejected (the finding's second half): ignoring older rows on read would let a reservation meet a
  row it cannot see, which `ReserveIdempotencyKey` would then have to overwrite — a second write
  path for no gain to the person.
- [x] D3 No legal hold and no marking phase — decided by: worker, on the `SESSION` kind's reasoning
  (`Catalogue.go`, `RunRetention.sweepSessions`): a key is bookkeeping about a request, nobody can
  take it out of its period, and a hold is placed on tenants, containers and items, not on the
  transport.
- [x] D4 No new index: `idempotency_gc_idx` (`created_at`) serves the oldest-first batch under RLS,
  and the primary key leads with `tenant_id` — decided by: worker. A tenant-leading `created_at`
  index (migration 0125) is the follow-up if a pass ever shows in the slow-query log.
