## 3. Decisions

- [x] D1 Resolve with `domain.Effective(instance, {}, workspace)` over the rows `readWaysHere` already
  reads, not `SignInPolicyResolver.Resolve` — decided by: worker. `anotherWayIn` has neither a tenant
  id nor a resolver wired in; `readWaysHere` already reads both rows in the one transaction; and
  `Effective(instance, {}, workspace)` is exactly the resolver's own call (`SignInRules.go:127-128`),
  so the two cannot disagree. Without an installation store the layer is empty, as `readWaysHere`
  already reads it, and the workspace resolves over the product default.
- [x] D2 `waysHere` keeps the installation's layer and answers `passwordIsAWayIn()` from it and the
  workspace it holds; `onlyProviderMethods` goes — decided by: worker. Computed when asked, never
  cached: `WorkspaceWriter.keepsAWayIn` sets `here.workspace` itself after reading (it does not ask
  this question, but a cached answer would be one more thing to keep in step).
- [x] D3 The operator's opening (§17.2) does not count as a way in for the guard — decided by: worker,
  unchanged from today: it is temporary and the guard asks about the rule.
- [x] D4 A sign-in name's open password door (identity.md §4.1, §17.1) does not count either —
  decided by: worker, unchanged from today: it reaches nobody with an address, who are the people
  the last way in exists for.
