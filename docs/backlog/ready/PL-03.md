## 3. Decisions

- [x] D1 The quota resolution keeps its place in `core/application/service/quota`; `Resolve` takes
  the levels as one value (`Levels`) so the plan cannot be passed in the installation's place —
  decided by: worker, the vocabulary's home (`Quota.go`'s package comment).
- [x] D2 A plan's limit may be higher or lower than the installation's open value; only an
  installation lock binds it, and a plan's lock under an installation lock is refused on write —
  decided by: `FitsUnder`'s reasoning and multi-tenancy.md §4.2 ("ignored on read, refused on
  write").
- [x] D3 `source` on a standing: `DEFAULT`, `INSTANCE`, `PLAN`, `EXCEPTION` (the operator's, per
  workspace) and `WORKSPACE` (the workspace's own AI budget); `lock` the existing `PolicyLock`,
  answering the level that locked whether or not an exception stands; `locked` keeps its meaning
  (`Read.go:156`) — decided by: worker; a field's meaning does not change under a client.
- [x] D4 The limits screen reads the plan's name where the workspace read already answers it
  (`sign_in_policy.plan`, PL-02), which every reader of `/quotas` also reads — decided by: worker;
  `/quotas` is an array and gains no envelope.
- [x] D5 `limits_exceeded` lists `{quota, limit, used}` for items, media bytes and webhook targets
  (the counted capacities; rates, day budgets and running exports pass) where `used > limit` against
  the resolved limit, exception included, read after the move in its transaction; PL-04 adds the
  people limit — decided by: worker, the milestone's task text; "at" the limit is not "over" it.
- [x] D6 `EffectiveAi` honours a plan's value only where it narrows what the installation leaves in
  force, and a plan's lock holds the value in force — decided by: multi-tenancy.md §4.2, PL-02's
  `Effective`.
- [x] D7 The per-token rate reads exception → plan (unless the installation locks it) →
  installation in the two authentication queries, a scalar subquery on the round trip that already
  runs; that the installation's own row was never enforced is fixed in the same step, test first —
  decided by: worker; AGENTS.md (a finding fixed on the branch), UC-INS-10 check 1.
- [x] D8 `installation_sources` keeps its name; its description becomes "what the levels above the
  workspace allow, the installation and its plan" — decided by: worker; a rename would be the
  owner's, and the field always meant "the level above" (`AiRule.Above`).
- [x] D9 The AI rule reads the plan through its own port (`AiRules.Plans`), one indexed query per
  resolution beside the workspace read: the AI layer cannot ride on `identity.Workspace` (§ 1) —
  decided by: worker, rule 1.
