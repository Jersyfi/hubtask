## 3. Decisions

- [x] D1 The preset answers its one issuer (`issuer`, Google's `https://accounts.google.com`), and
  each form fills it when the kind is changed to that preset, where the field is empty or still
  holds another preset's issuer — decided by: worker. Rejected: the issuer written into the client
  (a second place for a fact the domain owns); defaulting an empty issuer on the server (the form
  would still mark a filled field as missing).
- [x] D2 The Microsoft texts become one statement: the preset's *particular* says a directory's own
  address serves that directory and a shared one every directory listed below; `directories_required`
  says a shared address needs the list and drops "without a list it is all of them" — decided by:
  worker; it is a correction to what the server does (it refuses the save).
- [x] D3 The four refusals that rendered a raw provider kind name the provider without it ("this
  provider", "a provider without a directory", "the provider chosen") — decided by: worker. Each
  fires for known kinds only: `installation_invited_only` and `directories_unsupported` for the
  preset without a directory claim (generic), `provisioning_public` for the public one (Google),
  `kind_mismatch` for Google and Microsoft (the generic preset speaks for every issuer), so the
  sentence loses nothing. The domain keeps sending `kind` as a parameter: it is data an API client
  may read, and no test requires a parameter to be used in its message. Rejected: a
  client-side table translating params (a second mechanism in `lib/problem.ts` for four sentences).
- [x] D4 An invitation's refusal is the form's own, in a state of its own rather than the page's
  `failure`: drawn at the address field as its `error` (WCAG 3.3.1, the item in error identified),
  the typed address kept, the focus moved to the field, said once through the announcer — decided by:
  worker, from #1329's proposal. A role that could not be given after the invitation went out (link
  or mail) is also drawn at the form, not at the page's top; there the address is cleared, because
  an invitation did go out.
- [x] D5 The issuer is filled from the kind select's change handler, not an effect, so opening an
  existing provider (which sets `kind`) never touches its stored issuer — decided by: worker.
