## 3. Decisions

- [x] D1 **The `ai` area is a typed struct with a key list**, `identity.AiDefaults{Sources, MinJurisdiction}` with locks per key and `AiSwitches()`, like `PolicySwitches()`. PH-03's `ai.person_opt_out` is a third field and a third name. Resolution `EffectiveAi(instance, plan, workspace)` in `core/domain/model/integration` (plan empty until plans). Decided by ADR-0072 §2; worker: the shape. Rejected: a generic area registry (a refactoring of four existing areas this task does not need).
- [x] D2 **Orders.** `ai.sources`: allowed sets `NONE={}`, `OWN={own}`, `OFFERED={offered}`, `EITHER={own, offered}`; stricter = subset. `ai.min_jurisdiction`: `ANY < ADEQUACY < EEA < SELF_HOSTED`; an own declaration meets it when `THIRD_COUNTRY` ≥ `ANY`, `ADEQUACY` ≥ `ADEQUACY`, `EEA` ≥ `EEA`, `SELF_HOSTED` ≥ all. Effective allowed sources also drop `offered` when no model is offered (ADR-0072 §7: with nothing offered `EITHER` resolves to `OWN`). Decided by ADR-0072 §2, §7.
- [x] D3 **The choice and the narrowing live apart, because one carries consent and the other a restriction.** The consent-bearing choice is a table `ai_source` (tenant PK, `source` ∈ `OWN|OFFERED|NONE`, `offered_provider_id` → `ai_provider(id) ON DELETE SET NULL`, `version`, `updated_at`), under `tenant_isolation`, **excluded from the archive** for `ai_provider`'s reason; a restore leaves no row, which is `OWN` with the own model's consent as restored — and `ai_provider` is not restored either, so nothing is sent until an administrator decides again. The workspace's **narrowing** of `ai.sources` is an administrator's restriction and lives in the archived workspace settings (`tenant.settings`, key `ai` → `sources`, beside `sign_in_policy`), so export, backup and every restore mode carry it: a restore never silently widens what the workspace allows. No row and no key = `OWN` and undecided — today's behaviour, so no backfill. Proof: a restore round trip (`REPLACE_TENANT` and `NEW_TENANT`) in which the narrowing survives and the choice does not. Agreed with the coordinator, 2026-10-12 (review F2). Rejected: the narrowing in `ai_source` (lost on restore); the choice in `tenant.settings` (a restore would resume sending under a consent nobody gave again).
- [x] D4 **Migration 0129, expand only.** `ai_provider` gains `id` (backfilled, `NOT NULL`, the primary key), `display_name`, `processor`; `tenant_id` loses `NOT NULL`; a **unique index on `tenant_id`** keeps the old binary's `ON CONFLICT (tenant_id)` working (NULLs distinct, so several offered rows); checks: an offered row has a display name and a processor, is not `NOOP`, and has `processing_allowed = false`; the three policies of 0103. Every tenant statement gains `WHERE tenant_id = current_tenant_id()`, the census line too. The window: once an operator has offered a model on a new pod, an old pod's unscoped `FindAiProvider` may answer the offered row instead of the workspace's own, so the workspace's own AI stops answering on that pod until the rollout ends — accepted, because it fails closed: the offered row's `processing_allowed` is false by the check, so nothing is sent, and no offered row exists before an operator creates one (review F3). The migration test runs the previous binary's statements as the app role with an offered row present and asserts that nothing would be sent. `item_embedding`'s `model` check widens from 200 to 300 characters (`NOT VALID`, a wider bound every row already meets) for D10's qualified names. `test/integration/tenant_boundary_test.go` names `ai_provider`'s `NULL`. Decided by ADR-0072 §1, the coordinator (0129, 2026-10-12).
- [x] D5 **Consent per source, never written by a rule.** The own model's consent stays `ai_provider.processing_allowed` (UC-AI-03 unchanged). Choosing `OFFERED:<id>` *is* the consent for the offered model (ADR-0072 §3, "one control"), recorded as `ai.source_chosen` in the workspace's trail with from, to and the model's display name; choosing `OWN` or `NONE` withdraws it. No instance or plan value writes `ai_source` or `processing_allowed`. Agreed with the coordinator ("a per-workspace record for source, offered id, consent"); worker: consent for the offered source is the choice itself rather than a second boolean that would have to agree with it.
- [x] D6 **Narrowing stops, never deletes.** The resolver (`infrastructure/ai/Resolver.go`) asks the application's `AiRule` for the effective sources, minimum and choice in the same read-only transaction; a source not allowed, an own model below the minimum, an offered model gone → a `Noop` whose calls answer `ErrUnavailable` with `ai.source_not_allowed`. `ConfigureAiProvider` refuses where OWN is not allowed or below the minimum; `ReadAiProvider` and `RemoveAiProvider` always work. Decided by ADR-0072 §5; worker: refusing the own configure keeps the server and the screen in agreement (P-05).
- [x] D7 **Choosing.** `PUT /ai-source {source, offered_model_id?, sources?}`; `NONE` always; `OFFERED` needs the id of an offered model and `offered` in the effective set; the narrowing is checked with the sign-in vocabulary (`auth.policy_locked`, `auth.policy_loosens`). A new resource rather than a field on `/ai-provider`, because that one answers 404 for a workspace with no own model — exactly the consumer who uses an offered one. Worker: ADR-0072's Consequences say "`ai.source` on the workspace's AI resource"; the field is on the workspace's AI *source* resource; no existing field changes.
- [x] D8 **Operator use cases** `ListInstanceAiProviders`, `ConfigureInstanceAiProvider` (POST creates, PUT changes), `RemoveInstanceAiProvider`, after `InstanceProvider.go`: `admin:tenants` + register, `SystemScope` for writes, the instance journal, the same domain validation and third-country check as a workspace row, key purpose `ai_provider.api_key:offered:<id>`. No extra step-up: the operator's session already raised `admin:tenants` with one, and offering sends nothing anywhere (consent is each workspace's) — the workspace's own configure has none either. Removal confirms on screen that workspaces using it stop getting suggestions (P-04), without a count. Worker.
- [x] D9 **The instance file carries offered models**: `ai_models: [{display_name, processor, kind, base_url, completion_model, embedding_model, jurisdiction, api_key_env}]` — the key by the name of an environment variable, never in the file; identity by display name (unique among offered rows). `seed`: applied when no model is offered; `enforce`: the file is the list, screen and hubctl writes refused. The `ai` area joins the file's areas. Worker: UC-AI-06 check 1 names the file; a secret in a configuration file would be a key in clear.
- [x] D10 **Re-embedding.** A workspace write that changes the embedding model in use (choosing a source, changing the own `embedding_model`) seeds `ai.embed` in the same transaction. An operator's change to an offered model's embedding model seeds nothing — ADR-0072's "nothing enumerates workspaces" — because every workspace that has embeddings has a repeating `ai.embed` job, which finds them owed by model at its next pass; one without embeddings has nothing to rebuild. The AI screen says search by meaning is rebuilding while entries are owed under the current model (`search_rebuilding` on `GET /ai-source`, one count). Worker: this reads ADR-0072 §6's "self-seeded by the write" for the workspace's own writes and the job's own repetition for the operator's.
  **While a workspace re-embeds, a query is never compared with vectors of another model** (review F1). The rows already record their model and the search already reads only rows of the model that embedded the query (§ 1); what SC-11 adds is that the stored name identifies the model *space*, not only its name: an own model's vectors keep the bare name (no re-embedding after the upgrade), an offered model's are stored as `offered:<id>/<model>` — two sources with one model name are two spaces. The width needs no column: within one space it is one width, and a wider answer is refused before storing (ADR-0054). Search by meaning therefore reads only vectors of the space in use and falls back to search by words for an entry without one. Proof: an integration test with vectors of the own model present and the offered model of the same name in use — the search compares with none of them and answers by words, and the duplicates proposal finds none across the two.
- [x] D11 **D1 sees nothing.** With nothing offered and the default rule, `GET /ai-source` answers `sources: [OWN]`, `offered: []`, no lock; the screen renders exactly today's form and no source choice. (UC-AI-06 check 8, P-10.)
- [x] D12 **Where the rule is edited.** `ai.sources` and `ai.min_jurisdiction` are rows of the instance defaults (`/instance/settings`), shown with selects in words and the lock switch — the story's *Defaults → AI*; offered models on a new row *AI* of the installation group (`/instance/ai`). Worker (P-06). SC-11 merges before SC-07 (the coordinator, 2026-10-12); SC-07 then gives the `ai` rows its typed controls.

Fixed on this branch, own commit, test first: the own model's consent reads "Send this workspace's content to {host} ({where})" (host of `base_url`, the jurisdiction in words); the offered card names processor and jurisdiction. Worker (AGENTS.md, finding fixed where the rules allow).
- [x] D14 **New codes**, `en` and `de` (the `ai` and `app.ai` families are translated): `ai.source_not_allowed`, `ai.jurisdiction_below_minimum`, `ai.offered_model_unknown`, `ai.display_name_required`, `ai.processor_required`, `ai.offered_needs_a_model`, `config.instance_file_ai_key_missing`; `app.ai.*` and `app.instance.ai_*` for the screens; refusals of the narrowing reuse `auth.policy_locked`/`auth.policy_loosens`/`auth.policy_value_invalid`.
