## 3. Decisions

- [x] D1 Announce it as `features.search_filter: true` rather than record that the contract's
  filter field is the announcement — decided by: ADR-0064 decision 6 (the manifest says it) and the
  precedent `sign_in_rules` (a build-level `true`, so a client probes nothing an older server lacks).
  Rejected: "the field is the announcement" — it contradicts the accepted decision, and a client
  cannot read a request field from a server.
- [x] D2 The `features` description stops claiming "not what the build implements" without
  exception: it says that two keys, `sign_in_rules` and `search_filter`, are answered `true` by
  every installation of this version and exist for a client that also talks to older ones —
  decided by: worker. That is the truth of the code today, and it lists `sign_in_rules`, which was
  missing.
- [x] D3 api-guidelines.md §3 gets one sentence naming the key, beside the paragraph that says what
  `/search` takes — decided by: ADR-0064's `Rule lives in` line.
