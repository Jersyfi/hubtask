## 3. Decisions

- [x] D1 The leader drops whole month partitions past the horizon, as audit.md §3 decided ("a month
  partition at a time") — decided by: audit.md §3, the schema's note.
- [x] D2 The horizon is the longest audit period any workspace has (400 days today), read as the
  streams read theirs; a month goes when it ended before now minus the horizon — decided by:
  worker; the streams' rule. A partition holds every workspace, so the longest period decides.
- [ ] O1 **A tenant-wide hold on one workspace keeps the whole month for every workspace in it** — the
  only way a hold can keep a shared partition. While the hold stands, other workspaces' entries of
  that month are kept past their 400 days. Alternative: give the trigger a second, narrower
  exception and delete the other workspaces' rows of that month one statement each — "never one by
  one" (UC-AUD-07 check 3, audit.md §3) and a new way past the immutability lock. Proposed: the
  partition stays whole, and the run says why (`blocked: legal_hold` on the instance journal entry).
  **Whether this needs the owner** (a retention safeguard's effect on other workspaces' storage
  limitation) is for the reviewer to judge; if it does, it becomes a `decision` issue.
- [x] D3 The removal is recorded in each workspace that had entries in the month — the definer
  answers the month, and per workspace its count, before it drops — through one `audit.trail_removed`
  job per workspace (the extension fan-out's shape: identifiers cross, the entry is written in the
  workspace's own transaction and chain), plus one instance-journal entry with the total — decided
  by: worker; check 4 and the Story ("an entry says how many entries of which period went").
- [x] D4 The verifier is unchanged (§ 1); a test proves a chain without its oldest month verifies —
  decided by: worker.
- [x] D5 Rows in the default partition are not removed: PostgreSQL cannot drop a default partition,
  and migration 0043 left moving rows out of it to the operator. Their count past the horizon is
  reported (a gauge `hubtask_audit_default_partition_aged_rows`, and the run's log line), and a
  `finding` issue is filed for the operator's procedure — decided by: worker. Rejected: a trigger
  exception to delete them row by row (check 3's "never one by one", and a new door through T-15).
- [x] D6 An anchor whose sequence was removed is reported as such by the anchored check (not found)
  rather than as a break; later anchors are unaffected — decided by: worker; a test.
- [x] D7 The definer reads `retention_policy`, `retention_rule` and `legal_hold` across workspaces,
  like `drop_stream_partition`. On a managed database (#1494) it reads none of them and drops at the
  catalogue's 400 days — the safe direction for a hold is the wrong one, so the function refuses to
  drop when it cannot read `legal_hold` at all (no rows visible while a tenant exists) — decided by:
  worker, pending #1494's answer.
