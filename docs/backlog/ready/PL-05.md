## 3. Decisions

- [x] D1 The closed set moves to `core/domain/model/entitlement`; `plan.Feature` becomes an alias,
  so PL-01's API is unchanged and `identity.WorkspacePlan` can carry the set — decided by: worker
  (the import cycle); rejected: strings on the workspace.
- [x] D2 One port, `core/application/repository/admin.Entitlements` (`LeftOut(ctx)`), answers the
  transaction's workspace's set in one statement; the sign-in readers read the same rows through
  `OfWorkspace`, which `Find` already calls — decided by: worker; rejected: `OfWorkspace` on every
  outbox event and run (two statements and the whole plan where one row set is needed).
- [x] D3 A use case that only uses a feature declares it on its descriptor (`Entitlement`), and one
  registry middleware refuses it with `403 plan.not_included` and the feature, like
  `accounts.managed_accounts_off` — one place for every door, and the same declaration filters
  `automation_actions`. Where a use case's command decides it (switching an own provider on, a
  subscription's change other than pausing), the use case refuses with the same code. The gate runs
  before the use case's own authorisation: what a plan leaves out is no secret in the workspace
  (D8). The inbound address keeps its uniform 404 — decided by: worker; rejected: a check in each of
  fourteen use cases.
- [x] D4 A schedule while left out is moved on without a run; a relative-date occurrence due while
  left out is dropped — "without the occurrences it missed" with no job at inclusion (check 2 allows
  none) — decided by: multi-tenancy.md §4.2.
- [x] D5 An action refused because the plan leaves its feature out is skipped, not failed: a plan
  with automation and without webhooks (the preview's "Familie") must not switch a rule off by its
  streak — decided by: worker, P-03.
- [x] D6 What stays: reading everything, and every act that protects or ends — switching a rule off,
  deleting it, checking rules, rotating its inbound address; pausing a subscription, rotating its
  secret, deleting it; switching an own provider off, removing it. What is refused: creating,
  changing, switching on or resuming, and running or sending — decided by: worker, multi-tenancy.md
  §4.2 ("cannot be created or switched on", "no subscription is added") and P-03 (a person can
  always stop or remove what is theirs).
- [x] D7 A delivery queued before the move is not sent and stays `PENDING`: no status means "held
  back by the plan", a new one would change the contract's enum and the table's check, and
  `FILTER_FAILED` says something else. It is not sent when the feature returns either, since its
  job has ended. The deliverer says so in a comment — decided by: worker.
- [x] D8 `not_included` is answered to every signed-in person of the workspace: a member reaching a
  rules screen needs the same reason; the milestone's matrix names what owners and administrators
  see and narrows nothing; the account link (PL-11) is the part kept to owners and administrators —
  decided by: worker.
- [x] D9 Trigger polling and `HttpRequest` stay: polling reads events through a door (P-08), and
  `HttpRequest` is a call a person makes, not a rule's — decided by: worker.
- [x] D10 The runs screen loses its dry run and replay, the editor its save: the same rule as the
  approved preview's ("no create or switch on, reading stays"), shown on the draft pull request —
  decided by: owner's approval of the rule on 2026-10-16, applied.
