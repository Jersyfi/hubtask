## 3. Decisions

- [x] D1 Finding and paging is a new `POST /admin/tenants:query` answering `{data, page}`;
  `GET /admin/tenants` stays as it is — decided by: api-guidelines.md §1 and §4 (a reference in a
  query string reaches access logs; listings page in the body); the milestone's "`GET` … filtered"
  is task text, corrected in this commit; UC-INS-13 check 10 asks only for "page by page".
- [x] D2 The reference: opaque text, 1–200 characters, no control characters, no leading or
  trailing white space, unique among workspaces not yet purged — decided by: multi-tenancy.md §4.3,
  worker for the white space (two references that differ by a trailing blank are one mistake).
- [x] D3 Setting a reference is multi mode's; reading is every mode's, as the listing is — decided
  by: worker.
- [x] D4 The trail records the change as `Sensitive` ("changed" and a keyed hash), the journal
  records the act without the value — decided by: rule 10; `Open` would write it in clear.
- [x] D5 The filters and the keyset run inside one `SECURITY DEFINER` function, so a page reads
  its rows rather than the whole installation — decided by: worker; filtering `admin_tenants()` from
  outside would materialise every workspace per page.
- [x] D6 Not in the export — decided by: worker, § 2(c) 13; the export served every column of
  `tenant` until this task subtracted it.
- [x] D7 Reading by id, slug or reference goes through the query function, which reads the table
  rather than an index (its predicates are parameters of a non-inlined function) — decided by:
  worker — sound at today's number of workspaces; an index-driven lookup is a later change if the
  count grows by orders of magnitude.
