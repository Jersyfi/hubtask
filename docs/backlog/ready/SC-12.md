## 3. Decisions

- [x] D1 **The census is per level.** The workspace statement's `identity_provider` branch gains `tenant_id = current_tenant_id()` (the `ai_provider` branch has it since SC-11). A second statement counts the installation's own rows — `identity_provider` and `ai_provider` where `tenant_id IS NULL` — run once in `InstallationScope()` after the workspaces. Both group by store and key, so the status can name kinds (D3); the operator's total per key is unchanged in meaning, now correct. Decided by known-traps (the policy row) and ADR-0045; worker: the shape. Fixed test first in its own commit (a defect, not a feature).
- [x] D2 **The installation's round is one job without a tenant**, the same kind `secret.reseal`, dedupe `reseal:installation`, enqueued by `ResealSecrets` beside the workspaces' (`SystemScope`, which may write the job table). The worker runs it under `SystemScope` (the runner already does for a job without a tenant) with the installation's resealers: `IdentityProviderResealer` as it is (its `ListSealed` reads the level of the scope; the purpose of the empty tenant) and a new `OfferedAiProviderResealer` in `integration` (purpose per row). Anything moved → one `instance.secrets_resealed` entry in the instance journal with the counts — the installation's own record, as the operator's offers are. Rolling window: an old worker refuses a job without a tenant and the job retries until a new one takes it; worst case it dead-letters and the census says so. Worker: a second job kind would need the same old-pod answer and a registry entry for nothing; running the round inside the HTTP request would make the operator wait on every installation secret.
- [x] D3 **UC-INS-16 check 3 is met by the health report**, not by refusing: the ring is the environment (ADR-0045 — "the screen shows state, it does not turn the ring"), and refusing to start over one stale webhook secret would turn a forgotten value into an outage. The operator's whole health report gains `crypto.key_missing {key, store, count}` (warn) per key the ring no longer holds and kind still sealed under it, and `crypto.key_census_unchecked` (warn) when the census could not be read. The census crosses every workspace, so the health source serves the last result and refreshes it in the background through `SafeGo` at most hourly, under its own 60 s deadline, and after every encryption-status read (the operator looking at the keys screen refreshes the report); computed once at start. Every warning carries `counted_at` (the census's moment), and the operator's report says when the count was taken, so a stale number is never shown as current (P-11; the coordinator, 2026-10-12). The key screen's stranded banner names the kinds in words from the same `stores` breakdown. Worker; rejected: a census on every health read (one transaction per workspace on each poll).
- [x] D4 **Per source = per metric.** The offered source meters and is bounded under `ai_tokens_per_day`, the own source under `ai_own_tokens_per_day`; `usage_record`'s key already names the metric, so no column and no migration. ADR-0072 §4's "gains the source" is met by the metric's name. Consequences, named in the PR: an own model in multi mode loses today's 200 000 wall (ADR-0072 §4, UC-AI-06 6); on the upgrade day, own use metered earlier that day stays under `ai_tokens_per_day`, and during the rolling window an old pod meters own use there — at most one day of own use counted against the offered budget. Worker; rejected: a `source` column (a primary-key change on a hot table for a name the metric already carries).
- [x] D5 **`ai_own_tokens_per_day` is a quota row to read and the workspace's own to write.** In `quota.Names()`, the standings, the contract enum and the usage metric's label; default unlimited in both modes; no installation default and **not** in the operator's `TenantQuotas` — UC-AI-06 6 says an own model is limited "only by the workspace's own optional budget", and UC-AI-07's *Goal* says "a workspace for its own model". Stored top-level in `tenant.settings` as `ai_own_tokens_per_day` through the workspace settings' merge write — not inside `quotas`, whose write replaces the key, so no operator write (and no old pod's) can drop it; archived with the settings, so a restore keeps the restriction. Written by `SetOwnAiBudget` (`PUT /ai-budget {own_tokens_per_day: integer ≥ 1 | null}`, `null` = no budget), `PermissionStructure`, token scope `ai:manage`, trail `ai.own_budget_set` (Notice, required); `hubctl ai budget set <tokens>` / `--clear`. Worker: ADR-0072 §4 "a quota row like every other" read as the read side; the write follows the use cases.
- [x] D6 **The budget's day is the workspace's calendar day**, in `tenant.default_time_zone` — UC-AI-07 check 2 and its story ("renews at midnight (workspace time)"). The guard resolves the zone in the caller's transaction; the ledger's `period` for the two AI metrics is the workspace's local date (`Meter.Add` dates `at` in the location it carries; the automation meter passes UTC explicitly and keeps its UTC day). An unknown zone falls back to UTC. A zone changed mid-day takes effect from the next call (the day may be shorter or longer once). **A correction of `multi-tenancy.md` §4, not a deviation** (AGENTS.md: "correcting a wrong statement is not one"): the use case is the owner's statement of what a person sees, and the UTC day was J-15's worker's undocumented choice, never an owner decision. Decided by UC-AI-07 check 2; confirmed by the coordinator, 2026-10-12; named as a correction in the pull request.
- [x] D7 **The resolver tells the source.** `Resolver.Sourced(ctx, actor) (port.Provider, port.Source, error)` beside `For`; `port.Source` is `none | own | offered`. `Budgeted` takes that interface, checks the room of the source's quota and meters under it; `none` (and SC-11's refusals) checks and meters nothing. Every consumer keeps `For`. Worker; rejected: `Budgeted` reading the selection itself (a second read per call that can disagree with the first), and a field in `ProviderCapabilities` (a metric label set and an adapter concern).
- [x] D8 **What the screens show.** The AI screen's budget section: the offered model's use and cap where offered is allowed, the own model's use and its optional budget (with the control for administrators) where own is allowed — side by side in D6 (UC-AI-07 4). The limits screen lists both rows read-only. The operator's workspace quota editor and instance defaults are unchanged (no own row). Worker (P-05, P-06).
- [x] D9 **A pending direct call's sealed header secret is not re-sealed**: it lives in its job's payload only while the job is pending (the retry ladder), and procedure step 4 already says to wait for the census; a key retired while such a call is still retrying makes that one call fail with `crypto.unknown_key`. Named in `security.md` §8.1, not built; finding #1296 (the coordinator, 2026-10-12).
- [x] D10 **No migration.** Nothing in the schema changes; 0136 stays free.
- [x] D11 **New codes**, `en` and `de` (the `ai`, `app.ai`, `app.instance` and `config` families are translated): `crypto.key_missing`, `crypto.key_census_unchecked`, `ai.budget_invalid`; `app.ai.budget_*` per source, `app.instance.encryption_stranded` with kinds, `app.instance.store.*` (the kinds in words), `app.quotas.name.ai_own_tokens_per_day`, the journal action `instance.secrets_resealed`.
