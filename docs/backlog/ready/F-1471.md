## 3. Decisions

- [x] D1 A runtime error answers `expression.evaluation_failed` with `kind` one of
  `division_by_zero`, `modulus_by_zero`, `overflow`, `no_such_key` (a missing key, and a declared
  name the activation does not produce — CEL's `no such attribute(s)`), `no_such_overload`,
  `conversion`, `index_out_of_range`, `other` — read from CEL's message prefix, because CEL has no
  kind field (§ 1) — decided by: worker; the issue's proposal. `no_such_field` is left out: CEL
  raises it only for protobuf and native objects, which no environment here declares, so no test
  could reach it. Rejected: a code per kind (eight catalogue entries for one answer "the expression
  failed on these values").
- [x] D2 `evaluation_failed` is `ErrValidation`, not `ErrUnavailable`: the same expression on the
  same values fails the same way. What the category changes is the REST status where an error
  reaches one (422 instead of 503) and the use-case log line (none instead of a warning carrying
  CEL's text); the worker's retry and dead letter do not read it (§ 1), so the retention job is
  retried and dead-lettered exactly as before — decided by: worker. `timed_out` and
  `too_expensive` keep `UNAVAILABLE` (out of scope; unchanged behaviour).
- [x] D3 The error chain carries the kind, not CEL's error: CEL's text can hold a key or value from
  the data or the expression, and causes reach logs (rule 10) — decided by: worker.
- [x] D4 The cost refusal is told by `errors.As(err, &interpreter.EvalCancelledError{})` and its
  `Cause`, not by message text; the deadline by `ctx.Err()` as today — decided by: worker; a typed
  answer the library gives.
- [x] D5 The `en` sentence carries no `{kind}` placeholder: the run log stores the code without
  parameters, so a placeholder would render raw — decided by: worker.

## 4. Proof and steps

Proof: a table test in `infrastructure/expression/CEL_test.go` — one expression per kind against
the real CEL evaluator, **every kind of D1's closed list, `other` included**, so that a CEL update
which rewords a message fails this test instead of silently degrading the kind to `other`; each
answers `ErrValidation`, `expression.evaluation_failed`, the expected `kind`, and an error text that
quotes neither the data nor the expression. A new test asserts `timed_out` alone for a deadline in
the past; a cancelled caller answers `context.Canceled`. The fuzz target's property 2 (an
`expression.*` code) holds unchanged. `make gate-architecture` holds the code to `locales/en.json`;
run with the `en` entry alone it is green — the translation gate refuses wrong keys and
placeholders, not missing ones, and `make locales` reports `expression 0 / 10 missing` for `de`.
