## 1. Premise — what is true today

| Claim | True? | Evidence |
|---|---|---|
| A condition that cannot be evaluated stops the pass | true, **and a written rule** | `Sweeper.matchesCondition` returns the error, `Pass` returns it; data-retention.md §2's table: "one that cannot be evaluated **stops the pass** rather than defaulting either way" |
| Every rule of the workspace stops with it | true | `Pass` is one loop over the kinds and both phases; the first error returns, so the rules after it and phase two do not run |
| The trash and the other kinds stop with it too | true | the retention job is one transaction (`presentation/worker/Runner.go`: not `queue.Detached`, so `UnitOfWork.Within`); `RunRetention.Execute` returns the error from `sweepRules`, and the trash pass's removals, run before it, roll back with it |
| The failed `retention_run` row is kept | **false** | `sweepRules` writes it `FAILED` and returns the error inside the same transaction, which then rolls back — the trap "a write on a refusal path is rolled back with the refusal" (known-traps.md). The issue's text and F-1471's record say otherwise; corrected here and on the issue |
| The job retries, then dead-letters, and A-07 pages the operator | true | `Runner.fail`: any returned error is retried with backoff, then dead-lettered (`JobDeadLettered`), `HubtaskDeadLetter` (`deploy/observability/alerts/prometheus-rules.yaml`); the job carries the code (`expression.evaluation_failed` since F-1471), not the rule |
| Nothing in the workspace shows it | true | no endpoint reads `retention_run`; `RetentionPolicy` (`api/openapi.yaml`) has no last run or failure; no notification kind for it; the web app's retention screen shows rules, previews and effective rules only |
| A condition can compile and still fail on some entries | true | F-1471: division by zero, a missing key, a conversion, an index — on values of one entry; `item.labels[0] == 'x'` fails on an entry without labels |
| UC-LIF-04 names no failure | true | its *How to check* 1–9 and *Where it ends* say nothing about a rule that fails; UC-AUT-07 (automation) has "a rule that fails every time … stops itself, tells its author" — retention has no such sentence |

## 3. Decisions

- [x] O1 **One rule's failing condition stops only that rule, for that pass** — decided by: the owner,
  2026-10-15, decision #1502 (option A) → data-retention.md §2, UC-LIF-04 check 10.
- [x] O2 **The rule shows `last_failure {code, at}`, read-only, written in its own transaction and
  cleared by the next clean evaluation** — decided by: the owner, 2026-10-15, decision #1502 →
  data-retention.md §2, UC-LIF-04 check 10.
- [x] D1 The premise correction (§ 1, the `retention_run` row is not kept) goes on #1484 as a comment
  and is noted for F-1471's record readers there — decided by: worker; a wrong statement, not a
  decision.
- [x] D2 **What counts as "cannot be evaluated"**: a validation error from compiling or evaluating
  the condition. An unavailable database while resolving `item`, and an engine that is not wired,
  still fail the pass: neither is the rule's fault, and setting the rule aside would mark it failing
  for an outage — decided by: worker.
- [x] D3 **"Its entries are neither announced nor removed"** includes phase two: entries the rule
  marked in an earlier pass are not acted on while it is set aside, and its second stage is not
  announced — decided by: worker; the decision's wording, and the safe direction for a deleting
  pass. Block markers a page flushed before the failure was met stay: they announce nothing and
  remove nothing.
- [x] D4 **"Clean" is per rule and pass**: a rule the pass judged at least one candidate against
  without a failure. A rule the pass did not reach keeps what it shows — decided by: worker.
- [x] D5 **The separate transaction** is a new persistence seam, `persistence.Independent`, beside
  `Writable`: it always opens its own transaction on another connection. Named for its one use and
  its one danger (§ 2(d)) — decided by: worker. Rejected: writing in the pass's transaction (lost
  when the pass rolls back, which the decision rules out); a job of its own (a second schedule for a
  record that belongs to the pass).
