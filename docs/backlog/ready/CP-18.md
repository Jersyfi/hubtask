## 2. Coverage and the matrix

**(a)** UC-INS-14: check 8 (use offered for billing only while metering is on) — this task. Checks
1–7 and 9 onward are not touched: they concern the platform's subscriptions and deliveries, not the
instance level's write. No other use case's *Today* names this code.

**(b)** Not a change of access, a lifecycle or a state machine: one stored switch. The doors that

metering` — all reach `InstanceSettingRepository.Write` through `InstanceWriter.Write`

comparing before and after.

**(c)** Definition of Ready: use case UC-INS-14 check 8; contract none; migration none; locale none;

**(d)** Standing rules: rule 3 (the write stays inside the caller's transaction); rule 9 (the query

version (`AdvanceInstanceLevelVersion`) already orders them; this changes nothing there. Known trap
"the integration tests share one database": the test restores the level it read (`t.Cleanup`).

## 3. Decisions

- [x] D1 Clear the `metering` area, rather than always writing the row with `false` — decided by:
  worker — the write already means "what is not written is not decided" for every other area; a
  `false` row would be the one key written for its default. Rejected: always writing the row.
- [x] D3 No migration heals an installation that stored the stale row — decided by: worker — the
  screen and `GET /admin/settings` show the truth (on), so the operator sees it and switches off
  once more; a migration would have to guess intent from the journal. The release notes say it.
  Rejected: a forward migration reading the journal's last `metering` change.
- [x] D2 Nothing waits on the owner; #1603 entering CP is the owner's (2026-10-20, Decision 11).
