## 3. Decisions

- [x] D1 Count reads **per stream**. Each request's context carries a stream number, and
  `countingStream` keys its counts by it, as the issue's first proposal says. The test waits until
  every stream has completed its first read, with a deadline that guards only against a hang. Then
  it holds the 300 ms window and asserts that every stream read exactly once. — decided by: worker.
  The window now starts from an event, not from the clock, and the assertion is stronger than
  today's total, since it names the stream that read more than once.
  Rejected:
  - a longer window or a longer sleep, which hides the race;
  - waiting only for a total of 300 reads, which a stream reading twice while another has not read
    yet would satisfy.
- [x] D2 The window stays at 300 ms. It only has to catch a stream that reads again while nothing
  wakes it, and that is detected regardless of load. A poller with an interval longer than the
  window is outside what this test ever measured, and that is unchanged. — decided by: worker.
