# SC-05 — Operators and machines

**Task:** SC-05 · issue #1061 · `docs/backlog/milestone-SC.md`
**Checked against:** `origin/main` at `ba307730` on 2026-10-12
**Verdict:** ready

Four groups of work:
- **The register a person can read.** Operators are listed by name, address and workspace, with
  "you" marked. Adding the first entry also adds the person adding it. Only active accounts can be
  added. *Remove* confirms, and removing oneself asks twice. A service account is chosen from a
  list.
- **The hour that holds.** A token refresh and a reload keep `elevated_until`. A second elevation
  cannot replace a running hour.
- **The terminal.** `hubctl token create` sends the step-up. `hubctl admin elevate` raises a
  signed-in terminal session.
- **The private installation.** On a single-mode installation, *Installation* is the last section
  of *Administration*.

Migration 0135 (assigned by the coordinator).

## 3. Decisions

- [x] D1 **The list's names come from one narrow function.**
  - `operator_roster(p_caller uuid)` is `SECURITY DEFINER` and answers the register's rows joined to the account (display name, address, kind) and its workspace (short name, name), plus the adding account's name.
  - It answers **no row** unless `is_operator(p_caller)`, so the app role cannot use it to enumerate anything the register's own use case would not show.
  - It names only registered accounts, never a workspace's other accounts (UC-INS-05, *Where it ends*).
  - Decided by worker. Rejected: one read per workspace under its own scope — N transactions and a scope switch per row (trap: a nested scope may not switch tenant).
- [x] D2 **The first entry adds the person adding it, in the database.**
  - `enlist_operator(p_account, p_by)` answers an outcome: `added`, `added_with_caller`, `present`, `not_active` or `unknown`.
  - It takes `LOCK TABLE operator IN SHARE ROW EXCLUSIVE MODE` before reading "empty", inserts the caller too when empty, and refuses any account not `ACTIVE` and undeleted.
  - `AddOperator` journals each row it added.
  - The screen knows the register is empty from the list it just read, and says so before *Add*.
  - Decided by worker (UC-INS-05/3). Rejected: refusing the first addition unless the caller is named — it would make the owner do two things for one intent.
- [x] D3 **Expand, not replace.**
  - `add_operator` and `drop_operator` stay unchanged for an older pod during the rolling update and for SC-04's environment and machine doors.
  - Those two doors move to `enlist_operator` in this task, so they also refuse a non-active account.
  - The header of 0135 names the contraction (drop the two old functions) for a release after this one.
  - Decided by worker (rule 12).
- [x] D4 **Removing tells absent from last.**
  - `dismiss_operator(p_account)` answers `removed`, `absent` or `last` in one statement.
  - `absent` is `admin.operator_not_registered` (404), so the screen no longer tells a stale row "this is the last operator".
  - Decided by worker. A finding in check 5's area; its own commit, test first.
- [x] D5 **A service account is chosen from the reader's own workspace.**
  - The picker lists `GET /auth/service-accounts` of the workspace the operator is signed in to. That is the workspace the story creates it in, and a read its member managers already have.
  - It never lists another workspace's accounts (UC-INS-05, *Where it ends*). `hubctl admin operator add --service-account <name>` resolves the same list by display name.
  - Decided by worker. Rejected: an installation-wide service-account list — a cross-workspace account list, which *Where it ends* rules out.
  - **No new route** (review F1): `GET /auth/service-accounts` (`listServiceAccounts`, `api/openapi.yaml:3826`) is the existing listing behind `hubctl service-account ls` (`cmd/hubctl/Token.go:183`) and the administration's *Service accounts* screen. The picker and `--service-account` reuse it unchanged. Moving it in the URL space is a rename of an existing route, which is on the owner's list and not this task's.
- [x] D6 **"Single-workspace installation" is single mode.**
  - Where `tenancy_mode` is `single` and the reader can reach both areas, *Installation* moves from the account menu to the administration's last group, labelled "Installation — applies to every workspace you create" (UC-INS-04, Story). The row opens `/instance`, which keeps its own section.
  - Where the administration is not reachable for an operator, the account-menu row stays, so the area never disappears for somebody entitled to it (P-05).
  - A multi-mode installation that happens to hold one workspace keeps the account-menu row, because it is a platform's arrangement that will grow.
  - design-system.md §11.3 is corrected to say so.
  - Decided by worker.
- [x] D7 **A running hour is not replaced.**
  - `ElevateSession` refuses `auth.session_already_elevated` (409, `params.until`) **before** asking for the proof, so a client that lost its copy learns the end without spending a password.
  - The `UPDATE` writes only where no hour stands, so two raises at once leave one.
  - The web app adopts `until` from the refusal.
  - Decided by worker. It enforces UC-INS-04/4 as written, which no *Today* listed. A finding, own commit, test first.
- [x] D8 **The client keeps the hour across a rotation.**
  - `TokenStore` gains `rotate(pair)`, which replaces the pair and leaves the hour. The engine's `renew()` calls it through a new seam `platform.renewSession`.
  - `write` stays the new-session path that drops it.
  - Decided by worker. Rejected: re-reading the hour from the server after every refresh — the contract has no read of it, and a new route for a value the client already holds is speculative.
- [x] D9 **`hubctl admin elevate`**:
  - It runs on a `hubctl login` profile through `cli.proveAgain` and `POST /auth/sessions:elevate`, prints the end and the minutes left, and stores nothing new in the profile. The hour is the session row's, and the profile's own refresh rotates the same session.
  - On a token profile it is refused locally by the existing `cli.stepUp` sentence.
  - Decided by worker (UC-INS-04/6).
- [x] D10 **`hubctl token create` goes through `cli.proveAgain`** with `PostWithHeader`, like `admin tenant delete`. A scope that needs no proof makes no extra round trip. Decided by worker (UC-ID-17/3, UC-INS-06/2).
- [x] D11 **Corrections:**
  - design-system.md §11.3 (D6).
  - identity.md §19 (the register's functions, the self-entry, the unreplaceable hour, `hubctl admin elevate`) and §21 (I-4 built; the second I-9 renumbered I-12, the next free one).
  - The stale port comment and the German comment named in § 1.
  - Coordinator, 2026-10-12; worker for the rest.

Open for the owner: none. No field is renamed or removed, and no use case's *Goal*, *How to check* or *Where it ends* changes. D6 and D7 read the use cases' own words.
