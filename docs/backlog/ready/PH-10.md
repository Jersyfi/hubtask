## 3. Decisions

- [x] D1 **Any hold in force stops both acts.** A deletion request is refused, a pending workspace
  stays pending until the last hold is lifted, `REPLACE_TENANT` is refused, and one that runs keeps
  the workspace's holds — decided by the owner, 2026-10-09, decision #1233 (a) → data-protection.md
  §5, backup-restore.md §8.2, multi-tenancy.md §5, data-retention.md §4, UC-LIF-06 check 3, milestone
  decision 6 (pull request #1236). Every scope counts, `ACCOUNT` included: a workspace's deletion
  destroys a person's contributions as surely as a hub's.
- [x] D2 **The refusal.** `lifecycle.legal_hold`, 409, with the scope of the oldest hold in force
  and no reason — the code UC-LIF-06 check 3 names and `Purge.go:359-363` already answers. Asked
  before the typed name and the step-up, so a refusal never burns a proof (the precedent at
  `Deletion.go:103-104`). Decided by worker.
- [x] D3 **The grace job under a hold.** The guard reads the holds in its read-only transaction
  before any byte is removed, and the final transaction reads them again before the fall. Under a
  hold the pass removes nothing and returns `Repeat` with a day, so the deletion follows within a
  day of the last hold's release, whatever lifted it. A pending workspace whose deadline lies ahead
  repeats until the deadline instead of finishing — otherwise a second request folded into the
  waiting row (`Job.sql:32-34` keeps the earlier `run_at`) would run early, find the deadline ahead
  and end the only job (relevant once SC-08's *Cancel deletion* exists). No journal entry per pass:
  an entry per retry puts noise where evidence lives (`Lifecycle.go`'s precedent); the hold's own
  trail and the operator's listing (D10) say why the workspace stands. Decided by worker. Rejected:
  finishing the job and letting the release seed a new one — no release can reach a pending
  workspace (§ 1).
- [x] D4 **How a pending workspace under a hold gets out.** Access stays blocked
  (multi-tenancy.md §5), so its owner cannot release the hold while it is pending; the way back is
  SC-08's *Cancel deletion* (#1064), then the release, then a new request. The state arises only
  through the race of § 2(b), an older binary accepting a request during a rolling update, or a
  workspace already pending with a hold when this ships — the safe side of #1233 either way.
  Decided by multi-tenancy.md §5 and decision #1233; no deviation, no question.
- [x] D5 **A rehearsal stays possible.** Only a `REPLACE_TENANT` with `dry_run: false` is refused;
  the rehearsal writes nothing and keeps UC-BAK-05 check 1 ("any mode can be rehearsed") as
  written. The screen then offers no real run (D11). Decided by worker. Rejected: refusing the
  rehearsal too — it changes UC-BAK-05 check 1 for no protection.
- [x] D6 **Asked twice.** `StartRestore` refuses where the caller can read it; the restore job asks
  again inside `emptyTenant`'s transaction, under PH-01's shared lock, before anything is emptied,
  and fails the run with `lifecycle.legal_hold`. The safety copy taken before it stays: harmless,
  and the way back if anyone wants one. Decided by worker (known trap "read-then-write without a
  lock").
- [x] D7 **No restore into a living workspace writes a hold.** `REPLACE_TENANT` does not empty
  `legal_hold`; `REPLACE_TENANT`, `MERGE` under every rule and `SELECTIVE` write none of the
  archive's holds and count them as skipped in the report. `NEW_TENANT` brings them along as today:
  a new workspace — another installation's export included (#1074) — keeps the obligations it
  arrives with. Decided by worker, under data-retention.md §4 as #1236 words it ("a restore that
  runs keeps the workspace's hold records, never the archive's"). Rejected: `REPLACE_TENANT` only —
  a merge with `overwrite` would re-open a released hold and wipe its release (UC-LIF-06 check 7).
- [x] D8 **Finding: a resumed replace empties again.** `emptyTenant` records `emptied_at` on the
  run (migration 0121, expand only) in its own transaction; a resumed attempt that finds it set
  skips the emptying. Without it a hold placed mid-run would make the resumed attempt refuse (D6)
  and strand a half-restored workspace. Test first; if the test shows the resume already safe, the
  step shrinks to the test. Decided by worker (AGENTS.md, findings on the branch).
- [x] D9 **Finding: the import drops a hold's release reason.** `ImportLegalHold` gains
  `released_reason`. Test first. Decided by worker.
- [x] D10 **The operator sees that a hold stands.** `admin_tenants()` answers `legal_hold`
  (migration 0122, the 0118 precedent), `AdminTenant` carries it, `ListTenants` outputs it. A
  boolean only — no scope, count or reason: the operator needs to know the deletion cannot proceed,
  not what the workspace is preserving. The console leaves *Delete* out for a held workspace and says
  why; a pending one says its deletion waits on a hold; `hubctl admin tenant ls` marks both. Decided
  by worker (P-05 "broken when", P-08, P-11). Rejected: the refusal alone (P-05).
- [x] D11 **The restore screen.** *Replace* is offered only where the manifest grants
  `DELETE_CONTAINER` (`permissionVerdict`) — a finding, own commit — and its real run only while no
  hold is in force, read from the holds list (`ListLegalHolds`, `STRUCTURE`, which every owner
  holds). Decided by worker (P-05).
- [x] D12 **UC-BAK-05 check 5.** "Holds exactly what the archive held" gains "apart from its legal
  holds, which stay the workspace's", and `tasks:` names PH-10; labelled `decision #1233` in the
  description. Decided by the owner's answer, which this wording only carries into the check.
- [x] D13 **Outside this task.** Side findings (a) and (b) of § 1 become `finding` issues, opened by
  the coordinator and named in the pull request; #1150 stays its own fix. Decided by worker
  (AGENTS.md, "Working rules").
- [x] D14 **Order.** The code waits for #1211 (PH-01): the lock of its D7 is what makes the
  two-writer rows hold, the `Active` port it changes is the one read here, and `LegalHolds.go`,
  `Lifecycle.sql` and the repository port are shared files. #1236 lands before the last step, which
  turns its "decided, not built (#1228)" sentences into built ones. Decided by worker.
