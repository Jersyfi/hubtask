## 3. Decisions

- [x] D1 The eight AI asks answer `JobRef` — decided by: worker. api-guidelines.md allows it, it is
  additive, and it is the only way a client learns which job is its own. Rejected: a refusal as a
  suggestion row (a suggestion is a proposal somebody accepts).
- [x] D2 A refusal met by the job ends it in the stored state `FAILED` with the refusal's code and
  parameters, outside `Runner.fail`: no retry, no dead-letter count, no A-07, logged at info —
  decided by: worker. `FAILED` with a code is the contract's "did not work and will not be tried
  again"; `DEAD_LETTER` and A-07 are for work an operator must look at, and a spent budget is an
  answer. Mechanism: `queue.Result.Refusal` from the handler; `queue.Failure` gains `Refused` and
  `Params`, which `Queue.Fail` writes with a new fenced statement. Rejected: `SUCCEEDED` with a code
  (the contract sets the code on a failed job); the dead letter with only the metric skipped (an
  operator's queue fills with answers).
- [x] D3 The refusal's parameters travel: column `job.last_error_params jsonb`, `Job.error_params`
  in the contract — decided by: worker. Without them a spent budget reads "AI is switched off",
  which is false (§ 1). Rejected: a second code for the budget (ADR-0049 keeps one refusal); asking
  the workspace's AI state again from the web app (no member-readable surface says it).
- [x] D4 The web app follows the job beside the listing in all four follows; a `FAILED` job with a
  code ends the follow as `refused` — decided by: worker.
