## 3. Decisions

- [x] D1 Under `ANY` on a shared Microsoft endpoint (`/organizations`, `/common` of a preset with a
  templated issuer) the arrival's directory must be in the list; an empty list admits nobody —
  decided by: identity.md §10.3 ("the directory list decides") and #1380's proposal. Written in
  §10.4 as a bullet beside the `INVITED_ONLY` one, and in `MayAdmit`'s comment.
- [x] D2 Only the shared endpoints: `ANY` on one directory's own issuer still reads no list —
  decided by: worker. The test is `multiDirectoryIssuer && SupportsTemplatedIssuer`, which only
  Microsoft's preset meets; Google never has `ANY` (a public preset, `resolvedProvisioning`) and
  `GENERIC` has no directory claim, so neither is in scope. A Microsoft directory's own issuer is its
  own bound (a token from another directory does not verify against it), and narrowing it by a list
  would change rows #1380 does not concern; the web app also
  sends a hidden list left from a previous `DOMAINS` choice, which a wider rule would start reading
  silently. Rejected: "a non-empty list narrows `ANY` everywhere" (wider than the finding, and
  changes what existing rows admit).
- [x] D3 The save rule needs no change: `directories_required` is already enforced in every mode at
  both levels on the one constructor (§ 1) — decided by: worker, from the code; the configuration
  test pins it.
- [x] D4 A `methods` that `Tightened` does not report as moved is dropped from the patch before the
  last-way-in guard and the merge — decided by: worker, #1381's first proposal. The comparison is the
  one `Tightened` makes (against the rule in force), so the guard and the lock never disagree about
  what "changed" means; and dropping it, not only skipping the guard, keeps the resent value out of
  the workspace's own row, where it would pin the installation's `[OIDC]` and take effect with no
  guard once the installation lifts its lock or changes its default (the review's finding 1).
  Only `methods`: pinning another resent switch is today's behaviour for every switch and guards no
  way in. Rejected: letting the lock answer first for a locked switch (an unchanged locked value
  would still be judged by the guard when the lock check is skipped for it, and still pinned).
- [x] D5 No use case's *Goal*, *How to check* or *Where it ends* changes; identity.md §10.4 is
  corrected, not changed in substance (§10.3 already states the rule) — decided by: worker.
