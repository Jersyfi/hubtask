## 3. Decisions

- [x] D1 `features.mail` withholds the detour only when it is explicitly `false` — decided by:
  worker. An installation that does not answer the key is a server this client cannot judge, and
  the request is answered alike for every address either way. Rejected: hiding the link itself
  (the person would not learn why there is no way back).
- [x] D2 The no-mail sentence promises no mechanism: no link can arrive, ask whoever runs the
  workspace — decided by: worker. Neither the issue's suggestions nor UC-ID-04's re-invitation
  exist for an account with an address (§ 1); naming one would be the false promise #1319 is about.
  What the owner decides — a local recovery for D1/D2 — is reported, not decided here.
- [x] D3 A refused recovery code gets its own detail code — decided by: worker; the sentence must
  fit the person typing it (P-12), and the presented kind is the caller's choice, so T-02 holds.
  Rejected: choosing the sentence in the client from the field in use (a second place where a
  failure becomes words, which `apps/webapp/AGENTS.md` forbids).
- [x] D4 `CodeField` shrinks its places equally where its container is narrower — decided by:
  worker; a defect of the component at the 375 px rule (design-system.md), fixed where it is.
  Rejected: overriding the component's internals from the profile.
- [x] D5 The provider flow and the step-up render failures through `problem.ts` — decided by:
  `apps/webapp/AGENTS.md` ("a failure becomes words in `lib/problem.ts` only"). A failure of the
  client's own with nothing to quote says `app.something_went_wrong`, as `problem.ts` does.
