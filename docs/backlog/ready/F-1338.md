## 3. Decisions

- [x] D1 Option A of #1338 — decided by: worker, with the coordinator's direction for the owner's
  sweep, 2026-10-13. It changes no use case text and deletes nothing, so it is not on the owner's
  list.
- [x] D2 The arrival travels on the TERMS pending row: `account_id` becomes nullable; a row without
  one carries `link_provider_id`, `link_subject`, `arrival_email`, `arrival_display_name`,
  `arrival_directory`. Checks: arrival columns exactly when there is no account
  (`(account_id IS NULL) = (arrival_email IS NOT NULL)`), and a row without an account is a TERMS row
  with a provider (`account_id IS NOT NULL OR (purpose = 'TERMS' AND link_provider_id IS NOT NULL)`)
  — decided by: worker. The LINK step's columns already hold a provider identity waiting for a proof; the row
  lives minutes and is swept. Rejected: a provisional account in a new status (an account is what
  the finding says must not exist); keeping the OIDC flow alive (it is burned on the callback, by
  design).
- [x] D3 Admission is decided at the callback **and again at agreement**, against the provider as
  configured then (opened as every sign-in opens it: enabled, offered here), from the stored address,
  directory and a verified address — decided by: worker. An administrator who switches the provider
  off or to `INVITED_ONLY` while a step is open gets no new account. The newcomer access is given at
  agreement (`welcome`'s own re-checks); `auth.oidc_provisioned` records `email_verified` true, which
  every admitted arrival has. The address and name are validated (`ProvisionExternal`) at the
  callback too, so a bad one fails before the person agrees.
- [x] D4 The newcomer row is read by a separate repository method, `FindArrivalByToken`, which
  `AgreeToTerms` alone calls — decided by: worker. Every other step keeps reading `FindByToken`, which
  never answers a row without an account, so no other step meets a zero account.
- [x] D5 The terms in force are read before `settleAccount` only when the provider provisions this
  arrival — decided by: worker; one read on those callbacks, none on the others.
- [x] D6 `AgreeToTerms` gains an optional `Arrivals` (implemented by `OidcWriter`): it opens the
  provider before the agreement's transaction (a nested scope may not switch tenant) and provisions
  inside it. Without it wired, a newcomer's credential is refused as unknown — decided by: worker.
- [x] D7 Retention stays the pending row's: minutes, swept with the sessions; no account means no
  erasure path is needed beyond that, and no archive carries the row. The data catalogue says so —
  decided by: worker; no retention changes, so not the owner's.
