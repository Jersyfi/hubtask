## 3. Decisions

- [x] D1 `accounts` is a quota like the others, in `Names()` and `OperatorNames()`, unlimited in
  both modes by default — decided by: multi-tenancy.md §4's table, the task text.
- [x] D2 Counted: accounts of kind `USER`, not deleted, in status `ACTIVE` or `RESTRICTED`, or
  `INVITED` while the invitation is open (`redemption_expires_at` absent or in the future). An expired
  invitation frees its place, since the contract has no way to withdraw one; renewing it is a door
  — decided by: worker, the owner's rule read literally ("active and managed accounts and open
  invitations; not service accounts, not disabled or anonymised").
- [x] D3 The four doors take a narrow port (`PeopleLimit`), which the quota guard satisfies, so the
  identity service does not import the quota service. A door wired without it enforces no limit, as
  the other optional ports of these use cases read nil, and `cmd/server/PeopleWiring_test.go` reads
  the composition root's literals and fails on any door built without it — decided by: worker,
  rule 1's direction; failing closed would have meant every existing test of the four doors wiring a
  limit it does not exercise.
- [x] D4 `Usage.Accounts` is a plain count; a separate `Usage.LockPeople`
  (`pg_advisory_xact_lock` on `people:` and the workspace, the style of `Identity.sql:369`) is taken
  by the guard only where a limit is set, before it counts, so a read and an unlimited workspace pay
  nothing. Lock order: people before the audit log's lock, never the other way in one transaction —
  decided by: worker; one person too many is not what the owner asked for.
- [x] D5 One `capacity.accounts` sentence serves both readers: "This workspace cannot take anybody
  new: its limit of {limit} people is reached." — it tells the administrator what to raise and the
  person a provider brings why, without asking either to act — decided by: worker.
- [x] D6 A renewal asks the people limit before its new link is written, under the people lock:
  an invitation whose link is still open already counts and adds nobody, one whose link ran out
  takes a place again (`Usage.InvitationOpen`, the count's own condition). In the mail mode the link
  is written later by the mail's job, so a count after the renewal would not see it — decided by:
  worker; the diff review's blocker.
- [x] D7 The guard tells the platform a quota admitted only while the workspace was below the
  limit, so a renewal at the limit leaves the crossing standing — decided by: worker; PL-07's "once
  per crossing".
