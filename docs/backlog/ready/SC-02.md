## 3. Decisions

- [x] D1 The three answers are the use case's words: "Only people invited here", "Anyone from these
  organisations", "Anyone this provider knows" (`de`: "Nur hier eingeladene Personen", "Alle aus
  diesen Organisationen", "Alle, die dieser Anbieter kennt"); the list beneath names directories or
  domains per preset (UC-ID-11 check 4) — decided by: UC-ID-11 *Story*, identity.md §10.4.
- [x] D2 *New people get* is nothing, one role at the workspace, or one group — exclusive, as the
  story's "or" says; stored on the provider row (`newcomer_role`, `newcomer_group_id`), applied in
  the arrival's transaction — decided by: the task text, UC-ID-11 *Story*.
- [x] D3 #1167: the directory list narrows `INVITED_ONLY` for first arrivals on the provider's word
  (`MayAdmit`); an empty list does not narrow under `INVITED_ONLY` (the mode's bound is the existing
  accounts); an arrival bringing its own proof (`LINK`, the connect link, the invitation's link) is
  not narrowed, as under `DOMAINS` — decided by: ADR-0071 §4; identity.md §10.4 gains the line,
  §21 I-7 goes. Rejected: removing the list from the contract (a removal, the owner's).
- [x] D4 `OWNER` is never a newcomer's, directly or through a group — decided by: worker; reason:
  identity.md §16.3 hands `OWNER` to one named person with a fresh proof; every other role is an
  administrator's choice they could make by hand. Rejected: limiting to non-administrative roles —
  a group can carry `ADMIN` anyway, so the limit would be decoration.
- [x] D5 An installation provider carries no newcomer setting; its newcomers get nothing and are
  told — decided by: worker; reason: a group is a workspace's, and an operator does not decide a
  workspace's access (UC-INS-11 *Where it ends*). Rejected: a per-workspace newcomer setting for an
  offered provider — no use case asks for it.
- [x] D6 The newcomer is told through `has_access` on `GET /accounts/me` and the overview's and
  navigation's empty state, for every account without access — not a provider-only flag — decided
  by: worker; reason: the condition is the account's, and an account an administrator emptied is in
  the same position. **`has_access` is exactly `Memberships.HoldsAny`** — any membership of the
  account or one of its groups, at any scope — which is the very condition the server puts on a
  private hub of one's own (`AuthorizeOwnPrivateHub`), so one value answers both "is there anything
  here for me" and "may I create a private hub": a person whose only access is their own private
  hub, or a guest on one entry, is `true` and sees no notice. *Create hub* stays wherever it is
  drawn today and the server accepts it; it is absent only where `has_access` is false, where the
  server refuses every hub (§ 1) — the notice stands there instead of a control that would be
  refused (P-05). Re-read when the window regains focus, so a grant shows without a reload.
  Whether *Create hub* is drawn for a person with a role but no `STRUCTURE` while private hubs are
  switched off is today's behaviour, untouched here.
- [x] D7 The instructions stop carrying the address; it stands in its own read-only field with
  *Copy* (offered only where `navigator.clipboard` exists, the `FeedsDialog` pattern) on both
  provider screens — decided by: UC-ID-11 check 6.
- [ ] O1 #1166 — may a Google provider be *Anyone from these organisations*, bounded by Google
  Workspace domains (`hd`)? — waiting on the owner: decision issue #1284.
  The problem: UC-ID-11 check 4 and ADR-0071 §2 say yes; UC-ID-09 check 1 ("A public provider
  (Google accounts, personal Microsoft accounts) can only be set to *Only invited people*; the
  setting … cannot be changed") and UC-ID-11 check 2 say no if "Google accounts" means every Google
  provider. Example: Acme runs Google Workspace at `acme.example`; its administrator wants every
  Acme colleague in without inviting each — today only invitations work. **Proposal (a):** "public"
  means the personal-account population; Google may be `INVITED_ONLY` or `DOMAINS` (Workspace
  domains; a personal account carries no `hd` and is never admitted new), never `ANY`; UC-ID-09
  check 1 and UC-ID-11 check 2 read "personal accounts are admitted only by invitation; *Anyone
  this provider knows* is never offered for Google". Effect: administrators (D3, D4, D6) of a
  Google Workspace company admit their people by domain; members unaffected; operators unaffected.
  The Microsoft side finding of § 1 is a defect under either answer — #1285, not this task.
  **(b):** Google stays invite-only; UC-ID-11 check 4 names Microsoft only, ADR-0071 §2's Google
  row is withdrawn, the unreachable Google directory label goes. What waits: step 3 and UC-ID-11
  check 4 for Google; nothing else.
