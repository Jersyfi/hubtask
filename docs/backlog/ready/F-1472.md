## 3. Decisions

- [x] D1 Nesting is bounded by CEL's own `ParserRecursionLimit`, set to 64 (`port.MaxDepth`), not by
  a scan of the text before the parser: the parser already counts depth the way the checker
  experiences it (chained calls, operators, brackets), and a hand scan would count something else.
  64 keeps the worst accepted compile near 50 ms; `&&`/`||` chains are balanced by the parser and
  are not limited by it (150 `&&` terms compile) — decided by: worker. Rejected: 32 (refuses a sum
  of 40 terms for no measurable gain), keeping 250 (3.7 s).
- [x] D2 The deadline is the adapter's own, `port.CompileTimeout`: `Compile` runs parse, check and
  `Program` in `concurrency.Go` and waits for it or the deadline, whichever comes first. The port's
  signature does not gain a context — decided by: worker. Rejected: `Compile(ctx, …)` across the
  15 call sites — the checker cannot be interrupted, so a caller's context would only end the wait
  sooner, which the adapter's own deadline already does; the depth limit is what bounds the work.
- [x] D3 `CompileTimeout` is 1 s: a backstop, not the bound — twenty times the worst accepted
  compile measured, because the run paths compile on every run and a deadline near the real cost
  would refuse legitimate rules under load — decided by: worker.
- [x] D4 A refusal by depth, by CEL's node count, or by the deadline answers
  `expression.too_complex` (VALIDATION, no position), not `expression.syntax`: the expression may be
  perfectly well formed, and "not a valid expression" sends its author to look for a typo —
  decided by: worker; the same reasoning as F-1471.
- [x] D5 The limit is written into automation.md §1.2's table ("Nesting depth · 64 · checked by the
  parser; compiling has a 1 s deadline"), where the other three limits are — decided by: worker;
  implementing rule 7, not a deviation from a rule.

## 4. Proof and steps

Proof, in `infrastructure/expression/CEL_test.go` against the real CEL compiler:
the pathological input (240 `.map`) is refused `expression.too_complex` in under 500 ms; 65 nested
parentheses are refused the same way; a chain of 63 `.map` and 150 `&&` terms still compile; with
the deadline injected at 1 ms (a package variable a test may set, in an internal test file) a 60
`.map` chain is refused `too_complex`. The fuzz target gains the input as a seed and a fifth
property — one compile ends within twice `CompileTimeout` — so the nightly fuzz holds the bound.
`make gate-architecture` holds the code to `locales/en.json`.
