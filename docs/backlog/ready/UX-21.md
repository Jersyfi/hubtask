## 3. Decisions

- [x] D1 **Who asks an on-arrival proposal: the workspace, as the system** — an actor with the
  tenant and no account, the embedding pass's actor. Decided by: the owner, #1629 ("a workspace may
  switch on that a proposal is prepared on arrival" — the workspace is the one who asks); confirmed
  by the review. The switch is the authorisation, written under `STRUCTURE`; the trail names
  `SYSTEM` for each ask and the switcher in `ai.arrival_proposals_set`; the budget is the
  workspace's; the asker's own objection has nobody to apply to, and the content rules apply in full
  (D6).
- [x] D2 **Every ask — on arrival and by a person — offers the model the shared set only**: the
  collections everybody who may convert may write in — not trashed, not archived and not under an
  archived hub (effective archive, I-C3), outside private hubs. Decided by: the review (finding 3),
  the coordinator; worker for the reading. It is exact: converting asks `WRITE_ITEMS` at the
  workspace (domain-model.md §5), roles inherit downwards (§3.2), a private hub is reached only by its
  members. No private hub's collection is ever in a proposal another reader sees. Read by a
  repository read in the material's transaction (a system actor passes no catalogue read; a person's
  ask reads the same set), at most 100 in manual order (hub, then collection); a workspace with more
  offers its first hundred, and the person picks any other. `ListSuggestions`' narrowing of an
  unreadable `collection_id` remains as a defensive check.
- [x] D3 **`ListJumbleDestinations`** (`GET /jumble/destinations`, `hubctl jumble destinations`)
  feeds the person's picker: asks `WRITE_ITEMS` at the workspace (what converting asks), then keeps
  the collections where `CreateWorkItem`'s access request is permitted, through
  `access.Service.Permitted` over the page's paths (nothing audited per collection); answers
  `data[]` of `{id, name, hub_id, hub_name, hub_private}` in manual order, `size` 1–200 (default
  100), `next_cursor`; private hubs the caller is in included. The producer does not read it (D2).
  Decided by: worker (P-05 for the picker; P-08 for `hubctl`); rejected: a `writable` flag on
  `ListContainers` (one call per hub, two questions in one listing).
- [x] D4 **The switch is the workspace's own, off by default, with no installation or plan default
  and no lock**, stored with the AI positions in the archived settings, written by
  `SetAiArrivalProposals` under `aiSourceRequest` and guarded on the workspace's version. Decided by:
  #1629; worker for the level (P-14: no operator or plan decides what of a workspace's content is
  sent).
- [x] D5 **The seed reads only the switch and the replay flag, and enqueues** — a subscriber of
  `jumble.entry.received` in the dispatcher's transaction, `EmbeddingSeed`'s shape. Availability,
  the exclusion, the cap and the settlement are judged at the run, each ending the job with its
  outcome code. Decided by: the review (finding 5); rejected: seeding in the three doors (three
  places), a rule the switch writes (a rule nobody wrote; a plan without automation would lose it).
- [x] D6 **Whose content stays out**: the run reads the exclusion in the material's transaction. An
  arrival whose sender address is a kept-out person's is not material — for mail and webhook
  arrivals the address is the only signal there is. An arrival submitted by a kept-out account, or
  by an agent or a rule acting for one, is not material either: the entry records no submitter, so
  the seed copies the event's `Actor.ID` (as `submitted_by`, for a `USER` or `SERVICE_ACCOUNT`) and
  `Actor.OnBehalfOf` (as `on_behalf_of`) into the job. Decided by: data-protection.md §4.1; worker
  for the mechanism. The same gap for a person's *ask* about a kept-out colleague's capture is
  outside this task: finding F1, a `finding` issue named in the pull request.
- [x] D7 **Asking about a selection is the client asking each selected entry through `:suggest`**,
  four in flight, bounded to the loaded page's undecided entries; no bulk endpoint. Decided by:
  worker — every answer is per entry (its job, its refusal, its card), an agent does the same (P-08),

- [x] D8 **A daily cap on proposals on arrival**, `ai_arrival_proposals_per_day`, a quota like
