## 3. Decisions

- [x] D1 The guard: in `onclose`, run `close()` only when the element is no longer open, read
  from the event's own element (`event.currentTarget.open`) rather than the issue's `node?.open`,
  so it does not depend on the binding's lifetime; in both `Dialog` and `Drawer`, with a comment
  saying why that names the element without angle brackets (the design-system gates read
  comments) — decided by: worker. The event can only say "it was closed at some point";
  the element's own `open` says whether it still is. Rejected: dropping `onclose` altogether (the
  component would no longer follow a closing it did not make, e.g. a future `closedby` light
  dismiss); a generation counter (more state for the same answer).
- [x] D2 `Drawer` in the same pull request — decided by: worker. The issue names "every Dialog";
  `Drawer` is the same defect in the same lines, found while settling this one, and
  `packages/design-system/AGENTS.md` forbids a component changed *as a side effect of other work*
  — this task is the design-system task for the defect, so both components are its subject.
- [x] D3 The proof is a Playwright walk against the stubbed API, not a design-system unit test —
  decided by: worker. `packages/design-system/test` runs `node --test` without a DOM; a native
  `dialog`'s task-queued `close` exists only in a browser. The walks live where the screens are:
  `instanceplans.test.mjs` (the move dialog) and `shell.test.mjs` (the navigation drawer).
- [x] D4 The PL-06 keyboard walk loses its 100 ms pause before reopening — decided by: worker. The
  pause existed only to step around this defect; without it the walk is the person's real pace.
  The new walks are kept beside it because the keyboard walk's red depends on how the protocol's
  round trips interleave with the queued event; theirs does not (§ 4).

## 4. Proof and steps

Proof: the two new walks dispatch `Escape`, let Svelte's microtasks apply it, assert the element
closed, and click the opener — all within one task, so the native `close` event is certainly still
queued when the element opens again — then assert, after it has had time to arrive (200 ms), that
the dialog or drawer is still visible. Both failed on `main` in 5 of 5 runs on 2026-10-20 ("the
reopened move dialog closed itself", "the reopened drawer closed itself") and pass with the fix. The keyboard walk of PL-06 runs
without its pause. Shown in the running app (`docs/evidence/README.md`, "How to walk", *Looking*):
before and after screenshots of both screens in `docs/evidence/F-1600-2026-10-20/`. No new message code.

2. `fix(design-system)`: `Dialog` and `Drawer` ignore a stale `close` event; the two walks, the
   keyboard walk's pause removed.
