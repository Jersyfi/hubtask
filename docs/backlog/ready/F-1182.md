## 3. Decisions

- [x] D1 Removed at once; under a hold kept as today until the last covering hold is released, then
  the retention pass removes it — decided by: owner, 2026-10-10, #1248 → the data catalogue's
  `template` row, data-retention.md §4.
- [x] D2 A removal is a removal like a purge's: a journal entry (`USER` from the deletion,
  `RETENTION` from the pass) and a tombstone through the existing `Removals` port, so a restore does
  not bring the template back (BK-6) and the removal is marked as every removal is
  (offline-sync.md §7) — decided by: worker, on backup-restore.md §7. The tombstone window is not
  waited for: the deletion is a person's own act, as emptying the trash by hand is
  (`ObserveTombstoneWindow` is the automatic path's), devices learn of it from the change log at
  once, and no device can write a template back. The pass removes what a person deleted, so it does
  not wait either.
- [x] D3 Coverage: `Holds.Blocking` with the template's scope as the target — a workspace hold;
  a container hold on its hub or collection, and on the hub of its collection. An item hold never
  reaches a template (it sits on no entry), and an `ACCOUNT` hold does not either: a template names
  no author, and a node's `assignee_id` is not something the person contributed — decided by:
  worker, on data-retention.md §4 ("a hold on a container reaches everything below it") and the
  schema. Rejected: an account hold on anybody named as a node's assignee (a name in a plan is not
  the person's data in the sense §4 gives "contributed").
- [x] D4 The deletion keeps the soft delete as the held path rather than a new state: the row and its
  answers (`templates.not_found`) are what they are today, so nothing reads differently.
- [x] D5 Soft-deleted templates already in the database are removed by the first pass after this
  ships, where no hold covers them — decided by: owner, #1248 (a deleted template is removed;
  what was deleted before is the finding itself). Named here because it removes existing data for
  good on upgrade; an operator learns of it from the release notes.
- [x] D6 No migration and no new index: templates are few per workspace, and the pass reads them
  through `template_tenant_id_uq` filtered on `deleted_at` — decided by: worker.
- [x] D7 The catalogue's `template` row loses "today … a soft delete" and the claim about
  `created_by` (a correction, § 1) — decided by: the facts.
- [x] D8 The pass reports removed templates under no catalogue kind (templates have none and get
  none — no rule may target them): counted into the pass outcome, Removed for the removed rows,
  Blocked `legal_hold` for the held ones, never Matched (the reason the comment texts have) —
  decided by: worker.
