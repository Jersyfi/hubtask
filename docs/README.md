# Documentation

One place per kind of knowledge ([`AGENTS.md`](../AGENTS.md) § "Where knowledge lives"), and this
table names it, with the reader each place is written for. Write it there; elsewhere, link to it.
How a text is written, what a change adds and what it removes is in [How to write](#how-to-write).

| Place | What it holds | Who reads it, with which question | Who writes it |
|---|---|---|---|
| [`vision/`](./vision/README.md) | Why: principles, personas, the deployments D1–D7, non-goals | the owner, and a worker settling a concept: why does Hubtask do this, and for whom? | the owner |
| [`usecases/`](./usecases/README.md) | What must be true for a person — the yardstick for every change | a person checking the product: what must I be able to do, and how do I see that it holds? | the owner decides *Goal*, *How to check*, *Where it ends*; workers keep *Today* and the state |
| [`architecture/`](./architecture/arc42.md) | The current rule of each concern, one subject document per concern; arc42 is the entry; the configuration document and templates are [`configuration.md`](./architecture/configuration.md) | a worker about to change that concern: which rule holds here today? | the worker that changes a rule, in the same pull request |
| [`design/`](./design/design-system.md) | The design system and the product's voice; the direction for the user experience — where each product lives, the first start, the shared patterns — is [`architecture/user-experience.md`](./architecture/user-experience.md) | a worker building a screen: which component, token and word do I use? | the worker that changes a rule, in the same pull request |
| [`adr/`](./adr/README.md) | Why and when each decision was taken — a log, not the rules | someone tempted to undo a decision: why is it this way? | the worker that records a decision, named to the owner |
| [`backlog/`](./backlog/README.md) | Running milestones with what they deliver, their tasks and decisions; how work runs | a worker starting or resuming work: what runs, what comes next, how does work move? | workers, at a cut and while a milestone runs |
| [`privacy/`](./privacy/data-catalog.md) | The data catalogue, technical and organisational measures, the control mapping an operator's attestation cites, the NIS2 supplier pack, AI providers, the breach runbook | an operator or an auditor: which personal data is held, why, and for how long? | the worker whose change touches personal data or a mapped control |
| [`audit/`](./audit/event-matrix.md) | The event matrix | an auditor: which act leaves which event? | generated by `make generate`, never by hand |
| [`reference/`](./reference/settings-matrix.md) | Who configures what: every setting by level, its writer and the shipped roles that carry it | an administrator: who changes this setting, and at which level? | generated by `make generate`, never by hand |
| [`evidence/`](./evidence/README.md) | Runs no pipeline can make, and the current coverage report; a use case check is proven by a test instead | a worker or an auditor: what was run by hand, and what did it show? | the worker that made the run |
| [`archive/`](./archive/README.md) | Closed milestones, old run records, superseded drafts — history only | someone tracing history: what was decided or built then? | moved there when done; only its links are kept working |
| [`roadmap.md`](./roadmap.md) | What is still ahead on the way to `1.0.0`, and the suite after it | a visitor or the owner: what is still ahead? | workers, at a cut or a release |
| [`CONTRIBUTING.md`](../CONTRIBUTING.md) | The way in for a person: set-up, a pull request, translating, the licence | a newcomer: what is welcome, and how do I take part? | the worker that changes how contributing works |

Traps that have no home in code or a subject document are in
[`architecture/known-traps.md`](./architecture/known-traps.md). A question for the owner is an issue
labelled `decision`; something found next to the work is fixed there, and only what is clearly
bigger than a step becomes an issue labelled `finding`.

## How to write

As much as needed, as little as possible, for a person
([ADR-0106](./adr/ADR-0106-an-independent-review-and-the-owner-on-the-loop.md)). These rules hold
for every document, every `AGENTS.md`, every skill and every pull request description.

1. **Write for the reader of that place.** The table above names the reader and the question the
   reader brings. A sentence that does not help that reader act is left out.
2. **A sentence stands alone.** A person who has read only this section understands it. A citation
   (`rule 10`, `UC-ID-12/4`, `§9`) supports a sentence; it does not replace what the sentence says.
   No coined label, no abbreviation the glossary ([`arc42.md`](./architecture/arc42.md) §12) does
   not hold, no chain of arrows or symbols in place of a sentence.
3. **One word per thing**, and it is the domain model's word.
4. **The present only.** A document says what holds today. What held before belongs to the ADR and
   the archive; what is planned belongs to the backlog. The words "previously", "new", "now" and
   "updated" mark a sentence that tells history.
5. **Short sentences in full words.** A text gets shorter by leaving things out, not by
   compressing what stays.

No document has a length limit, because a limit produces shorthand. A code comment is a few
lines. The root `AGENTS.md` holds the map, the rules and the loop, and no step-by-step procedure:
a procedure is a skill.

**What a change owes.**

| The change | The documentation it owes |
|---|---|
| A fix | Nothing. The test says what is true and the commit says why. A document that was wrong is corrected. |
| New or changed behaviour | The use case's *Today*, state and `checked_by`; the subject document's section if a rule changed |
| A new rule or structure | The subject document's section; an ADR only by the test in [`adr/README.md`](./adr/README.md) |
| A mistake that passed every gate | One entry in [`known-traps.md`](./architecture/known-traps.md) |
| Any change | No file where a section of an existing file fits. A section of the description with nothing to say reads "None". |

**What a change removes.** A change that makes a sentence false rewrites or deletes that sentence
in the same pull request. It appends no correcting paragraph, no "update" note and no struck-through
line.

| The text is | In the change that causes it | What keeps it safe |
|---|---|---|
| False from this change on | Rewritten or deleted | The author searches every tracked file (`git grep`) for each name the change renames or removes: an operation, a setting, a table, a message code, a section number. That reaches `docs/`, every `AGENTS.md`, the skills, the Markdown files at the root, the `Makefile`'s help comments, the workflows, `scripts/` and the comments in the code. The reviewer runs the same search on its own. |
| True, and said in another place too | May become a link | Only after reading that the other place says it |
| True, said only here, and seemingly unnecessary | Left as it is | It waits for a tidy pass: one document per pull request, no rule changed (`.agents/skills/tidy/SKILL.md`) |

Deleting stays safe because an ADR keeps the reasoning and is not edited, a numbered section keeps
its number, `make gate-docs` refuses a citation of a section that is gone, and the diff shows every
removed line to the reviewer.
