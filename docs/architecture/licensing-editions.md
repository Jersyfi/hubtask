# Licence and Edition Model

> This document describes what was decided and how it is implemented. The decision itself, with
> the options weighed against each other, is [ADR-0013](../adr/ADR-0013-licensing.md).
> It is not legal advice.

---

## 1. What the requirements demand

| Requirement | Consequence |
|---|---|
| Source is public, community contributes | Public repository, readable history, contributions accepted under a CLA |
| Private self-hosting: **all** features, no limits | No feature gate anywhere in the core |
| Commercial use is sold, to companies | The licence must reserve commercial production use |
| Funding model may change later | No rights given away that would block the change |

A permissive licence (MIT/Apache-2.0) fails the third point: it hands unrestricted commercial use
to everyone, including large providers, for nothing.

## 2. The licence

**Business Source License 1.1.** The full text with the parameters filled in is [LICENSE](../../LICENSE).

| Parameter | Value |
|---|---|
| Licensor | Jérôme Bastian Winkel |
| Licensed Work | Hubtask, all versions |
| Additional Use Grant | Free use — including production self-hosting with the full feature set — for any non-commercial purpose. Covers private and household use; non-profit and public-benefit organisations; teaching and non-commercial research; and evaluation, development, demonstration and contribution, including by companies. |
| Change Date | Three years after a given version is first publicly distributed |
| Change License | Apache-2.0 |

Two consequences worth stating plainly:

* **This is not "open source" in the OSI sense.** It is source available, and it converts to open
  source on a schedule. Describing it as open source in marketing would be false, and the project
  does not do it.
* **The Change Date applies per version.** Version 0.4.0 published in March 2027 is Apache-2.0 in
  March 2030, regardless of what happens to newer versions, to the project, or to the Licensor.
  That is the guarantee against abandonment and against a rug pull.

### Who needs a paid licence

| Who | Needs a paid licence? |
|---|---|
| A private person self-hosting for themselves or their household | No |
| A registered non-profit using it for its charitable purposes | No |
| A school or university, for teaching; anyone, for non-commercial research | No |
| A company evaluating, testing, or developing against it | No |
| A company running it for its own operations or customers | **Yes** |
| Anyone offering it, or a service built substantially on it, to third parties for a fee | **Yes** |
| A freelancer or sole trader using it in their professional practice | **Yes** |

The freelancer line is the debatable one, and it was drawn deliberately: the model is "free for
private persons, paid for commercial activity", and a sole trader's practice is commercial
activity. It is also the line most likely to be revisited.

**No-cost commercial licences** are granted on request to non-profits, educational institutions,
and public bodies whose use falls outside the Additional Use Grant, and case by case to small
projects where charging would be absurd. This is policy, not licence text — it can be adjusted
without amending anything, and it is the pressure valve for a boundary drawn strictly.

Requests: licensing@hubtask.eu.

**The CI licence gate** blocks GPL and AGPL dependencies. This is not ideology: a copyleft
dependency would make it impossible to relicense the result, which would break both the commercial
licence and the promised conversion to Apache-2.0.

**Trademark protection matters more than licence text** for keeping the project's identity. The
licence permits forks; the trademark policy means a fork cannot call itself Hubtask. Official
container images come only from the project registry.

## 4. Editions

There is **one** code path and **one** image. The differences are legal and operational, never
functional:

| Edition | Audience | Technically |
|---|---|---|
| **Community (self-hosted)** | Private individuals, non-profits, evaluation, development | `HUBTASK_TENANCY_MODE=single`, every feature active, no licence key, no telemetry |
| **Commercial** | Companies, service providers | Adds a licence key as legal evidence, optional metering, optional add-ons (SLA support, managed instances, SCIM/advanced SSO, extended retention) |
| **Hosted** (later) | Customers who do not want to operate it | Multi-tenancy mode plus billing |

Implementation rules:

1. **No feature kill switch in the core.** `EditionPolicy` describes only limits that make
   operational sense (tenant count, rate limits) and is unbounded in community mode.
2. **Metering is opt-in** and off in self-hosting. `UsageRecord` (active users, items, automation
   runs, storage) exists as a port and a data model so that *any* billing model can be built later
   without touching the domain.
3. **No telemetry without consent.** An optional, documented, anonymous version ping, off by
   default.
4. **Optional commercial add-ons** — if they ever arrive — live in a separate `ee/` directory with
   its own licence file and attach through the same ports. The core stays fully functional and
   buildable without `ee/`.
5. **The licence key** (later) is a signed token with a validity period and a scope, verified
   offline, with no network requirement. An invalid key does **not** restrict any functionality;
   it produces a notice in the admin area. Technical enforcement would contradict requirement 2
   and would cost more trust than it protects revenue.

## 5. Funding, and what happens if it does not work

Maintenance is currently funded by donations ([GitHub Sponsors](https://github.com/sponsors/Jersyfi))
and, once companies start using it in production, by commercial licences.

The commitment to private users is: **free, with the full feature set, for as long as maintenance
is sustainable.** That is a real commitment, and it is also an honest one — it has a condition
attached, and the condition is stated rather than hidden.

If donations and commercial licences stop covering maintenance, the options, in order of
preference:

1. Widen the commercial boundary — for example, treat freelancers and very small companies as
   paying users where today they are borderline.
2. Introduce a paid tier for *new* private-use features, leaving the existing feature set free.
3. Move to a different licence model for **future versions**. Everything already published keeps
   its terms and its Change Date; no rights are ever withdrawn retroactively.

Any such change is published as an ADR **before** it takes effect, not announced afterwards.
That sequencing is the whole difference between a licence change and a rug pull.

## 6. Settled questions

These were open before the repository went public. They are closed, and the reasoning is in
ADR-0013:

* **Licensor** — Jérôme Bastian Winkel, as a natural person. A later transfer to a company is
  possible; the CLA already permits sublicensing, so it needs no contributor consent.
* **Definition of commercial use** — written out in the Additional Use Grant, with the
  freelancer boundary made explicit rather than left to interpretation.
* **Change Date** — three years, chosen over four because the guarantee is what the community
  gets in exchange for a non-OSI licence.
* **CLA tooling** — CLA Assistant, triggered on the first pull request.
* **Legal review** — the Licensor's own responsibility, outside the project backlog.

Still genuinely open, and tracked as product work rather than licensing work:

* Trademark registration for the name and logo (availability check at DPMA/EUIPO).
* When commercial licences start being sold, and in what form. The metering data model stays
  inactive but present until then.
