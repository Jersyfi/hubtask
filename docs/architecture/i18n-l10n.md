# Internationalisation & Localisation

The application must support **every language** — not just translation, but timekeeping, sorting,
search, text direction and formats.

---

## 1. The ground rule: the server delivers no display text

Every human-facing output of the API is a **code plus parameters**, never a finished sentence
([ADR-0011](../adr/ADR-0011-i18n-message-codes.md)):

```json
{
  "code": "activity.item_completed",
  "params": { "actor": "Anna", "item_title": "Review the quote", "at": "2026-08-14T09:12:00Z" }
}
```

So every language is possible without a backend change (QS-08), and one event can appear in
different languages in different clients.

**Exceptions** where the server renders: **email**, and the sentences `hubctl` shows a person. They
go through the `i18n` port in the **recipient's** locale, not the trigger's — the account's, else the
workspace's default, else the installation's (§2). The ICS feed is not an exception: it composes no
sentence. The product has no push notifications and no PDF; the one notification channel is
`EMAIL`.

The catalogues are embedded in the binary (every `locales/*.json`) and can be overridden from
`HUBTASK_LOCALE_DIR`: a file for a carried tag overrides it key by key, a file for a new tag adds the
locale.

## 2. The locale model

| Level | Field | For a signed-in person | For an anonymous request |
|---|---|---|---|
| Account | `account.locale`, `account.time_zone`, `account.week_start?` | 1 | — |
| Request | `Accept-Language` | 2 | 1 |
| Tenant | `tenant.default_locale`, `tenant.default_time_zone` | 3 | — |
| Installation | `HUBTASK_DEFAULT_LOCALE`, `HUBTASK_DEFAULT_TIMEZONE` | 4 | 2 |

An account's preference is not overridden by the browser at hand; the header decides only where no
account has spoken. The server resolves the chain in `AuthenticateToken`, the client in `locale.ts`,
by the same rule.

* Locale format: **BCP 47** (`de`, `de-AT`, `pt-BR`, `zh-Hans`, `ar-EG`).
* Negotiation through `golang.org/x/text/language` (`language.NewMatcher`), built once over the
  catalogues present with the source language as default, shared by the REST middleware and the
  renderer ([ADR-0056](../adr/ADR-0056-golang-x-text-and-idna.md)): `de-AT` lands on `de` when that
  is what there is, `pt-BR` prefers `pt-BR` over `pt`. The actor carries the client's own tag, region
  included (content language and week start want it); the catalogue is matched again at render
  time, down `de-AT → de → en`.
* An `Accept-Language` that is unplaceable, malformed or over the bound resolves to the installation
  default and is **never refused**: a wrong language is a nuisance, a refused request an outage.
* Time zones: **IANA** (`Europe/Berlin`), never fixed offsets; `time/tzdata` is embedded, so the
  container needs no system tzdata.
* The permitted locales are data: `/meta/capabilities` returns `supported_locales`, derived from the
  catalogue files present (embedded and `HUBTASK_LOCALE_DIR`), so a language is a file, not a
  release. Each entry carries direction, week start and decimal separator (§6). The account's
  language picker is this list.
* **The `1.0` locale set** is eleven: the ten most spoken languages by total speakers (Ethnologue
  2025) and German — `en`, `zh-Hans`, `hi`, `es`, `ar`, `fr`, `bn`, `pt`, `ru`, `id`, `de`. A locale
  is *selectable* when its catalogue is present; the binary carries `en` and `de`. §6's metadata
  table covers all eleven.

## 3. The message catalogue

| Aspect | Rule |
|---|---|
| Format | **ICU MessageFormat**, in the subset below |
| Files | `locales/<locale>.json`, one flat file per locale, source language `en` |
| Keys | Hierarchical and semantic (`errors.capability_not_supported`, `email.reminder.subject`). A key beginning with `_` is a translators' note, skipped by both renderers |
| Plural rules | CLDR categories (`zero/one/two/few/many/other`) — required for Arabic, Polish, Russian |
| Register | One register through a whole file — the second person of [voice-and-tone.md](../design/voice-and-tone.md) 1.4, in German *du*. A code whose English is a placeholder stays one |
| Translation process | Pull requests against `locales/`, in a layout Weblate reads unchanged; `CONTRIBUTING.md` § "Translating" says how, `make locales` how far. Translated by hand by somebody who reads the language: an unread machine translation is not shipped, because the source fallback is better ([ADR-0055](../adr/ADR-0055-translation-process.md)) |
| CI | `test/architecture/translations_test.go` (`make gate-architecture`): an unknown key or a placeholder differing from the source fails; a missing key is reported by family and does not fail. The loader refuses a message outside the ICU subset and a duplicate key, in every catalogue |
| Fallback | A missing translation falls back to the source language, never to an empty string or a key name |

### Two renderers, one catalogue

`locales/en.json` is read by both halves of the product and copied by neither: the binary embeds it
through `locales/Embed.go`, and `apps/webapp/src/lib/i18n/catalogue.ts` imports the same path — the
one place in the workspace allowed to reach out of its member for it
([project-structure.md](./project-structure.md) §2.1). The client bundles the source catalogue and
loads each other one lazily when the resolved locale asks.

Both implement **the same ICU subset**, each held by a gate:

* simple arguments, `plural` with `offset:` and `=n`, `selectordinal`, `select`, `#` inside a
  plural, nested messages in every branch, and apostrophe quoting;
* anything else — `number`, `date`, `time`, other argument types — is **refused by name** at parse
  time. A date reaches a message already formatted (§4).

Plural categories come from each platform: `Intl.PluralRules` in the browser,
`golang.org/x/text/feature/plural` in the binary. `catalogue.test.ts` parses every message of every
catalogue for the client; the Go loader parses every catalogue, embedded or overridden, and refuses
the file on the first construct outside the subset, so the refusal comes at writing or start-up,
never when a recipient reads Polish. `infrastructure/i18n/Message_test.go` mirrors `format.test.ts`
case for case.

The one deliberate difference: the client groups digits through `Intl.NumberFormat`; the server
carries no number symbols and writes a number as given (it renders only counts and limits).

**A message may use only what the subset implements**, in the source and every translation; a
construct beyond it is added on both sides first. The source phrases around plurals where it can (a
count last, after a colon).

Client-only display text lives in the same file under `app.*`; a second catalogue under `apps/` is
the one thing a source of truth must not have.

## 4. Date, time, calendar

| Topic | Rule |
|---|---|
| Storage | `timestamptz` (UTC) plus a separately stored IANA zone where local time matters to business logic (due dates, reminders, recurrence) |
| All-day due dates | `due_date_only = true`; a date without a time in the user's zone |
| Recurrence | RFC 5545 RRULE plus a time zone; DST transitions resolved via local time (09:00 stays 09:00) |
| Reminders | Relative (`-PT30M`) or absolute. **The entry's zone decides when it fires, the recipient's how it reads.** An all-day due date counts from the start of its day in its own zone (`DueDate.Anchor`); the message is rendered in the recipient's locale and zone (§1) |
| Start of week | `account.week_start` where set, else the locale's row (§6, through the same matcher, so `de-AT` reads `de`'s), else Monday. Resolved onto the actor and read by `@start_of_week`/`@end_of_week`, so two colleagues reading one saved view may each see their own week |
| Calendar weeks | ISO-8601 by default, the CLDR variant where it differs (`en-US`). A week *number* is the client's to draw; the server shows none — its only week number is the backup expiry's bucket, ISO by design |
| Non-Gregorian calendars | Display is the client's business; ICS feeds stay Gregorian per RFC 5545 |
| Working hours and holidays | Not part of 1.0; planned as a `WorkCalendar` extension |

## 5. Text: storage, comparison, search

| Topic | Rule |
|---|---|
| Encoding | UTF-8 throughout; database encoding `UTF8`. Names sort under the **query's** collation: migration `0080` defines `hubtask_name` from `und-x-icu` (ICU root — locale-independent, the same everywhere) where PostgreSQL has ICU, else from the database locale, and every name-ordered read says `COLLATE hubtask_name` (a gate holds it). No index is built on it: the lists are short, and an indexed ICU collation needs its version tracked across upgrades |
| Normalisation | Input is NFC-normalised **once, on the way in**: each text kind's domain constructor normalises through `core/port/text.Normalizer` before bounding and checking ([ADR-0056](../adr/ADR-0056-golang-x-text-and-idna.md)). A constructor without the port refuses non-ASCII text, and a gate holds every constructor to being handed one; length limits count the form a person sees. Rows keep `normalize(…, NFC)` on titles, names and bodies as a second line, and the query compiler binds every compared text as `normalize($n, NFC)`. **No backfill:** an older row keeps its bytes until its next edit |
| Length limits | In Unicode code points (grapheme clusters for title truncation in clients) |
| Uniqueness | Bucket and label names are case- and accent-insensitive per scope (`unaccent` + `lower`) |
| Sorting in the UI | Server-side `ORDER BY name COLLATE hubtask_name` for containers, buckets, labels, groups, backup targets and a query sorted by `title`; `/meta/capabilities` answers `natural_ordering`, so a client using `Intl.Collator` knows whether the server sorted the same way. `order_key` stays `COLLATE "C"`: a rank key rests on byte order |
| Full-text search | `tsvector` with a language-dependent configuration ([ADR-0034](../adr/ADR-0034-language-dependent-search.md)), chosen from `item.content_language` (default: the creator's locale), `simple` where the installation has none, CJK included. A trigger maintains the document, resolving the configuration at write time, and adds a `simple` copy at the same weights so word forms sit beside stems ([ADR-0066](../adr/ADR-0066-search-is-one-question.md)): a query is read under the searcher's configuration and still finds an entry in another. **No language is chosen when searching.** The last typed word's beginning is matched under `simple` as a prefix. No language detection. A row records its configuration; `ReindexSearch` (`POST /search:reindex`, `hubctl search reindex`) rewrites exactly the stale rows in batches and reports how many. Of the `1.0` set, `zh-Hans` and `bn` have no stock configuration in any supported PostgreSQL and use `simple` plus the trigram index |
| CJK/Thai | The `simple` configuration plus a trigram index (`pg_trgm`), so search works without word boundaries |
| Semantic search | Optional, via embeddings (pgvector) — cross-lingual ([ai-first.md](./ai-first.md) §2) |

## 6. Text direction and presentation

The server makes no layout decisions but supplies the metadata: `/meta/capabilities` carries per
supported locale `{ "locale": "ar", "direction": "rtl", "week_start": "SATURDAY",
"decimal_separator": "." }`, the week start in the account's own vocabulary (the account's value
overrides it, §4). The direction is the script's, inferred where the tag states none; week start and
decimal separator come from a table in `infrastructure/i18n` covering the `1.0` set, checked against
the browser's `Intl`, since `golang.org/x/text` exposes neither
([ADR-0056](../adr/ADR-0056-golang-x-text-and-idna.md)). A locale without a row is answered with its
script's direction, `MONDAY` and `.`, and the server logs at start which locales lack one.

Colours are carried as **tokens** (`color.red.500`), not hex values, so themes, contrast modes and
accessibility stay solvable in the frontend; custom hex values are also allowed.

### What every frontend owes

The localisation half of the binding client requirements; the accessibility half is
[`design-system.md` §10](../design/design-system.md#10-accessibility). A first-party client builds
against it; a third-party one is told about it.

1. **Speak the negotiated locale**: `supported_locales` and §2's chain (before sign-in,
   `navigator.languages` in the header's place), with the server's fallback; the catalogue is the
   server's file (§3).
2. **Render every code through the catalogue, with the fallback** of §3, in §3's ICU subset.
3. **Format with `Intl`, from the account's locale** — numbers, units, dates, times, relative times;
   sort with `Intl.Collator`, reading `natural_ordering` (§5). The API returns raw values (§7).
4. **A moment is read on the reader's clock; a due date on its own.** Instants in the account's zone
   (else the workspace's, else the browser's); a due date in its `due_time_zone`, named when not the
   reader's; an all-day date with no time (§4).
5. **The week starts where the manifest says**: the account's `week_start`, else
   `supported_locales[].week_start` — the server's `@start_of_week` answer (§4). A week number, if
   shown, is ISO 8601 unless `Intl.Locale(...).getWeekInfo()` says otherwise.
6. **The document runs the way the locale's script runs.** `dir` on the root from
   `supported_locales[].direction`; logical properties, never `left`/`right` (`design-system.md`
   §3); every component rendered in both directions on the workbench's direction axis
   ([ADR-0037](../adr/ADR-0037-component-workbench.md)). `lint-direction.js` refuses a physical
   inline side in any client tree, and an icon with a direction turns round by itself.
7. **Everything grows by 40 %.** `design-system.md` rule 4; the workbench's pseudo-locale axis finds
   a layout that breaks in German before German arrives.
8. **Truncate by grapheme cluster, count by code point** (`Intl.Segmenter`); counting UTF-16 units
   would refuse what the server accepts (§5).
9. **An entry's language is data**: `content_language`, picked from the manifest's `text_languages`;
   a language not in it is still stored and searched word by word (§5).
10. **Keyboard input follows the locale**: decimals typed with
    `supported_locales[].decimal_separator`, parsed to a raw value before reaching the contract.
11. **Names are `display_name`, whole** — no first/last split, no computed initials (§7).

A client does **not** owe language detection (§5), translating user content in place (§7), or a week
number from the server.

## 7. Other localisation-relevant points

| Point | Implementation |
|---|---|
| Names and forms of address | Only `display_name`, no split into first and last name (not culturally universal) |
| Email addresses | IDN-capable: the domain is brought to ASCII (Punycode) through `core/port/text.DomainEncoder` (`golang.org/x/net/idna`, confined to `infrastructure/text`, [ADR-0056](../adr/ADR-0056-golang-x-text-and-idna.md)) before an address is stored or looked up, so `anna@müller.de` and `anna@xn--mller-kva.de` are one account. The local part keeps its case-folding only. Without the port a Unicode domain is refused. No backfill |
| Slugs and URLs | ASCII by validation (lower-case letters, digits, hyphens), never transliterated; display is through `display_name` |
| Numbers and units | CLDR formatting in the client; the API returns raw values |
| Timestamps in events and webhooks | Always RFC 3339 in UTC plus a `time_zone` field where relevant |
| Translatable user data | User content is **not** translated in place. `AiTranslate` ([ai-first.md](./ai-first.md) §2) reads one entry in another language on request, bounded and display-only, stored nowhere |
