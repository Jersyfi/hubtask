# SC-05 — a using walk of the operators on a private installation

**When:** 2026-10-12 · **Commit:** `630015bf` plus the documents (branch `claude/sc-05-operators-and-machines`)
**Kind:** using ([README](./README.md), "How to walk") — the server built from the branch with the
web app embedded, single mode, against a PostgreSQL of its own migrated to 0135 and a mail catcher;
Chromium through Playwright, light theme, at 1280 × 900 and 375 × 812.

**Use case checks it shows:** UC-INS-04 checks 1 and 3 (the installation as the administration's
last group on a private installation, not in the menu; the hour kept over a reload), UC-INS-05
checks 1, 3, 4, 5 and 6, UC-INS-06 check 1. The acceptance of SC-05: a colleague added on a private
installation without locking the owner out.

The screenshots are in [`SC-05-2026-10-12/`](./SC-05-2026-10-12/); what the script read is
[`walk.log`](./SC-05-2026-10-12/walk.log).

## How the installation was prepared

Through the product's own operations: the setup code the server printed spent on *The Family* and
its owner `jerome@family.example`; Ada invited by the owner and her invitation redeemed from the
mail it sent; Bob invited and left invited; a service account *The shop* created by the owner.

**One step by hand:** the setup puts its owner into the operator register (SC-04), so an installation
set up today never has an empty register. The private installation this check is about is the one
that configured nothing - one set up before the register existed, or with its row removed - so the
walk's database had its single register row deleted (`DELETE FROM operator`) before the walk. From
then on the owner is the operator only as the owner of the only workspace.

## What was pressed

The owner signed in through the card; *Installation* in the administration; the password in the
step-up; *Add them* with Ada's address; a reload; *Add them* with Bob's address; *Make it an
operator* with *The shop*; *Remove* on Ada and on the owner, each left with *Keep*. Nothing was
removed. Removing, and removing oneself to the end, are pressed by
`apps/webapp/e2e/instanceoperators.test.mjs`, which reads what the screen sent.

## What was seen

- After adding Ada the register holds the owner and Ada (`walk.log`), and the reload kept the hour
  and the screen: the owner was not locked out. The same is proven against the real functions and
  journal by `test/integration/operator_roster_test.go`.
- No script error on any screen; no horizontal overflow of the page at either width.
- The owner's name is their address: the setup card asks for no name (SC-04), so the first row reads
  `jerome@family.example` twice.

## What was found

- At 375 px the register's table scrolls sideways inside its panel, as the workspaces table does
  (noted in PH-10's and SC-08's walks; older than this task).
- A read retried after a token refresh carried the refused token and signed the reader out - found
  while proving UC-INS-04 check 3, fixed on this branch in its own commit, test first
  (`packages/sync-engine/test/engine.test.ts`).
