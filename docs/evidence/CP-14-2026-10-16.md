# CP-14 — a workspace's own address in multi-tenant operation

**When:** 2026-10-16 · **Branch:** `claude/cp-14-workspace-address`
**Kind:** using ([README](./README.md), "How to walk"). A native server binary was built from the
branch with the web app embedded. It ran with `HUBTASK_TENANCY_MODE=multi` and
`HUBTASK_BASE_URL=http://hubtask.localhost:18545`, against a throwaway PostgreSQL container that was
removed afterwards. The first start's setup made the workspace `anna`, whose host is
`anna.hubtask.localhost:18545`. Chromium resolves every `*.localhost` to this machine.

The browser was the in-app browser pane at 1280 × 900. The account's language was set to English;
the signed-out cards follow the browser's language, here German.

## What it does not show

- **No sign-in was completed at a provider.** No identity provider that would accept this
  installation's client was available. The provider's return was put into the address by hand,
  with a real live state minted by the server; the code was made up, so the exchange ended in the
  provider's refusal. That the session minted on the workspace's host is the workspace's follows
  from the exchange running there: the existing sign-in tests cover it.
- **A connection and a step-up returning through the base host** were not walked, because both
  leave for the provider from a signed-in tab. The forward keeps the query whole and lands on the
  host whose `sessionStorage` holds the tab's note and its bearer (`oidc.test.ts`, the record's
  D6). The server finds such a flow only for that session, as before
  (`step_up_flow_test.go`).
- **An expired or spent state** gives the same 404 as an unknown one. `LocateOidcFlow_test.go`
  proves it, and `identity_provider_test.go` does so against PostgreSQL, the cross-tenant read
  included.
- **The mailed invitation** is proved by `DeliverNotification_test.go`; this installation had no
  mail server.

## Seen and changed

The first build answered `:locate` with `401 access.credential_required`. The route was missing
from the public routes in `presentation/rest/Auth.go`. `gate-contract`, which compares that list
with the specification, would have refused it at `make verify-pr`. It was fixed on the branch and
the walk was run again on the rebuilt binary.
