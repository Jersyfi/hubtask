# PK-02 — a person renames and removes a passkey, and the factor rule counts it

**When:** 2026-10-16 · **Branch:** `claude/pk-02-rename-and-remove-a-passkey` at `fb6ed8b5d`
**Kind:** using ([README](./README.md), "How to walk"). The server was built from the branch with the
web app's bundle embedded and run against a fresh PostgreSQL 16 (pgvector) migrated to 0163, single
mode, `HUBTASK_BASE_URL=http://localhost:18491`, mail to a local catcher; the installation was set up
with its setup code (`scripts/dev-workspace.sh --bootstrap`) for a throwaway owner. Playwright drove
Chromium, light theme, English, at 1280 × 900 and 375 × 900, with Chromium's **virtual
authenticator** standing in for the devices: a platform authenticator with user verification for the
first passkey, a USB key without it for the second. Real step-up, real verifier, real transactions,
real mail - nothing stubbed. The workspace's rule was set to `EVERYONE` through `PATCH /tenant`
behind a step-up, as the sign-in rules screen does.

**Use case checks it shows:** UC-ID-22 checks 2 (the name changed afterwards), 4, 5 and 7; UC-ID-03
check 5 beside a key is shown by the stubbed walk `apps/webapp/e2e/passkeys.test.mjs` (the app turned
off beside a key, then the last key stays) and proven by the service and integration tests.

**What was not walked:** a key that signs in after being removed - nothing signs in with a passkey
before PK-03; the row is gone, which PK-03's sign-in refuses.
