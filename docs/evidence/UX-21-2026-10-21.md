# UX-21 — jumble proposals that wait

**When:** 2026-10-21 · **Branch:** `ux-21-proposals-that-wait`
**Kind:** looking ([README](./README.md), "How to walk"). The web app was built from the branch and
walked by `apps/webapp/e2e/arrivalproposals.test.mjs` and `apps/webapp/e2e/jumbleselection.test.mjs`
in Chromium through Playwright, English, at 1280, 768 and 375 px, light and dark (`SCHEME=dark`),
against the stubbed API of `apps/webapp/e2e/fixture.mjs`. `EVIDENCE=<dir>` keeps the screenshots; a
choice of them is here.

**Use case checks it shows:** UC-JUM-07 checks 10, 11 and 12, as far as the screens go. What the
server does is proved against PostgreSQL as the application role: the arrival, the real dispatcher
round with the seed and the worker's run of the job it queued - off by default, switched off since,
the day's cap, the spent budget (`test/integration/arrival_proposals_flow_test.go`); the switch's
stored shape (`arrival_proposals_test.go`); the shared set and the picker's destinations, private
hubs and archive included (`jumble_destinations_test.go`, `private_hub_readers_test.go`); an entry
behind fifty newer arrivals (`jumble_suggestion_test.go`).
