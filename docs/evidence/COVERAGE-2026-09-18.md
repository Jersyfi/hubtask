# COVERAGE — every use case of the catalogue, and where the web client reaches it

**2026-09-18, `main` after F6-01…F6-14 (milestone F6); extended 2026-09-27 by milestone SI.** One
row per use case `catalogue.Descriptors()` returns, with the web client's answer: the
route and the control that reaches it, or *omitted* with the reason. `0.9.5` asks for this table with a column
per client; F6-15 writes the web column, and convergence (F7) adds the two shells' columns to it
(`roadmap.md`). `tools/checkdocs` holds the first column to the catalogue in both directions
(milestone-F6.md decision 16): a use case added without a row, or a row naming no use case, turns
`make gate-docs` red.

The table below is the count; it keeps no sum of its own, because every pull request that adds a
use case would change it, and two of them merged without catching up would conflict there or add up
wrong ([ADR-0083](../adr/ADR-0083-a-merge-without-catching-up.md)).

The rows milestone SI added to the operator's column are the instance layer's
([ADR-0070](../adr/ADR-0070-the-instance-layer.md)). **SI-17 built the dashboard that reaches
them**, so most of them are `reached` now; the ones that stay omitted are the *writes* to the
installation's own configuration, which ADR-0070 §5 puts where a repository records them — the file
and `hubctl admin`, with the dashboard showing what is in force.

The three reasons an omission may give are decision 16's; "nobody built it" is not a reason and
stands in the table only as the issue that will remove the row's omission — the three rows that
carried it on 2026-09-18 (#773, #774, #775) were reached the day after. Routes are the
webapp's (`apps/webapp/src/lib/routes.ts`); a control is named as its screen names it, and the
store method beside it is where the use case is called.
