# QS-08 — A new language is added

**2026-09-15, local development machine, `main` at `1800f40f` (M-13 and #604 merged).** The claim
[arc42.md §10.2](../architecture/arc42.md) makes in one line — *"a new language (Arabic, for
example) is added → only translation resources plus enabling the locale; no code change; the RTL
flag in the manifest"* — and the requirement [`i18n-l10n.md`](../architecture/i18n-l10n.md) opens
with: *the application must support every language.*

`0.8.0` built the server half of every line of that document that was not built (M-01…M-13).
M-14 is the fourteenth, and its whole job is to add a language the way an operator would and look.

| | Value |
|---|---|
| Binary | `cmd/server` and `hubctl`, run from the checkout with `go run`; roles `api,worker,scheduler,automation` in one process, `HUBTASK_TENANCY_MODE=multi` |
| Database | a fresh `pgvector/pgvector:pg16` container, migrated from empty to `0081`, the server connected as `hubtask_app` |
| The language | **`ar.json`, fourteen keys plus a note, written by an operator into `HUBTASK_LOCALE_DIR`** — the invitation and assignment families, the seeded structure, and the one sentence `hubctl` shows for a bad identifier. Not committed, not embedded, not a release: a file in a directory, and a restart |
| Catalogues embedded | `en.json` (the source), `de.json` (M-01) |
| Mail | an SMTP sink on `127.0.0.1:2525` writing every message to a file; `HUBTASK_SMTP_SECURITY=none` |
| Client | none — `hubctl`, `curl` and `psql`. The interface's half of QS-08 is `F5`'s, and the last section says so |
| Transcript | the scripted session below, `S` being the operator's directory; nine steps, none skipped |

**Method.** One script, run twice: the first run found #603 (below), the fix merged, the database
was thrown away, and the run below is the second, from an empty database. Nothing was set up by
hand between the steps; what the script did is what an operator would do. No token, no password
and no secret is in this file; the tenant and account identifiers are the walk's own.

## What each step proved

1. **The manifest lists the locale the moment its file exists**, with the RTL flag and the
   week's first day: `ar`, `rtl`, `SATURDAY` — from the catalogue files present, the embedded two
   and the operator's one (M-01, M-05). No code changed and no build ran.
2. **A workspace is provisioned in Arabic** and its seeded structure is Arabic — the hub, the
   collection, the buckets, the labels — because provisioning renders the seed codes in the
   workspace's default locale and the operator's file has them (M-01; C-09's mechanism).
3. **The invitation goes out in Arabic** to two people who have not chosen a language: the
   workspace's default, which is the second link of §2's chain. In the first run of this walk it
   went out in English — the delivery rendered in the account's own locale and nothing else, and
   an invited person has none. That is [#603](https://github.com/Jersyfi/hubtask/issues/603),
   fixed in [#604](https://github.com/Jersyfi/hubtask/pull/604) before this run, and it is the
   kind of defect only a walk finds: M-01's two-recipients test invited with explicit locales.
4. **Each person chooses a language and is written to in it, from one kind of event**: Amira
   assigns an entry to each, and Dora reads *„Review the offer" zugewiesen* while Karim reads
   *أسند إليك «Review the offer»* — German from the embedded `de.json`, Arabic from the operator's
   file, the entry's title untranslated in both, because a title is user content (§7).
5. **`Accept-Language: ar-EG` on a request that states no content language** leaves the entry
   tagged `ar-EG` — the client's own tag, region and all, negotiated against the catalogues
   present by the one matcher (M-04) and travelling on the actor into the entry's
   `content_language` (§5).
6. **`@start_of_week` is a Saturday for the Arabic workspace**: of two entries due on the most
   recent Saturday and the Friday before it, only the Saturday one is in this week. The owner has
   no `week_start` of her own; the locale's row answers `SATURDAY` through the same matcher a
   message is rendered through (M-05, M-06).
7. **`hubctl` reads the operator's file too**, under the server's own variable, and speaks the
   person's language: the same refusal in Arabic from the file and in German from the embedded
   catalogue (M-01).
8. **`natural_ordering: true`**: the labels in step 3 came back under `hubtask_name`, which on this
   image is the ICU root collation (M-08).

## What the interface still owed, and the walk that closed it (F5-14, 2026-09-16)

QS-08 was walked above for the server, `hubctl` and mail, and was **not yet true of the web app**
when it was written: `apps/webapp/src/lib/i18n/catalogue.ts` imported `locales/en.json` and
nothing else, so the interface rendered English for Amira, Karim and Dora alike. F5 built the
client's half — the `import.meta.glob` over `locales/*.json` (F5-07), the language switching from
`supported_locales` (F1's chain, made lazy in F5-07), `de.json` whole (F5-08), `Intl` throughout
(F5-09) and the RTL audit (F5-10) — and this section is the interface walked the way the server
was: the operator's file, a person switching their own language, and nothing else.

**Where.** The same binaries and the same file as above — `cmd/server` from the checkout with
`ar.json` in `HUBTASK_LOCALE_DIR`, `apps/webapp` from the checkout with the file laid beside
`en.json` and `de.json` where the client's glob reads — on the local development machine, because
the F5 change was not yet on the integration environment when this was walked: the F5 pull
requests are held until `0.9.0`'s last task lands. The walk is the same walk there; the file's
place and the person's click do not change.

**The operator's file.** The fourteen keys above plus twenty-nine of the interface's own
(`app.nav.*`, the inbox, the timeline's controls, the search, the AI ask) — enough to see Arabic
where the file has a word and the source language where it does not, which is §3's fallback and
not a defect.

**The walk, in three steps.**

1. **The manifest lists the file's language for the client too**: `supported_locales` carries
   `{locale: ar, direction: rtl, week_start: SATURDAY, decimal_separator: .}` beside `en` and `de`,
   and the profile's *Language* select offers `ar` — from the manifest, not from a list in the
   client.
2. **Karim chooses Arabic in his profile, and nothing else.** The account's `locale` becomes `ar`;
   the document arrives `dir="rtl" lang="ar"` on the next render, the navigation reads
   الرئيسية · بحث · الوارد · سلة المهملات · هذا التثبيت · إعداداتك from right to left, the wordmark
   sits at the right, the side navigation on the right, and the announcer said *Saved.* in the
   source language because the file has no word for it — which is the point: a word the operator
   did not write renders as the source, never as a key.
3. **Every route, in Arabic and right-to-left.** All thirty-one routes of the route table opened
   under `ar`: `dir="rtl"` and `lang="ar"` on every one, the navigation Arabic on every one, no
   error on any, Arabic text where the file has the code (the administration index الإدارة, the
   inbox الوارد, the timeline's أبكر · لاحقاً · العودة إلى اليوم, the entry's *اسأل الذكاء
   الاصطناعي*), the source language where it does not. The layout is the RTL audit's
   ([RTL-2026-09-16.md](RTL-2026-09-16.md)): the breadcrumb collapsing from the right, the
   board's columns starting at the right, the timeline's axis running the other way with its
   chevrons turned, `1.5` staying `1.5`, dates as `16‏/09‏/2026، 5:25 م`. Then Karim chooses
   English again in the same select, and the document turns back.

**The notifications** were Arabic since step 4 above and are unchanged by the interface.

**What the walk found.** One thing, not a defect of QS-08: the profile's *Language* select shows
the tags (`en`, `ar`, `de`) rather than each language's own name, which `Intl.DisplayNames` would
give for nothing. Filed as [#715](https://github.com/Jersyfi/hubtask/issues/715).

So "no code change" now holds for every surface: the server, mail, `hubctl` and the interface. A
language is a file, on both sides, and enabling the locale is the operator's restart.

Two smaller things the walk could not check, named rather than left out: a **translated
notification with a plural** (no shipped email has one; M-02's renderer is covered by its mirrored
tests rather than by this walk), and the **client's `Intl` formatting** of the manifest's decimal
separator (a client's business, M-13).
