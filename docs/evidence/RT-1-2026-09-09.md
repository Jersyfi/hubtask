## What the container is, and what it is not

**It is not Ollama, and not a model.** RT-1 asks a resilience question — does a stopped dependency
degrade exactly its own feature, and does it recover — and answering it needs a container that
serves the provider's wire format, can be stopped, and can be started again. It does not need a
model. Pulling one would add hundreds of megabytes and minutes to every `gate-resilience` run on
every pull request, to prove nothing this test asserts.

So the container is `nginx:alpine` with a four-line configuration answering one OpenAI-compatible
completion, and the adapter under test is the real `infrastructure/ai.OpenAiCompatible` reaching it
through the real guarded client, the real breaker and the real health registry. The image is
overridable through `HUBTASK_TEST_AI_STUB_IMAGE`, like the other two.

**Where the wire's shape is proved instead**, because this file should not be read as proving it:

* The **adapters' own suite** (`infrastructure/ai/Ollama_test.go`) is table-driven with the wire as
  its parameter, and both adapters pass it. That is ADR-0049's own countermeasure — "a second
  adapter cannot quietly behave differently" — and it covers the request bodies, the response
  shapes, the ordering, and the failure cases.
* The **scripted session** (J-16) exercises a real provider end to end against a real stack.

A resilience gate that pulled a language model to prove a socket can stop would be a slower gate
that proved the same thing.

## What it adds to the 2026-08-25 run

Two claims that could not be made with two dependencies:

**Attribution across three.** "Exactly its own feature and nothing else" is a claim about the whole
report, and it is only as strong as the number of things that could have been wrongly implicated.
During the AI outage the object storage and SMTP rows are both up and both probed, media is stored
and a message is delivered, and `hubtask_degraded_mode{feature="media"}` and
`{feature="notifications"}` are asserted at 0 while `{feature="ai_suggestions"}` is 1.

**A degradation with a timestamp, from a pool.** The AI provider is the first dependency whose
breaker is not a singleton — a provider is per tenant, so there is one breaker per endpoint — and
the health report has to answer "since when" from a set rather than from one object. It answers the
*earliest* open endpoint's moment, because that is what somebody reading a degradation is asking:
how long has this been going on. The first version of the probe answered no timestamp at all and
this test caught it.

## What it still does not cover

* **A real model's behaviour.** Nothing here says anything about what a model answers, and nothing
  should: that is not a resilience property.
* **Per-tenant attribution in the health report.** The report is the installation's view — "some
  configured provider is cut off" — and never names an endpoint, because an endpoint is a tenant's
  configuration (rule 10). A workspace's own view of its provider is a client question and is F5's.
* **The budget's refusal**, which is a quota and not an outage, and lands in J-15 with the
  refusal shape H-08 fixed.
