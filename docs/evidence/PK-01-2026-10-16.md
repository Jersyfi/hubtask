# PK-01 — a person adds a passkey

**When:** 2026-10-16 · **Branch:** `claude/pk-01-add-a-passkey` at `0872c3854`
**Kind:** using ([README](./README.md), "How to walk"). The server was built from the branch with the
web app's bundle embedded and run against a fresh PostgreSQL 16 (pgvector) migrated to 0161, single
mode, `HUBTASK_BASE_URL=http://localhost:18480`; the installation was set up with its setup code
(`scripts/dev-workspace.sh --bootstrap`) for a throwaway owner. Playwright drove Chromium, light
theme, English, at 1280 × 900 and 375 × 900, with Chromium's **virtual authenticator** (the DevTools
`WebAuthn` domain) standing in for the device: a platform authenticator with user verification for
the first passkey, a USB key without it for the second. Real step-up, real challenge, real verifier,
real transactions - nothing stubbed.

**Use case checks it shows:** UC-ID-22 checks 1, 2, 3 and 6, as far as a walk can - check 3's ten
is shown by the stubbed walk `apps/webapp/e2e/passkeys.test.mjs` and proven by the service and
integration tests.

**What was not walked:** a real platform passkey, a FIDO2 key and a U2F key (ADR-0085 §1). They need
hands at a device; they are asked of the owner on the pull request. The verifier's acceptance of a
browser's real answer is also held by `infrastructure/webauthn/Captured_test.go`, a registration
Chromium made, replayed.
