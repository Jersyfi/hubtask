# SC-38 — an installation lock turns an invite-only offered provider on everywhere

**When:** 2026-10-12 · **Commit:** `49c60e98` on `claude/sc-38-installation-lock`
**Kind:** using ([README](./README.md), "How to walk"). The server was built from the branch with
the web app embedded and ran with `HUBTASK_ROLES=api` and `HUBTASK_TENANCY_MODE=single`. It had its
own PostgreSQL, migrated from empty to 0133. The workspace and its owner were set up through the
printed setup code (`scripts/dev-workspace.sh --bootstrap`). The walk ran Chromium through
Playwright in the light theme, in English, at 1280 × 900 and 375 × 812.

**Use case checks it shows:** UC-INS-11 check 4.

**What was not walked (milestone SC, Decision 9):** no real identity provider is available to the
project. The two offered providers and the installation's lock on the ways to sign in were written
straight into the database:
- *The platform*: `GENERIC`, *Only people invited here*.
- *Contoso Entra ID*: `MICROSOFT`, *Only the Microsoft directories below*.
- The lock: `instance_setting` `sign_in.methods`, `lock_origin = INSTANCE`.

A configured provider has to answer its discovery document, which neither of these issuers does.
Nobody signed in at either provider. Everything after the database writes went through the
product.

The screenshots are in [`SC-38-2026-10-12/`](./SC-38-2026-10-12/). What the script read on each
screen is in [`walk.log`](./SC-38-2026-10-12/walk.log).

## The lock lifted

| Step | What it shows |
|---|---|
| The `sign_in.methods` row deleted | `GET /identity-providers` answers both rows `offered_here: false`, `installation_lock: NONE`. Each workspace is back on its own switch at once, and nothing was written into it. |
| `POST /auth/sessions` with the owner's password | `201` — the password is a method again |

## Found

- The password row described what switching the password off would cost even where the
  installation locks the password on. A mandated provider makes that state common. Fixed on this
  branch in `caf9b4af`, with an engine test.
- The installation screen's introduction said that no offer is ever on unless a workspace takes
  it. That is no longer true under the lock. Corrected on this branch in `49c60e98`.
- The last-way-in guard reads the workspace's own methods, not the resolved ones — #1290. Nobody is
  locked out, because the fallback catches it.
