**2026-09-16, local development machine, `task/f5-10-rtl-audit` on `task/f5-09-intl` (F5-01…F5-09

## The workbench: 199 stories, every one at `dir=both`

**Summary.** 175 stories mirror to the pixel. 24 list a difference, and every one is read below:
21 are inline elements — a `code`, a `span`, an icon — inside an *English* sentence, which the
bidi algorithm lays out as a left-to-right run wherever the paragraph runs, and which an Arabic
sentence would not show; the three `CodeBlock` stories keep `direction: ltr` by design, because
code runs one way whatever the page does. **Three were findings, all the same one:** the
`Switch`'s checked knob travelled *beyond* its track in the `rtl` pane, and `DueDateControl` holds
a switch. The cause is below (§ "What was found"); it is fixed in this pull request, and the three
stories mirror to the pixel now.

## What was found

1. **Three `padding-left` in the application** — the list of what a copy left behind
   (`DuplicateDialog.svelte`, `TemplatesDialog.svelte`) and the template editor's tree
   (`TemplateEditor.svelte`). All three indented from the left whatever the document did. Now
   `padding-inline-start`. The design system's own conventions test had the rule since F1-05; the
   application had no gate for it, which is the next finding's reason.
2. **No gate over the application.** `build/lint-direction.js` now refuses a physical inline side
   — `padding-left`, a bare `left:`, `float: right`, `text-align: left`, a physical corner radius,
   a signed `translateX`, a physical resize cursor — in every `.svelte`, `.css` and `.html` file
   under `apps/` and `packages/`. Its selftest plants fourteen violations and thirteen logical
   spellings; the conventions test asserts the selftest before applying the rule to every
   component's whole source, and `pnpm lint` in the design system, the webapp and the website runs
   it. A line that has to name a side carries `design-system-lint-ignore` with its reason.
3. **Icons with a direction did not turn round.** ADR-0041's set had no mark for it — the backlog's
   "the `mirrored` mark ADR-0041's set provides for" described a provision that did not exist.
   `build/icons.js` now declares `MIRRORED` (the arrows, the chevrons, `external-link`, `log-out`,
   `panel-left`), the generated `base.ts` carries it, `icons/index.ts` adds the two marks that
   draw a flow (`automation`, `dependency`), and `Icon` flips a mirrored glyph under
   `[dir='rtl']`. The three call sites that flipped a chevron by hand (`Breadcrumb`, `SideNav`,
   `TaskRow`) no longer do — two flips cancel.
4. **`:dir(rtl)` does not match what the workbench renders.** The `Switch` asked `:dir(rtl)` for
   its knob's travel, and the `rtl` pane showed the knob beyond the track: Chromium 152 does not
   match `:dir()` on an element inserted *after* its ancestor's `dir` attribute was set — which is
   every element the workbench renders into a pane, and every element the application renders
   after the manifest arrives and turns the root round. `Switch` and the new `Icon` rule ask
   `[dir='rtl']` instead, as the rest of the package already did. A probe: a fresh `div` appended
   under a pane whose parent matches `:dir(rtl)` does not match it.
5. **Nothing in the application's scripts reads a side.** No `ArrowLeft`/`ArrowRight` without the
   direction, no `scrollLeft`, no `clientX` arithmetic that assumes a side (`dragging.svelte.ts`
   measures distance, not direction).

Nothing was left as an issue: every finding is fixed in the pull request that carries this file.

## What this does not show

- Arabic *content*. The entries, hubs and collections of the walk carry English titles; the
  interface's own words were Arabic for the forty-three codes the operator's file held. A walk
  with an Arabic workspace would show the same layout with fewer bidi runs.
- Firefox and WebKit. One engine was walked; the `:dir()` finding is Chromium's, and the fix does
  not depend on it.
- The pseudo-locale and 200 % zoom together with `rtl`. The axes exist; this walk held them at
  their defaults.
