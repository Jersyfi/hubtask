**When:** 2026-10-13 · **Commit:** `00be810b` (branch `claude/sc-15-walk`)
**Kind:** using ([README](./README.md), "How to walk"). The installation came up with the reference
stack `deploy/docker/compose.yaml`: the image was built from this commit with `docker build -f
deploy/docker/Dockerfile` (one minute, cache warm), started with `docker compose up -d` under its
own project name. The `.env` is `.env.example`'s required three secrets plus the port (18510), the
operations port (19510) and the base address. **No SMTP** (`HUBTASK_SMTP_HOST` empty;

## What was found

1. **An enforcing instance file with a refused value hangs the start instead of stopping it.**
   With `legal.accessibility_url: ftp://…` in enforce mode the value was not written, but the
   process logged no refusal and did not exit: `/readyz` answered `starting` for over two minutes,
   the container reported *healthy*, the API served pages and `/auth/sign-in-rules`, and the
   worker logged 141 `dependency_unavailable` warnings (claiming jobs, sampling the queue) while
   `/meta/health` called PostgreSQL *ok*. The same start with a valid file was ready in four
   seconds. `cmd/server/main.go` says such a file "should stop the start". UC-INS-09 check 6's file
   door therefore refuses the value but says so nowhere an operator reads (log in
   `walk.log`). → `finding`
2. **Installation → AI and Defaults → AI speak of offered models on a private installation.**
   UC-AI-06 check 8 says that in D1 "none of this appears: there is no 'offered model'". The
   workspace's screen holds to it, but the D1 owner's *Installation* section has *AI* with
   "The AI models this installation offers every workspace… Offer a model" (step 21), and the
   defaults editor offers *The offered model or their own* and *Only the offered model* — the
   latter would leave the only workspace with no AI at all while nothing is offered. → `finding`
3. **The proof dialog for the hour calls it irreversible.** *Prove it is you* reads "This one is
   irreversible, so Hubtask asks again before it happens." when raising the session for an hour
   (step 7), which is not irreversible. → `finding`
4. **Locked and open limits read the same on the workspace's *Limits*.** Entries was locked (*not
   go higher*); every row, Entries included, reads "The installation's default" (step 19), where
   UC-INS-09 check 5 asks for "set by the installation" where locked. *Sign-in* draws the
   difference (step 17). → part of the same `finding` as 5
5. **Small wording on the defaults.** The language choices are the codes `en` and `de`, on the
   installation's and the workspace's screens; the storage limit is bare bytes
   (`10737418240`) on *Limits*, and `hubctl admin settings show` prints it as `1.073741824e+10`;
   a locked field on *Sign-in* says "Set by the installation for every workspace." twice; the
   overview counts "0 of 18 switches decided" where *Defaults* counts "0 of 35 settings"; the
   phone's drawer cuts the row to "Applies to every workspace …".
6. **Vocabulary a private person meets.** *Limits* says "Raising a limit is the operator of this
   installation's to do… Ask whoever runs it." to the person who runs it; the overview shows
   *Suspended* and *Being deleted* counters and the journal's introduction names suspension and
   deletion, which a single installation cannot do (no control is offered, so UC-INS-07 check 4
   holds). deployments.md says D1 never has to learn *operator*.
7. **Seen, not judged here:** Sam (member) typing `/administration/workspace` gets the
   administration's navigation and the workspace's form filled in, with *Save* (nothing was
   saved). Which administration screens a member may read is not a check of this walk.
