# SC-13 — a using walk of an invitation on an installation without mail

**When:** 2026-10-12 · **Commit:** `d8dba932` (branch `claude/sc-13-invitations-without-mail`)
**Kind:** using ([README](./README.md), "How to walk"). The server was built from that commit with
the web app embedded. It ran with **no `HUBTASK_SMTP_HOST`**, so `/meta/capabilities` answered
`features.mail: false`, and with `HUBTASK_TENANCY_MODE=multi` so that `scripts/dev-workspace.sh`
could provision the workspace. Its database was its own PostgreSQL 16 (pgvector), migrated to 0127
and reached as `hubtask_app` (row level security in force). The workspace was `home` ("Our home"),
whose owner is `anna@home.example`. The browser was Chromium through Playwright, light theme, at
1280 × 900 and at 375 × 812 (a phone, touch).

**Use case checks it shows:**
- UC-ID-14 check 5: no mail is sent, the link is shown once, and the link works exactly like a
  mailed one.
- UC-ID-14 check 6: an address that was already invited gets its own sentence.
- UC-ID-07 checks 2 and 3, seen with the link that was handed over.

The screenshots are in [`SC-13-2026-10-12/`](./SC-13-2026-10-12/).

## What was pressed

- *Create the invitation link* three times: Bert, Clara, and Dora at 375 px. Each press made one
  `POST /accounts:invite` and the role's `POST /memberships`.
- *Show the link*, the acknowledgement, and *Done*.
- In Bert's browser, *Set the password and sign in*.
- *New invitation link* on Clara's row (one `POST /accounts/{id}:renew-invitation`).
- *Create the invitation link* again with Clara's address, which was refused.

## What was seen

- **The database after the walk:**
  - no `notification.invitation` job at all;
  - three `account.invited` entries and one `account.invitation_renewed` entry, each with
    `delivery: LINK`;
  - no entry in the trail containing `hbt_inv_`;
  - `auth.invitation_redeemed` for the owner's own provisioning and for Bert.
- **After *Done*:** the page's markup no longer contained the token.
- **No script error** on any screen.
- **The card names the installation's host.** It reads "to localhost:18413", the host the link
  names, because in multi mode the base address is the installation's. A mailed link would show the
  same. The card names neither the workspace nor the address: that is #1289, which SC-13 does not
  change. On a single-workspace home server, the base address is that workspace's own.
- **The refusal is drawn at the top of the page.** The already-invited sentence is the page's
  failure banner, above the table and away from the form, like every other refusal on *People*.
  The live region announces it.

## Not walked

- **A provider sign-in through the link.** No real identity provider is available to the project
  (milestone SC, decision 9). Instead, `TestAnInvitationWithoutMailIsALinkThatWorksLikeTheMailedOne`
  shows the link's token is the one the provider's start looks up, and
  `apps/webapp/e2e/signin.test.mjs` shows the card handing the token to the provider.
- **An installation with mail.** The engines test `invitationlink.test.mjs` covers it, and so does
  the integration test `TestAnInvitationWithMailQueuesTheMailAndAnswersNoLink`.
