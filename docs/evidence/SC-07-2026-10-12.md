## What was pressed

- On *Defaults*: every one of the 34 keys was set from its own control, five of them locked, then
  *Save*. Nothing else was sent.
- Afterwards, `GET /admin/settings` answered all 34 keys exactly as sent. Counts came back as
  numbers, flags as booleans, the ways in as a list (`walk.log`: "saved differently: 0"). The week
  start's row holds the ISO number `7` (`instance_values_test.go` proves the stored shape).
- The instance journal's entry for the save names the localisation and quota keys among what moved,
  never a value.

The same six refused values went to two doors:

| Value | `hubctl admin settings set` | An enforcing instance file at start |
|---|---|---|
| `sign_in.min_length twelve` | "That is not a value this setting takes." | `auth.policy_value_invalid [switch=sign_in.min_length]` |
| `sign_in.min_length 3.5` | the same | the same |
| `localisation.week_start WEDNESDAY` | the same | `auth.policy_value_invalid [switch=localisation.week_start]` |

## What was seen

- No script error on any screen, at either width.
- No sideways scroll at 375 px on the form, the table or the workspace screen.
- No key as the contract spells it, and no value as the contract spells it, on the defaults screen.

## What was found, and fixed on the branch

- **The keys were drawn in the order of their names.** A JSON object carries no order, so the sign-in
  rules read alphabetically, not in the groups the workspace's own screen uses. Each key now answers
  its `position`, and the screen draws by it (`49ad5cf5`, with tests). The screenshots above are of
  the fixed build.
- **An empty string among the enum values of `default_week_start`** gave the generated workflow
  nodes an option without a name, and their build refused it (`ca596aad`).

## What was not walked

- A file in `enforce` mode serving a valid level. The engine test shows that state: the path is
  named and no control is drawn.
- A second workspace provisioned under the installation's defaults. That a new workspace starts with
  the installation's language and zone is `ProvisionDefaults_test.go`.
