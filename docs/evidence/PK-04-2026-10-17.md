# PK-04 — a security key as the second factor, the fresh proof and the setup

**When:** 2026-10-17 · **Branch:** `claude/pk-04-security-key-factor` at `385ca4e79` (plus the locale
for the session list's label)
**Kind:** using ([README](./README.md), "How to walk"). The server was built from the branch with the
web app's bundle embedded and run against a fresh PostgreSQL 16 (pgvector) migrated to 0176, single
mode, `HUBTASK_BASE_URL=http://localhost:18500`; the installation was set up with its setup code for a
throwaway owner, Bert. Playwright drove Chromium, light theme, English, 1280 × 900, with Chromium's
virtual authenticator standing in for the device: a USB key **without user verification** - presence
only, as a key without a PIN. Real challenges, real verifier, real transactions - nothing stubbed.

**Use case checks it shows:** UC-ID-21 checks 5, 6 and 9 (the key's button), UC-ID-22 check 8.
UC-ID-21 check 8's factor half (keys still serve with `PASSKEY` switched off) is proven by
`KeyFactor_test.go`; the keyboard and the status region by `apps/webapp/e2e/keyfactor.test.mjs`.

**What was not walked:** a real security key and a real platform passkey - the browser's own prompt is
answered by the virtual authenticator without drawing. Asked of the owner on the pull request.
