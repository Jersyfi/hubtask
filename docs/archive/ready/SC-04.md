## 3. Decisions

- [x] D1 **The setup is one public use case.** `SetUpInstallation` in package identity (it opens the
  session through `SessionWriter`, as redemption does), routed at `POST /auth/installation:set-up`,
  public, in the auth rate class. The seeding is `ProvisionTenant`'s, extracted into one exported
  method both call, so a set-up workspace is the same as a provisioned one; identity reaches it
  through an interface wired in `cmd/server`. Decided by worker. Rejected: provision + redeem as two
  calls — two transactions, and a half-set-up installation between them.
- [x] D2 **The register's refusal names the register, and the check fails closed.** The actor carries
  the administrative scopes the register withheld; `RequireScope` answers
  `access.operator_register_required` (403) for one of them. A register that cannot be read drops the
  scope and marks it, and the admin route answers `access.operator_register_unreadable` (503). Decided
  by worker (UC-INS-03/5, P-11). Rejected: refusing the whole request at authentication — the token
  keeps doing everything else it names (ADR-0005).
- [x] D3 **The `operator` pseudo-workspace.** The scripts no longer create it; no migration or job
  deletes an existing one (deleting could remove data irrecoverably — an owner-list item); UC-INS-12
  check 5 is met by the census not counting a workspace that holds no `USER` account as a customer.
  `is_operator` is left unchanged and keeps counting every workspace. Decided by the coordinator,
  2026-10-12.
- [x] D4 **The census answers six numbers in one statement.** `instance_census()` gains
  `workspaces_service_only`; the three status counts exclude those workspaces; the overview shows the
  sixth as one line ("1 workspace holds only service accounts"), so the screen still adds up with the
  workspace list (UC-INS-12/1). Dropped and created in one transaction; the query names its columns,
  so an older pod reads the new function. Decided by worker.
- [x] D5 **The code on the console, not in the log stream.** At start the code is written as a
  one-time banner straight to standard error, not through the structured logger, so the logger's
  redaction and its "the log contains no token" test stay as they are. security.md states it as the
  one deliberate secret on the console with a threat row T-24: whoever can read the container's
  output can set up an empty installation — the same person who could reach its database; 30
  minutes, single use, only its hash stored, every row deleted on setup, rate-limited, 60 bits.
  Decided by the coordinator, 2026-10-12. The gate is unchanged.
- [x] D6 **Several processes, several codes; renewal by restart.** Each process with the `api` role
  issues its own code; every unexpired, unspent one is valid; the claim serialises the setups and
  the loser answers `setup.already_done`. An expired code is renewed by restarting Hubtask, and the
  refusal says so. Decided by the coordinator, 2026-10-12. Rejected: one shared code — a second
  process would have to print a code it did not issue, or invalidate the first.
- [x] D7 **Single mode's short name** is derived from the workspace's name (lower case, letters and
  digits, hyphens; `workspace` when nothing usable remains). It routes nothing in single mode and the
  operator may rename it later through `/admin/tenants`. Decided by worker (P-10).
- [x] D8 **Where the person is signed in.** The session pair lives per origin (`sessionStorage`), so
  the person stays signed in at the address they set up from — in multi mode the installation's own
  host, which an authenticated request may use. The card's success says the workspace's own address.
  Decided by worker. Rejected: carrying the session to the subdomain in the address — a credential in
  a URL (identity.md §14.4).
- [x] D9 **Live warnings in the health report.** The registry gains a warning source evaluated per
  report under a deadline: an empty register on more than one workspace (counted as `is_operator`
  counts), the `HUBTASK_OPERATORS` entries still waiting, and "could not be checked" when the read
  fails. A narrow function answers the numbers. Decided by worker.
- [x] D10 **`HUBTASK_OPERATORS`** is a comma-separated list of `workspace:address` (a short name
  holds no colon), e.g. `acme:ada@acme.example,demo:bob@x.eu`; in single mode a bare address is
  accepted too and means the one workspace, since the operator never chose its derived short name
  (D7). Applied at start and on the scheduler leader's tick at most once a minute; a malformed list
  refuses to start. An entry adds; removing it removes nothing. Decided by worker (UC-INS-02's story).
- [x] D11 **The machine door** is `hubtask operator add --workspace <slug> --email <address>` in the
  server binary: the server's own configuration and connection, the `RestoreOperator` use case
  (no scope: the door is the machine; not in the registry, so no web route can reach it), the journal
  label `machine`, output and refusals rendered from the catalogue in the installation's default
  language. Decided by worker (UC-INS-03, *Where it ends*).
- [x] D12 **The smoke tests and scripts.** `dev-workspace.sh --bootstrap` takes the setup code
  (`HUBTASK_SETUP_CODE`) and performs the setup; it then mints the control plane's token through the
  API with a step-up. `compose-smoke.sh` (both modes) and `hubctl-e2e.sh` read the code from the
  container's output and set up through the route; their reminder and drill fixtures are written
  through the API where they can be, and `psql` stays for reading assertions only.
  `sync-engine-conformance.sh` (a conformance test, not a smoke test) keeps its SQL seed and becomes
  a `finding`. Decided by worker.
- [x] D13 **Corrections of the task text** (milestone SC-04): "Migration 0108's … sentence corrected"
  becomes "ADR-0070's and identity.md §19's" — a merged migration never changes (rule 12); and
  multi-tenancy.md §1, domain-model.md §2 and deployment.md §2.1 are corrected about how a single-mode
  tenant comes to exist. Correction, coordinator 2026-10-12.

Open for the owner: none.
