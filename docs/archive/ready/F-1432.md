## 3. Decisions

- [x] D1 The client learns which issuer paths are shared from the preset (`shared_issuer_paths`:
  first path segments, as `PersonalIssuerPaths` spells them; an issuer is shared when its first
  segment is one of them; non-empty exactly where `supports_templated_issuer` is true; the domain's
  one list feeds both the check and the answer), not from a copy of the server's list — decided by: worker; a screen that guesses the server's
  policy is wrong the day it moves. Rejected: drawing the field under `ANY` whenever the preset
  supports a templated issuer (it would be ignored on a directory's own issuer).
- [x] D2 A shared issuer's field is required in every mode the form draws it in; under
  `INVITED_ONLY` the existing optional hint becomes the required one for a shared issuer — decided
  by: the server's rule (§ 1, first row).
- [x] D3 The renewal lives in the members dialog, on the row of the invited account, for a reader
  who manages the workspace's members — decided by: worker; there is no listing of invitations, and
  the dialog is where a hub's invitee is shown. Who may renew stays as the server has it —
  `MANAGE_MEMBERS` on the workspace, as for inviting at all; a hub's manager can invite nobody
  either, so renewing at the invitee's scope would be a new permission (rejected; not this fix).
  Drawn on every `INVITED` row, inherited ones too: the server ignores the scope. Rejected: a list of pending invitations on *People*
  (needs a new read of every account, a contract change for a convenience).
- [x] D5 Only the list a form draws is sent — decided by: worker; a list nobody can see must not be
  saved.
- [x] D6 Out of scope, reported as a finding: `ANY` stays offered on `/common` and `/consumers`,
  which the server refuses (`provisioning_personal`); leaving it out needs the personal paths in the
  contract too — decided by: worker.
- [x] D4 No ADR — decided by: worker; both follow existing rules (ADR-0071 §3, identity.md §12).
