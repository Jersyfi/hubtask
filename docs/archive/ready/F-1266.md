## 3. Decisions

- [x] D1 One table of route templates in the middleware (`shownOnceRoutes`, method and contract path)
  marks every answer of those routes as shown once, beside the handler's header — decided by: worker.
  The class is a property of the operation, and one table can be held to the contract by a test;
  marks scattered over twenty handlers cannot. The header stays for the one conditional case (an
  invitation shows a link only where no mail goes) and the two start-password handlers keep theirs.
  Rejected: a header in each handler (no test could find a missing one short of driving every
  handler); `x-` extension in the contract (a contract change for an internal storage rule, rule 11's
  order for nothing a client reads).
- [x] D2 The contract test's credential fields are a fixed list (`token`, `secret`, `client_secret`,
  `access_token`, `refresh_token`, `pending_token`, `step_up_token`, `recovery_codes`,
  `start_password`, `owner_redemption_token`, `invitation_link`, `otpauth_uri`, and a top-level
  `code`), found at any depth — nested objects, `allOf`/`oneOf`/`anyOf`, arrays — with the conditional
  invitation routes exempt by name and reason — decided by: worker, from § 1's survey.
- [x] D3 The rows already stored are purged by a migration that empties `response_body` of every
  `idempotency_key` row whose `endpoint` is one of the marked templates, and deletes no row — decided
  by: owner, comment on #1266 ("purge the rows already stored"), the form by the worker. It leaves the
  key and its status, which is exactly what the new code stores for those routes, so no replay the
  guarantee promises changes beyond what this pull request decides anyway; and it reaches the
  workspaces the sweep never visits (§ 1). The table's row level security is forced, so the
  migration gives itself a policy for its statement where the migrator is neither superuser nor
  BYPASSRLS, as 0019 does. Rule 12: an old pod writing a marked body during the rollout leaves a row
  the sweep removes after a day; nothing reads the column's absence as an error. Backups taken
  before keep what they hold; said in the pull request.
- [x] D6 `provisionTenant` keeps its replay body, named in `rest.ShownOnceKept` with the reason —
  decided by: worker, keeping what UC-INS-06 check 3 promises today. UC-INS-06 check 3 ("answers the same result both times") is
  held by `gate-compose` (`scripts/compose-smoke.sh`), which replays the provisioning and reads the
  workspace's id; a body-less replay fails it, and the owner's words on #1266 name tokens, secrets and
  codes, not provisioning. So the owner's redemption token (single use, fourteen days) stays in the
  replay record until the record goes. Whether to store the body without the token instead (the
  reviewer's alternative) changes what a replay answers, so it is the owner's; it is raised in the
  pull request and nothing waits on it.
- [x] D5 A repeat of a marked route answers the status with no body — decided by: owner, #1266 (the
  comment: the middleware "completes the key with the status and keeps no body"; "fixing this finding

  decided it for start passwords. So UC-INT-10 check 8 ("answers the first result") and UC-INS-06
  check 3 ("answers the same result both times") hold for these routes as the status, nothing created

  survive a replay — is named in the pull request for the owner, not built.
- [x] D4 Documents: api-guidelines.md §5's idempotency row gains "an answer that carries a credential
