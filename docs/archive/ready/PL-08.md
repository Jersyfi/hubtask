## 3. Decisions

- [x] D1 Statement-level triggers on `work_item` (insert, delete), `media_object` and `account`
  (insert, delete, update — every update, since PostgreSQL allows no column list beside transition
  tables; one whose delta is 0 writes nothing) keep, per workspace and UTC day, `value` = the day's highest and `closing` = its last
  count, by the statement's delta from its transition tables; the day's first write recounts once
  (`count(*)`, `sum`, `count_people()`) and takes the count before the statement as the day's start.
  "Written where the count changes", every path at once, no job visiting workspaces — decided by:
  worker; no single door exists (§ 1); the record's review chose deltas over a count per statement.
- [x] D2 The counts are recorded always; only offering them is the switch — decided by: Decision 18
  (recording and offering are two things), #1555 (offering is opt-in); counts are `NON_PERSONAL`.
- [x] D3 Metrics are the ledger's names: `items`, `media_bytes`, `accounts` (`HIGHEST`, UTC day),
  `ai_tokens_per_day`, `ai_own_tokens_per_day` (`SUM`, the workspace's day),
  `automation_runs_per_hour` (`SUM` of the runs metered, throttled ones included, UTC day) —
  decided by: worker; one vocabulary with the quotas.
- [x] D4 `final_through` is the last date ended in every zone: the day before the UTC date twelve
  hours ago — decided by: worker; UTC-12 is the earliest zone.
- [x] D5 The installation ledger `usage_archive` has no row policy and no foreign key, keyed by the
  bare id, grants `INSERT, SELECT, DELETE`; named in multi-tenancy.md §2.1, `rlsExceptions` and the
  restore drill's list in the step that creates it — decided by: multi-tenancy.md §4.3.
- [x] D6 The read is `admin_usage()`, `SECURITY DEFINER`, through the owner's own `SELECT` policy on
  `usage_record` (0159's pattern); the sweep is `sweep_usage()` with the owner's `DELETE` policy, run
  daily by the scheduler's leader — decided by: rule 3; the precedent's bail-out without a bypass is
  why the policies are the owner's own, not a bypass.
- [x] D7 The switch is `metering` on the installation level beside `blocklist_file` (key
  `metering.enabled`), off by default, no lock; `hubctl admin settings set metering on|off` —
  decided by: worker; it is the installation's alone.
- [x] D8 The read pages by workspace and bounds the range to 366 days — decided by: worker;
  api-guidelines.md §4 (listings page).
