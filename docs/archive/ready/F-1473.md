## 3. Decisions

- [x] D1 The stores throw a failed page (`if (next.status === 'failed') throw next.error;`), as
  `audit.more` does. `failed` is the only answer besides `ready` (§ 1), and it carries a
  `TransportError` for a refusal, a server fault, a timeout and offline alike, which `renderProblem`
  renders; a page from the replica cannot occur on these paths; the view catches it, renders it with `renderProblem` and passes it as
  `failedLabel`; it clears at the next press and on a filter change — decided by: worker, the
  pattern F-1447 set (PR #1459). Rejected: a failure state kept in the store (a second shape for
  the same answer the other four lists already give).
- [x] D2 `PrivacyView` and `WebhooksView` get the same fix, each in its own commit, named in the
  pull request — decided by: worker, AGENTS.md "a finding outside the task is fixed on the branch
  where the rules allow"; it is the identical defect, found while checking this one. Rejected: a
  further `finding` issue for a two-file change of the same kind.
- [x] D3 No `endLabel` for these four lists — decided by: worker; today the button vanishes at the
  end, the issue asks only for the failure, and an end sentence is a copy question for each list.
  The audit trail keeps its own.
- [x] D4 No ADR — the rule exists (`apps/webapp/AGENTS.md`, `design-system.md` §4).
