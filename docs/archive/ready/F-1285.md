## 3. Decisions

- [x] D1 Personal accounts are admitted only by invitation, for every provider — decided by: owner,
  2026-10-12, #1284 → UC-ID-09 check 1, UC-ID-11 check 2 (already on `main`).
- [x] D2 Stored rows are held at arrival, not migrated — decided by: worker. A domain rule reads a
  personal account (no directory, or a directory the preset names as personal) under `DOMAINS` and
  `ANY` as under `INVITED_ONLY`: admitted only where an account here already holds the authoritative
  address, never provisioned. `MayProvision` takes the arriving identity for that. Rejected: a
  migration rewriting stored rows (it would change an administrator's configuration without them,
  and a `DOMAINS` row listing the personal directory beside company ones would lose nothing it should
  keep — the reading above already does exactly that); refusing only at configuration (stored rows
  would go on provisioning strangers, which is the defect).
- [x] D3 What a personal account is lives in the preset table as data: `PersonalDirectories`
  (Microsoft: the documented id) and `PersonalIssuerPaths` (Microsoft: `common`, `consumers`) —
  decided by: worker, following the table's own rule ("adding a fourth is adding a row"). Google
  needs neither and is unchanged: its personal account carries no `hd`, so `DOMAINS` never admits
  it, and `ANY` was refused from the day it existed (`Public`). An empty directory is not read as
  personal: that would loosen a Google `DOMAINS` row with an empty list (admits nobody) into an
  invited-only one.
- [x] D6 The screen keeps offering `ANY` for Microsoft and leaves the refusal to the 422 — decided by:
  worker. The preset's modes do not know the issuer typed below them; the refusal names the issuer
  and why. Rejected: a per-issuer mode list in the presets answer (a contract change for one rare
  configuration).
- [x] D4 `ANY` is refused on an issuer that serves personal accounts; `DOMAINS` on such an issuer
  stays, bounded by the list, and the personal directory is refused in a list under `DOMAINS`/`ANY` —
  decided by: worker, from the issue's proposal. Two codes rather than reusing
  `provisioning_public`: that sentence says "anybody in the world can hold an account at {kind}",
  which is untrue of Microsoft's company-tenant issuers.
- [x] D5 Documents: identity.md §10.3 (Microsoft's row) and §10.4 (the personal directory bullet);
  the contract's two descriptions; the two locale texts — decided by: worker (corrections of a
  document stating the system wrongly). ADR-0071 §2 keeps its history; identity.md is where the rule
  lives.

Outside this task, reported to the coordinator rather than fixed: `ANY` on `/organizations` (or on
`/common` with a list) admits every work account in the world, because `MayAdmit` under `ANY` never
reads the directory list that `directories_required` demanded — the list is then "a list nothing
consults". Not a personal-account question, so not #1285.
