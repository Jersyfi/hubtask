# F-1320 — The frame asks only what the reader may read

**Task:** F-1320 · issues #1320, #1330 and #1083 (findings) · milestone "CL — A clean slate" (no Delivers line)
**Checked against:** `origin/main` at `66c1109c` on 2026-10-14
**Verdict:** ready

A finding fix, not a milestone task. The commits carry `Task: F-1320` (and `Task: #1330`,
`Task: #1083` for the issues it also closes), so `make gate-pr` reads this record. It exists because
the fix adds a field to `api/openapi.yaml` and touches more than eight files.

All three findings are one defect: the web app does not know what the reader holds on the
workspace itself, so it probes (`GET /quotas`, `GET /meta/health`) and records refusals (#1320), or
does not ask at all and draws what the server refuses (#1330, #1083).

## 3. Decisions

- [x] D1 How the client learns what the reader holds on the workspace: an additive, caller-scoped
  manifest field `workspace_permissions` — the permissions the caller holds unqualified on the
  workspace itself, from every membership there (own and through groups), resolved as `Authorize`
  resolves them and recording nothing; absent for an anonymous caller — decided by: worker. ADR-0032
  ("which area a person is offered is the manifest's answer") and the `instance.reachable`
  precedent; the vocabulary is the role matrix's columns the client already reads (UC-WRK-22 check
  7). Rejected: `administration.reachable` alone (would need a second field for the jumble's three
  gates); composing the role from `GET /memberships?scope_type=TENANT` in the client (refused and
  recorded for an auditor and a guest — the defect again — and blind to group memberships); not
  recording refusals of these reads (changes what the trail records, audit.md §4 — not a worker's
  call). The field reports the account's roles, not the credential's scopes; the contract's
  description says so.
- [x] D2 The administration's condition stays `STRUCTURE` or `READ_CONFIGURATION` held on the
  workspace — decided by: ADR-0063 decision 1, `quota/Read.go`. The frame no longer reads
  `/quotas` to learn it; *Limits*, *Runs* and the AI screen still read it where they show it.
- [x] D3 The health report is read where the reader holds `STRUCTURE` or `READ_CONFIGURATION` on the
  workspace, or the session is elevated (an operator's `admin:tenants`) — the two conditions
  `GetHealthReport.go` answers — decided by: `GetHealthReport.go:89-110`.
- [x] D4 A typed administration (or jumble) address the reader is outside of renders the frame's
  not-found page (`route.unknown`), and nothing while the manifest is not yet read for this actor —
  decided by: worker, P-05 ("a level somebody is outside of does not appear at all") and UC-WRK-22
  check 5's "answers as not found"; rejected: a sentence "you may not open this" (tells somebody
  about a level that is not theirs) and a redirect (hides that the address was wrong).
- [x] D5 The jumble (UC-JUM-01 check 7, UC-JUM-02 check 7, #1250): the row, the route and the tour
  step with `READ` on the workspace; the capture form and each entry's convert, dismiss and ask with
  `WRITE_ITEMS`; *Make a new address* with `AUTOMATION`; the comments in `JumbleView.svelte` and
  `routes.ts` corrected — decided by: owner, #1250 (2026-10-10), and the use cases' checks. Convert,
  dismiss and ask are not named in the checks; they are the same server condition as capture
  (`Settlements.go`, `Suggesting.go`), so P-05 holds for them too — decided by: worker.
- [x] D7 A role changed during a session reaches the client at the next manifest read (the four
  session transitions and the retry), as `instance.reachable` does today; until then the server
  refuses as before — decided by: worker. Reading the manifest again on a membership change would
  need the change stream to tell the client about its own memberships, which is wider than these
  findings; rejected for this fix, named in the pull request.
- [x] D8 The auditor inside the administration is offered writing controls the server refuses —
  not this fix (the guard is about who enters the area); reported as a new finding — decided by:
  worker.
- [x] D9 UC-JUM-01 *Where it ends*: "everyone with a role on the workspace reads it" becomes
  "everyone whose role on the workspace reads it" (the auditor reads no content, domain-model.md
  §3.2) — a `correction`, named in the pull request — decided by: worker (the sentence states the
  system wrongly).
- [x] D6 Documents: `domain-model.md` §3.2 (the manifest reports the caller's workspace
  permissions), `docs/design/design-system.md` §11 (the administration's condition read from the manifest),
  `automation.md` §1 (the runs screen still reads `GET /quotas` for the hour's count — unchanged,
  checked),
  `api/openapi.yaml`. No ADR: an additive field on an existing caller-scoped document — decided by:
  worker.
