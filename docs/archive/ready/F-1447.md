## 3. Decisions

- [x] D1 `$props.id()` once per component (Svelte allows one, at the top level), every id of that
  component derived from it with its old prefix (`tooltip-${instanceId}`); in `Radio` it is declared
  above the `$props()` destructuring whose `name` default uses it — decided by: worker. It is what `Table` does; a caller-given id
  was the alternative and is not needed, since none of the 21 is named from outside today.
- [x] D2 The convention test refuses `Math.random(` in every `.svelte` and `.ts` under
  `packages/design-system/src`, comments stripped, replacing the `Table`-only test — decided by:
  worker. A rule for one file was the gap #1447 found. The one copy outside the package,
  the web app's `PasswordField` (`rules-…` list id), is moved in the same step; the web app has no
  such convention test, so it is named here rather than gated.
- [x] D3 `TimelineRow.isLocked` (absent = movable, today's behaviour for every caller) — decided by:
  worker. A locked row draws no end handles, takes no drag on its bar or in the tray, and keeps its
  title as the way to open the entry; `data-locked` lets the stylesheet drop the grab cursor.
  Rejected: a component-wide `isReadOnly` (a contributor's rows differ row by row); `isMovable`
  defaulting to true (a boolean whose absence means yes reads wrong at the call site).
- [x] D4 `TimelineView` takes `changeRefusal` and `isReadOnly` from `ContainerView`, as `Board`
  does, and locks a row when either refuses — decided by: worker. One source of the verdict for
  both layouts.
- [x] D5 `LoadMore` takes `failedLabel` (resolved text): drawn beside the button and announced
  through an always-mounted `role="alert"` region; the button stays, so pressing it again is the
  retry. `CommentThread` passes it through as `loadMoreFailedLabel`. Each call site catches the
  failure, renders it with `renderProblem`, and clears it on the next press — decided by: worker.
  Rejected: a toast (detached from the list it is about); hiding the button (no retry).
- [x] D6 `audit.more` throws the failed state's error instead of returning silently, so the audit
  screen can say it — decided by: worker; it was the one reader that swallowed it.
