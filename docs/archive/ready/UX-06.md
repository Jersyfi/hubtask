## 3. Decisions

- [x] D1 The mark's geometry and forms are the owner's, as given in the review the decision cites
  (#1630, the artifact "Hubtask, lebendig", claude.ai/artifact/DSHQgwKqnCeQChUVx9whKZ): full
  (viewBox 64: the open outline path `M42 5.5H22A16.5 16.5 0 0 0 5.5 22v20A16.5 16.5 0 0 0 22
  58.5h20A16.5 16.5 0 0 0 58.5 42V30`, stroke 7, round caps; plane 26 at 15,23 r 8.5; core 12 at
  21,31 r 4; spark r 5.5 at 54,12); reduced below 24 px (outline `M42 6H22A16 16 0 0 0 6 22v20a16
  16 0 0 0 16 16h20a16 16 0 0 0 16-16V30`, stroke 9–10, no core, plane 24–26, spark r 7–8); mono
  (`currentColor`, the core knocked out of the plane); app icon (the mark at 72 % on an indigo
  rounded square, outline white); wordmark lower-case Plex Sans Condensed 700 — decided by: owner,
  #1630 → `design-system.md` §9. Where the owner gave a range (stroke, plane, spark of the reduced
  form) the worker picks one value per range by looking at the small size steps in the story and
  writes it into `mark.ts` with the reason. Step 8 names `src/mark.ts` in §9 as the geometry's home.
- [x] D2 UX-01 lands first; this branch is rebased onto `main` after UX-01 merges and before
  step 2 — decided by: the coordinator, 2026-10-21. The mark is drawn only from semantic tokens,
  never primitives: `brand.*` (D3) alias UX-01's indigo, raspberry and amber. UX-01's interim
  repointing of `Mark.svelte` and the workbench story is replaced here — the first is deleted, the
  second rewritten. Rejected: adding an `amber` family here — UX-01 owns the families.
- [x] D3 `brand.*` semantic tokens per mode — decided by: worker. Part → hue, aliasing UX-01's
  steps (the values follow UX-01 as merged; the contrast test is the authority on the step):

  | Token | Part | Light | Dark |
  |---|---|---|---|
  | `brand.outline` | the open outline (hub) | indigo, as `accent.primary` (600) | indigo, as `accent.primary` (400) |
  | `brand.plane` | the plane (collection) | raspberry, as `accent.signature` (600) | raspberry, as `accent.signature` (400) |
  | `brand.core` | the core (task) | amber 500 | amber 400 |
  | `brand.spark` | the spark (completion) | amber 500 | amber 400 |
  | `brand.tile` | the app icon's square | indigo 600 | the step the `fill` role accepts |
  | `brand.tile-outline` | the outline on the tile | white (neutral 0) | white (neutral 0) |

  Why a family of its own: a role name says what the colour is for and lets the palette move under
  it; reading `accent.primary` directly would tie the mark to whatever the button colour becomes,
  and `status.warning` for the core would make a logo say "warning". **`text.brand` (UX-01) is a
  text colour for brand words in running text; `brand.*` colour the mark's parts — neither stands
  in for the other.** Contrast roles in `test/contrast.test.js`: `brand.outline` is an `indicator`,
  3:1 against **every** surface it may sit on — `bg.canvas`, `bg.surface`, `bg.raised` and the
  canvas under each `ambient` wash — in both modes; `brand.tile` is a `fill` carrying
  `text.inverse`; `brand.plane`, `brand.core`, `brand.spark` and `brand.tile-outline` are
  `decorative`, with the reason: parts of a logotype, which WCAG 2.2 SC 1.4.11 does not require to
  meet a contrast floor (not information needed to identify a control or state), and the outline
  already carries the mark's shape at 3:1. The tab strip is the browser's chrome, outside the
  product's surfaces, so the tab icon has no contrast pair. Rejected: no tokens, literals under the
  lint exemption (today's `favicon.svg`).
- [x] D4 `Logo` is a component, not an `Icon` — decided by: worker — `Icon` is `currentColor`
  only (`design-system.md` §12) and the mark has three colours; the mono form is a `Logo`
  variant. Props: `size` (`sm`, `md`, `lg`, `xl`, from the space scale's 200, 300, 400 and 600
  steps) choosing the reduced form for `sm` (below 24 px) and the full form from `md`; `variant`
  `color` | `mono`; `wordmark` (resolved text, optional); `label` (the accessible name when there
  is no wordmark; without either the svg is decorative). The form is chosen by the size step, never
  measured. The mono knock-out is one even-odd compound path (the plane's outline and the core's,
  `fill-rule="evenodd"`), so no mask and no `id` that two instances on one page would share.
- [x] D5 `Logo` joins wave 5 (the shell), heading count 5 → 6 — decided by: worker — it is part
  of the frame every page carries; the website also uses it, as it uses other waves.
- [x] D6 The wordmark — decided by: worker. The caller's text "Hubtask", lowered by CSS
  (`text-transform`), not the string "hubtask": copying, searching the page and translation tools
  keep the name as it is written in prose, and a screen reader announces the same word either way;
  the test asserts the accessible name case-insensitively. `translate="no"` on it: the product is
  called Hubtask in every language (`AppFrame.svelte:335`). The face comes from a new token
  `fontFamily.wordmark` that names the condensed face first and directly, at `fontWeight.bold`
  (700) — not `--font-display`, whose meaning may change with UX-02's script faces. **The
  lockup in a right-to-left document:** the mark stays at the inline start and is never mirrored
  (it is not in the mirrored icon set; the spark stays top-right), the wordmark follows it in the
  inline direction. **The wordmark does not grow** with the story's +40 % text axis: a name is not
  translated; the story shows that axis and says so. Rejected: an outlined wordmark path (a second
  drawing of text the font already draws).
- [x] D7 One geometry, two outputs — decided by: worker. `src/mark.ts` holds the paths and the
  form-for-size rule; `Logo.svelte` draws it with `var(--brand-*)`; `build/mark.js`, run inside
  the package's `build`, writes exactly two standalone files into `dist/mark/`, colours from
  `values.light` / `values.dark`: `favicon.svg` (D9) and `app-icon.svg` (a 1024 square: the mark at
  72 % on the `brand.tile` square, outline `brand.tile-outline`) — the source F7's icon tool takes.
  Exported as `@hubtask/design-system/mark/*`. The mono and reduced forms, the dark form and the
  wordmark are shown through `Logo` in the story, not as files; F7 generates any further platform
  source from `mark.ts` when it needs one. Rejected: committed files with copied literals (drift,
  the website's state today); a file per form (nobody consumes them yet).
- [x] D8 The tab icon follows the system's scheme, not the device's theme choice — decided by:
  worker — the tab strip is the browser's chrome, drawn in the system's scheme; ADR-0043's choice
  governs the document, which the icon file cannot read. Rejected: swapping the link from
  `theme.ts` (a second owner of a document attribute, `apps/webapp/AGENTS.md`).
- [x] D9 The tab icon's file and how it is shipped — decided by: worker.
  * **Light by attributes, dark by one rule.** The reduced mark's light colours are presentation
    attributes (`stroke=`, `fill=`); a single `style` element holds only the
    `prefers-color-scheme: dark` override. A style the engine blocks degrades to the light form,
    never to an unstyled one. The server sends its policy on every answer, the icon included
    (`Handler.go:160`), so whether an engine applies an image-context SVG's own style under
    `style-src 'self'` is proven, not assumed: in Chromium, Gecko and WebKit, with the real
    policy on the response (step 6). **If any engine blocks it**, the worker's fallback is a single
    form for both schemes — the reduced mark on the `brand.tile` square, no `style` element — and
    the record of the pull request says so. Why an image-context SVG is outside the "no inline
    style" rule is written where that rule is enforced (`apps/webapp/build/check-csp.js`, a
    comment; `apps/webapp/AGENTS.md`, one line): the rule protects the document; an SVG loaded as
    an image runs no script and cannot style the page.
  * **Shipping.** A small Vite plugin in `apps/webapp/vite.config.ts` emits `favicon.svg` under
    its stable name — the only file from `dist/mark/` that enters `apps/webapp/dist` — and serves
    it in development; `index.html` links it with `type="image/svg+xml"`. The website takes the
    same file through a prerendered endpoint, `src/routes/favicon.svg/+server.ts` with
    `export const prerender = true`, and drops `static/favicon.svg`.
  * **No raster.** No `.ico`, no touch icon: a rasteriser would be a new dependency, the owner's.
    So a WebKit browser before release 26 (no vector tab icon) shows no tab icon, as today.
  * Rejected: `publicDir` pointed at `dist/mark` (would ship `app-icon.svg` into the binary);
    `assetsInlineLimit` inlining it as a `data:` URI (the document would change with every icon
    change, the file not cacheable on its own).
- [x] D10 The app icon has one form for both schemes — decided by: worker — it is a source for F7,
  an indigo square with a white outline that reads on light and dark launchers.
- [x] D11 Not touched, or touched only where they state the old: the workbench's own chrome
  wordmark (`Workbench.svelte:76`, chrome, not the product), `TRADEMARK.md` (names "the logo"
  generically), the compact bar (§11.2 keeps the title there) — decided by: worker; each is
  outside check 4. `site.css` stops styling `.site-mark`: the website sizes the mark through
  `Logo`'s `size`, and `Logo`'s classes are owned by `Logo` alone.
- [x] D12 The installed app's icon — decided by: the coordinator, 2026-10-21: the question is the
  milestone's, raised as decision issue #1671 (split check 4; the installed app's icon becomes
  check 5, carried by F7). It does not gate this task. Until the owner answers, UC-WRK-33's
  *Today* carries "Check 4: the installed app's icon not met — no installed app before F7
  (ADR-0031, roadmap.md); #1671".
