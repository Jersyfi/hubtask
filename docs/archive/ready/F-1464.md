## 1. Premise — what is true today

| Claim | True? | Evidence |

| The provider forms offer *Anyone* (`ANY`) for a Microsoft issuer on `/common` and `/consumers` | true | `IdentityProviderView.svelte` draws `preset.provisioning`, `InstanceProvidersView.svelte` `preset.installation_provisioning`; neither looks at the issuer for the mode |

| `personalIssuer` is a first-segment match on `PersonalIssuerPaths` (`common`, `consumers`) **or** a personal directory's id (`9188040d-…`) | true | `personalIssuer`; `PersonalDirectories` in `IdentityProviderPreset.go` — an issuer `https://login.microsoftonline.com/9188040d-…/v2.0` is refused too |

| The instance form corrects a mode the preset does not permit | true | `InstanceProvidersView.svelte`'s `$effect` moves `provisioning` to `modes[0]`; the workspace form has no such correction |

## 3. Decisions

- [x] D1 The preset answers `personal_issuer_paths`: the first path segments that make an issuer
  one serving personal accounts — `PersonalIssuerPaths` and `PersonalDirectories` together, as
  `personalIssuer` reads them; one domain method feeds both the refusal and the answer — decided
  by: worker; F-1432's D1 reasoning, a screen that guesses the server's policy is wrong the day it
  moves. Rejected: a copy of the list in the web app.
- [x] D2 Where the issuer is personal, the forms leave `ANY` out of the modes unless it is the
  current value, and while it is, say why with the server's own message
  (`identity_provider.provisioning_personal`, which names both alternatives). No automatic move to
  another mode: a stored `ANY` row still admits organisation accounts (§ 1), and which narrower mode
  a workspace wants is its administrator's choice — decided by: worker; P-05 is met by the absent
  option and the sentence. Rejected: moving `ANY` to `INVITED_ONLY` as the instance form does for a
  mode the preset forbids (it would change what a live row admits on the next save, unseen).
- [x] D3 No ADR — decided by: worker; identity.md §10.3/§10.4 already hold the rule.
