* P-11: a busy control shows progress only while the caller says it is busy; the caller ends it on

## 3. Decisions

- [x] D1 One guard for every unavailable control (`reason.ts`): capture-phase listeners on the
  control — and on its `label` for `Checkbox` and `Switch`, so the forwarded click is covered — that
  on `click` and on `keydown` of `Enter` and `Space` call `preventDefault` and
  `stopImmediatePropagation` before any caller's handler (Svelte delegates `onclick` to the root, so
  a stopped event never reaches it), and show the reason. Implicit form submission is a synthetic
  click on the default button and is stopped with it; the existing walks
  `identityprovider.test.mjs:290-299` and `instanceproviders.test.mjs:288` press `Enter` in a form
  whose save is unavailable and must still see no request. `pointerdown`/`mousedown` propagate as
  today — decided by: worker, with the reviewer (finding 1). Rejected: wrapping the caller's
  `onclick` (misses handlers on ancestors and a form's submission).
- [x] D2 `Select` shows an unavailable option's reason in the option's own text, worded by the
  caller: a prop `describeUnavailable(label, reason)` returning resolved text (a message code such
  as `{label} — {reason}` in the caller's locale). Without it an unavailable option shows its label
  and the reason as its `title`. The closed control shows the current option's label, never the
  joined text, and is sized by the labels alone (a hidden sizer), so an option's reason never
  widens it. Check 1 for a native option: the reason is visible in the place the person tries —
  the open picker — and the option is announced as unavailable by the platform; an option has no
  focus of its own to show a bubble on — decided by: worker. Rejected: a separator chosen in the
  component (a sentence fragment per locale); a list under the field.
- [x] D3 Unavailable fields stay focusable by keyboard: `aria-disabled` and the guard, never the
  native attribute. `Input` and `Textarea` stay editable to the platform and the guard refuses the
  press (which shows the reason and opens no keyboard) and every edit (`beforeinput`, `drop`; a
  composition is undone on `input` before the caller hears of it) - not `readonly`, which WebKit
  draws two pixels narrower than an editable field and which turns `Backspace` into "back" there.
  A `range`, `color` or `file` input also has every key but leaving refused. `Select` refuses the
  press and every key but leaving (its picker never opens), holds only its current option, and
  drops `required`. Their reason moves into the
  bubble at the control, like every other control — the field keeps no in-flow line, so an
  unavailable field has the height of an available one. A field locked from above says so with
  `SourceChip` (pattern 6), not with a reason line — decided by: worker, with the reviewer
  (finding 6).
- [x] D4 `Tabs` tracks focus and selection apart: the arrows move focus over every tab, an
  unavailable one included, and select only an available one (automatic activation stays for
  those). `ViewSwitcher` drops its skip loop: the arrows move focus to the next view; an available
  one is chosen as before, an unavailable one is focused and not chosen — decided by: worker,
  with the reviewer (finding 15). WAI-ARIA allows focusable disabled items in composites.
- [x] D5 The bubble is one shared part (`_Reason.svelte`) beside the control, out of flow at every
  moment — `hidden` while not showing, raised to the top layer by `anchor.ts` while showing — and
  always the control's `aria-describedby` target; for an unavailable control the reason is the only
  description it adds. It shows on mouse hover of the control or the bubble (kept while the pointer
  is over either, hidden after a grace of `--motion-attach-duration` once it left both — SC 1.4.13
  *hoverable*), on focus (`focus` caught in the capture phase: WebKit sends no `focusin` for a date
  field), and on a click or tap of the control (inside the guard). It lines up with the control's
  inline-start edge in the bubble's own left-to-right box, the text in the control's direction:
  Firefox places an anchored element centred on, or spanning towards the start of, an anchor in a
  right-to-left box a viewport's width away. `pointerleave`
  of a non-mouse pointer is ignored. It hides on blur, `Escape`, and a `pointerdown` outside control
  and bubble (listened for only while showing). `Tooltip` keeps its API and is rebuilt on the part.
  `IconButton` keeps `title` while available and drops it while unavailable, where the bubble shows

## 4. Proof and steps

**Check 1** — `apps/webapp/e2e/workbench-layout.test.mjs`, in three engines, against the built
workbench served under `style-src 'self'`. Every component with a reason has the stories *in a row
of buttons* and *in a table row*; each draws the row twice, with and without the reason. For each,
over the axis matrix of D10, the test:
1. records the box of every element on the stage except `[role=tooltip]`;
2. hovers (mouse at the box), focuses (`Tab` to it), clicks and taps (touchscreen) the unavailable
   control and asserts after each: every box unchanged to the pixel; the bubble visible with the
   reason as its text; the control focused (keyboard) with `aria-disabled="true"` and
   `aria-describedby` naming exactly the bubble; the story's counters for the caller's `onclick`
   and the parent row's `click` still zero;
3. moves the pointer from the control onto the bubble and asserts it stays; presses `Escape` and
   asserts it hides;
4. compares the two rows: same heights, same positions of the siblings — the reason takes no
   space.
It can prove the claim because it measures rendered layout in the engines the product supports,
not markup. The arrows of `Tabs` and `ViewSwitcher` are walked in LTR and RTL. `Select`'s closed
width is compared with and without an option's reason. The guard's form case is the existing app
walks of D1.

**Check 6** — the same test on the busy stories of `Button`, `Switch` and `Checkbox`: switched to
busy and back by a driver button in the story, every box unchanged, `aria-busy` set while busy,
toggling guarded. The story *Saving a setting* shows the `Toast` with *Undo* after it.

**Evidence** (Phase 2): the workbench states linked in the PR — both themes, RTL, +40 %, compact
and large — and the app walked where a `Button` with a reason is on screen (the template dialog of
the use case's story, the rule editor's arrows), with screenshots in the PR. The engine test is
named in UC-WRK-32's `checked_by:`.
