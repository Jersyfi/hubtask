## 3. Decisions

- [x] D1 Not an event: the record is written in the grant's own transaction by a notice the use case
  calls (`notification.RecordRoleGranted`), as the emergency access does — decided by: domain-model.md
  §4 ("membership changes are not events"). Rejected: a `membership.granted` domain event (it would
  appear on webhooks and the change stream, contrary to §4).
- [x] D2 The record names the grant in a new column `membership_id`, foreign key on
  `(tenant_id, id)` `ON DELETE CASCADE`; the mail reads role, scope and place at delivery — decided by:
  worker, following migrations 0096 and 0138. A role taken away before its mail went takes its
  record with it: nobody is told of a role they no longer hold. Needs `UNIQUE (tenant_id, id)` on
  `membership`, built `CONCURRENTLY` in its own migration.
- [x] D3 Category MEMBERSHIP, so the existing switch and its title preference govern it — decided by:
  the domain's comment on `CategoryMembership`.
- [x] D4 A grant to a group mails nobody — decided by: worker. Check 9 says "the person"; a group's
  members did not change, the group's reach did; a grant to a large group would mail everybody in
  it at once; and joining a group mails nobody today either. Written in domain-model.md §3.2 and in
  the code. Reported to the coordinator as a possible follow-up for the owner.
- [x] D5 Only the GrantMembership use case tells, from `Execute`'s transaction and not from `record`,
  which the managed account's creation shares — decided by: worker. The side-effect grants are
  the actor's own (the owner of a private hub they create, a provider newcomer arriving), or a
  managed account, which has no address and whose creator hands over the start password in person.
- [x] D6 A grant of a role the person already holds at that scope tells nobody: the use case asks
  `MembershipGrants.Holds` (a new repository method, one parameterised `EXISTS`) before writing, in
  the same transaction — decided by: worker. Two identical grants at the same instant may both mail;
  accepted, since the second row they leave is the open duplicate finding and a unique index there
  would first have to remove existing duplicates (deleting rows is the owner's). Rejected: reading
  `ListAt` page by page (a workspace scope can hold thousands of grants).
- [x] D7 A workspace-wide role is told too, with its own sentence — decided by: worker; check 9 names
  hub, collection and entry, and leaving the strongest grant silent would be the gap reported again.
- [x] D8 Its own job kind `notification.role_granted` with 20 attempts — decided by: the rollout
  argument of `queue.KindEmergencyAccessEmail`: a process of the previous release would read the
  record without its subject as `PrivateHubTrashed` and send that mail.
- [x] D9 The role and the place are message codes rendered in the recipient's locale and passed as
  parameters; the place carries its article (German needs the gender) — decided by: worker.
