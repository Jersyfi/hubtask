# UX-16 — One menu for an entry, and undo

**Task:** UX-16 · issue #1648 · `docs/backlog/milestone-UX.md`
**Checked against:** `origin/main` at `5f2562f02` on 2026-10-21 (UX-08, UX-02, UX-09 merged); UX-03
(#1665) and UX-04 (#1682, the frame's toast host) read from their branches and awaited before the
web-app steps; decision #1685 from its documentation pull request #1686
**Verdict:** ready

The task carries UC-WRK-28 checks 1, 3, 4, 5 and 6; check 2 (the entry page's head menu) is UX-17's
and uses the component this task builds. Most of the task is the web app: one entry menu computed
in one pure module and drawn by one component on every surface, undo on the frame's toast host,
board selection, the pane from board and timeline, and a layout the device keeps for the person.
Two pieces are not: **a deleted label cannot be brought back today** (no operation exists), so
check 3's "deleting a label … offers *Undo*" needs a new use case, `RestoreLabel`, contract first
(D7); and the bulk bar's trash can only be undone atomically with a bulk `RESTORE_ITEM` (D9). The
long press is the owner's decision #1685 (ADR-0088): a still hold opens the entry menu on release,
*Select* first; a hold that moves drags.

**P-05**: an action is listed only where `mayDo`/`holds` and `supports` permit it; a state refusal
on a single entry keeps its reason; a read-only area lists only what it permits; *Undo* is offered
only where the inverse is permitted (the same permission as the act), and off with its reason when

**P-03**: undo never deletes; the trash and the labels dialog stay the second way back.
Known traps: *a live region created already filled is not announced* — the host's status region is
mounted empty (UX-04 D8); *`Handler.Invoke` skips validation* — every restore refusal through
`registry.Invoke`, the router and MCP; *the registry refuses an undeclared input key* — the
controller test through the router (`include_deleted`); *a capability test can ask itself* — the
menu tests assert literal item lists per role; *splitting a screen breaks what pointed into it* —
the `data-tour` anchors on list rows and the layout switch, and `Alt`+arrow handling on the list
and board, are kept and re-asserted by the existing walks; *the integration tests share one
database* — tenant B, own collections; *a count needs the plural form* — every count message;
*a drag is measured* — the still hold against the moving hold is walked with touch (`hasTouch`) on
list, board and timeline; *a read-then-write without a lock* — `SetLabelRestored` is one
conditional `UPDATE … WHERE deleted_at IS NOT NULL`, the name index decides the race with a create;
*`engine.reset()` clears every subscription* and account change — the toast stack is cleared on
sign-out and on an account or workspace change (D8).
Two writers at once: the toast's undo of a trash meets a second person's restore — `:restore` is
idempotent per deletion; a label restored while another takes its name — the index refuses the
later writer (`labels.name_taken`); two restores of one label — the second changes nothing and
announces nothing.

## 3. Decisions

- [x] D1 One pure module computes the menu, one component draws it — decided by: worker.
  `lib/entries/entryMenu.ts` returns the `MenuItem[]` for an entry from a context (role verdicts,
  manifest support, archival and area, the level when known, the surface's extras);
  `EntryMenu.svelte` draws the ⋯ trigger and wires right-click, the menu key and the still hold;
  `EntryActions.svelte` owns the dialogs the items open (dates, person, labels, share, move,
  duplicate) once per screen. It lives in `apps/webapp`, not the design system (its `AGENTS.md`: the
  component knows the manifest). The list's `everyItem`/`menuItems` move into it unchanged in
  meaning. Rejected: a menu per surface sharing helpers — today's drift.
- [x] D2 Order and groups — decided by: worker, from check 1's order, §11.8's "trash last and alone"
  and ADR-0088's "*Select* first": *Select* · *Open* · *Mark as done*/*Reopen* · *Dates* · *Person* ·
  *Labels* | rank ×4 · inside · out · to another collection | the board's *Move to <column>* (§11.9
  keeps it as SC 2.5.7's alternative) | *Duplicate* · *Share* · *Copy link* | *Archive* | *Move to
  the trash*. *Select* is listed only where a bulk bar acts (list, board) and for a writer.
- [x] D3 Right-click, the menu key and the still hold open the same `Menu` at its ⋯ — decided by:
  worker. The design system's `Menu` gains an exported `open(index)` that focuses the first item
  when opened from outside its trigger (design-system step 5, with a story and an engine walk); the
  `contextmenu` event (`preventDefault`) and the `ContextMenu` key or `Shift`+`F10` on a focused
  row call it with the first item focused. A right-click with `Shift` keeps the browser's own menu
  — for a pointer-initiated event only; `Shift`+`F10` from the keyboard always opens ours.
  Rejected: a point-anchored context menu, which needs a new overlay mode (`anchor.ts` has none).
- [x] D4 The long press — decided by: owner, 2026-10-21, #1685 → ADR-0088, `design-system.md`
  §11.9, UC-WRK-28 check 4 (supersedes ADR-0063 decisions 8 and 13; touches `ux-inventory.md` §E5
  "Keyboard and pointer … hold on touch, long-press" and "Board … selection by Ctrl-click and
  long-press"). A still 300 ms hold on a coarse pointer opens the entry menu **on release**; a hold
  that moves past the threshold drags (list grip, board card, timeline bar). The drag helper
  decides on release, not when the timer fires (`dragging.svelte.ts`, `Timeline.svelte`'s
  pointer handling), so one gesture cannot both drag and open. The list's hold-to-select goes.
- [x] D5 Who sees *Share* — decided by: worker. Sharing grants a role on the entry, which asks
  `MANAGE_MEMBERS` along the path (`MembersDialog.svelte:134`); listed only where `holds(role,
  'MANAGE_MEMBERS')` — OWNER and ADMIN in the shipped matrix, not MEMBER. Label deletion and
  restore ask `STRUCTURE` (OWNER, ADMIN). *Copy link* for everyone who reads.
- [x] D6 The level and the role where the surface has neither — decided by: worker. List, subtree
  and board know the level and the reader's role. Search and the timeline read on opening the menu
  the entry's level (`items.query` scoped to the parent, manual order) and its parent; search also
  opens the reader's role along each hit's path with the hits (`people.open(path)`, as
  `ContainerView` does for its own), so the menu's role answer is ready when it opens. Until then
  rank, inside and out are off with `app.move.moving` and the writes are not drawn (role
  undetermined → open and copy link only). Rejected: leaving rank and move out of those surfaces,
  which check 1 forbids.
- [x] D7 **A deleted label can be restored** — decided by: worker; the coordinator's ruling on the
