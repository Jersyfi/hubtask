## 3. Decisions

- [x] D1 The faces — decided by: owner, 2026-10-20, #1625 → `design-system.md` §3, milestone UX
  Decision 5.
- [x] D2 What the coverage test reads — decided by: worker. One committed data file,
  `packages/design-system/fonts/faces.json`, lists each shipped face: family (and the name to
  rename from), package, stylesheets, the subsets kept, the weights and their declared ranges, the
  ISO 15924 scripts it covers, the Unicode blocks it may serve (D4), and a sample of each script's
  letters. `fonts.js` builds from it (one list, not two). Two tests hold it: a **Go test** in
  `infrastructure/i18n` (`ScriptFaces_test.go`) maps every row of the `1.0` table and every
  catalogue the binary embeds to its script (`language.Make(tag).Script()`, as the direction does)
  and requires a face for it in the file; a **design-system test** (`test/fonts.test.js`) requires,
  for every listed script, that each sample code point lies in the `unicode-range` of a face of that
  family in the built `dist/`, that the family is in the `ui` and `display` stacks of
  `tokens.json`, that every `@font-face` has a `unicode-range` and only `url(./fonts/…)` sources
  (no `local()`, no scheme), that no script face's range leaves its blocks, and that each package
  has its licence row and notice (D9). The Go side reads x/text's CLDR likely subtags, the client
  (D5) the browser's `Intl.Locale.maximize()`; both are CLDR, and for the eleven tags they agree
  (`Latn`, `Hans`, `Deva`, `Arab`, `Beng`, `Cyrl`). A difference for a rarer tag would change which
  heading stack applies, never whether a face is shipped. Rejected: a JS test reading `locales/`
  (a second reach out of a member, `project-structure.md` §2.1) and a hand-kept list of the eleven
  tags in JS (the trap).
- [x] D3 IBM Plex Sans SC from `@ibm/plex-sans-sc` 1.1.0, without `@ibm/telemetry-js` — decided
  by: the coordinator, 2026-10-21 (the only distribution of the face #1625 approved). The telemetry
  package is removed through the workspace's `overrides` (`'@ibm/telemetry-js': '-'`) and SC's
  `postinstall` refused by `allowBuilds: { '@ibm/plex-sans-sc': false }` in `pnpm-workspace.yaml`
  (pnpm 11's setting; with `strictDepBuilds` an undeclared script would fail the install instead).
  `fonts.test.js` reads `pnpm-lock.yaml` and fails if `@ibm/telemetry-js` appears under `packages:`
  or `snapshots:`, and separately if the override or the `allowBuilds` entry is gone. Verified by a
  clean `pnpm install --frozen-lockfile` and a build of the image's `ui` stage. Only the split,
  hinted woff2 files and the per-weight stylesheets are read. Rejected: committing the files (git
  history), fetching them at build time, Noto Sans SC (another face than the owner chose).
- [x] D4 Separate families, each limited to its script's blocks — decided by: worker, the blocks
  after the review (F2). Each script face keeps its own family name (`IBM Plex Sans Arabic`, …,
  `IBM Plex Sans SC`, `Noto Sans Bengali` — Fontsource's "Noto Sans Bengali Variable" renamed by a
  per-face `rename` in `faces.json`, as fonts.js already renames Plex Sans). The three stacks in
  `tokens.json` gain them after the Latin cut: `display` = Condensed, Plex Sans, the script faces,
  system-ui, sans-serif; `ui` = Plex Sans, the script faces, Noto Sans, system-ui, sans-serif;
  `mono` = Plex Mono, Plex Sans, the script faces, ui-monospace, monospace. Only each package's own
  script subset is kept (`arabic`, `hebrew`, `devanagari`, `thai`, `bengali`, SC's chunks), and
  fonts.js intersects every `@font-face`'s `unicode-range` with the face's blocks in `faces.json`
  and drops a file left with an empty range: Arabic U+0600–06FF, 0750–077F, 0870–08FF, FB50–FDFF,
  FE70–FEFF; Hebrew U+0590–05FF, FB1D–FB4F; Devanagari U+0900–097F, A8E0–A8FF, 1CD0–1CFF; Thai
  U+0E00–0E7F; Bengali U+0980–09FF; SC: CJK Unified Ideographs U+4E00–9FFF and Extension A
  3400–4DBF, CJK Symbols and Punctuation 3000–303F, Halfwidth and Fullwidth Forms FF00–FFEF, CJK
  Compatibility 3300–33FF. So an arrow, a Greek letter or a dotted circle on an English page never
  reaches a script face (SC's first chunk carries Greek and arrows). Bengali's danda (U+0964) is in
  the Devanagari block and is served by the Devanagari face, as the Unicode standard shares it.
  Rejected: registering the script files under the family `IBM Plex Sans` — the variable face
  declares `100 700`, the static faces single weights, and a browser matches weight before
  `unicode-range`, so Arabic at 450 would fall past the family.
- [x] D5 Headings in a script the condensed cut lacks — decided by: worker. Glyph by glyph the
  `display` stack already falls to Plex Sans at the heading's own weight (check 2). So that a
  Russian or Arabic heading is not set half condensed (digits, punctuation) and half regular width,
  `applyDocumentLocale` also sets `data-script` (the locale's script,
  `new Intl.Locale(tag).maximize().script`, D2 for the CLDR note) on the root beside `lang` and
  `dir` — the same owner, the same fact — and `fonts-scripts.css` sets `--font-display` to the `ui`
  stack on `[data-script]:not([data-script='Latn'])`. Timing: `adopt` runs at boot from the browser's
  languages and again when the manifest arrives, so `data-script` changes exactly when `lang` does;
  a Russian reader whose browser asks for `en` sees condensed headings until the manifest has been
  read, as `lang` says `en` until then. Rejected: a `:lang()` list (a hand-kept list of languages,
  wrong for the next one an operator adds).
- [x] D6 Weights — decided by: worker; SC's by the coordinator, 2026-10-21 (F1). Static script
  faces (Arabic, Hebrew, Devanagari, Thai): 400, 500, 600, 700; the 400 file is declared

  declared `400 500` and SemiBold declared `600 700`; body, `medium` and regular text use the
  regular cut, and a Han heading at 700 uses the 600 cut, the nearest cut that ships (the browser
  does not embolden a face whose declared range contains the weight). Noto Sans Bengali: the

  as it does today for any glyph outside Plex.
