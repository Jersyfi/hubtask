So this file records **what a reader would be given**, not what one said. The reader pass proper
is the next assessment; the website's statement says so, dated, and this file is the one it
points at until then.

## The rows, as the tree answers them

| Row | What was looked for | What was found |
|---|---|---|
| 4.1.2 Name, role, value | Every control's name, role and state | 676 controls over 31 routes, every one named; 378 icons, every one hidden from the tree beside its label; roles native (`button`, `a`, `input`, `select`, `summary`) or the five ARIA ones the design system uses on purpose (`radiogroup`/`radio` for the layout switcher, `treeitem` for the workspace tree, `menu`/`menuitem`, `switch`, `region` for a scroll region); states through the native attribute or `aria-checked`, `aria-expanded`, `aria-current`, `aria-busy` |
| 1.3.1 Info and relationships | Headings, lists, tables | Above: one `h1` per route (asserted by the residue test since F5-11), sections as `h2`/`h3` in order, lists of `li`, tables with `caption` and `th` |
| 1.1.1 Non-text content | Every `Icon` named or silent | Every icon `aria-hidden`; none bare. An icon-only control carries its name on the control (`IconButton`'s `label`), which is where a reader looks |
| 3.1.2 Language of parts | `lang` on an entry in another language | The item route: `h1[lang=pt-BR]` and `p[lang=pt-BR]` on an entry whose `content_language` is `pt-BR` (F5-06) |
| 3.3.1 Error identification | A refusal read with its field | A field's refusal is the field's `error` (rendered by `Input`/`Select`/`Textarea` through `aria-describedby` and `aria-invalid`); a form's refusal is a paragraph with `role="alert"` beside the form (F5-12) |
| 4.1.3 Status messages | A live region heard once, not twice | One announcer (`status/polite`) in the frame; a `Banner` is its own `status` or `alert`; the two upload panels each keep an empty polite region for their progress. No message is written to two of them: the announcer is the only thing `announcer.say` writes, and a banner's text is not repeated into it |

## What was found

1. **The main navigation was named after its first link.** `<nav aria-label="Home">` — a reader
   of landmarks would hear "Home navigation" beside a "Home" link. Named `Sections`
   (`app.nav.label`, in `en` and `de`).
2. **The application had no way to the accessibility statement.** The frame gains a footer with
   the one link out of the application, to `hubtask.eu/accessibility/`, in a new tab and labelled
   as such.
3. **The website's page had no statement.** It gains the standard (EN 301 549 / WCAG 2.2 AA),
   the status as this pass found it (*partially conformant, assessed by the makers*; the reader
   pass not yet run), the known exceptions with their dates (the reader pass; #711's missing
   lift; the reader's own content), who assessed it and how, and the date — with the sentence
   that reserves *published* for the first stable release, as §10 asks.

Nothing else: the tree is what the walks before it left it.

## What this does not show

- **A reader's voice.** Everything above is what a reader is handed, not what it said; the
  order in which VoiceOver reads a card, whether NVDA announces a `switch` as one, how Orca
  handles the tree's arrows — all unheard. The next assessment.
- The dialogs' insides, the menus' items and the popovers, which the tree holds only while they
  are open; the keyboard walk entered and left each one (`A11Y-keyboard-2026-09-16.md`).
- Firefox and WebKit's trees. One engine.
