# ADR-0057 — The SDKs: which packages, under which licence, extracted or not

**Status:** accepted · **Date:** 2026-09-16 · **Decided:** 2026-09-17, the licence part; the names and the extraction stay open

## Context

[ADR-0027](./ADR-0027-monorepo-structure.md) deferred one decision to before `1.0.0`: "extracting
the generated SDKs into a separately licensed repository". Its reason still holds word for word.
[ADR-0013](./ADR-0013-licensing.md) puts this repository under BSL 1.1, whose Additional Use
Grant reserves commercial production use; a client library under that licence is one a company
may not link into a product it sells, and a client library nobody may build on is not an SDK. So
`packages/api-client` has been kept "free of anything but generated output so that the extraction
stays a move rather than a rewrite" — a discipline the package's own `CLAUDE.md` restates.

Milestone `0.9.0` builds three SDKs (P-02, P-03 in
[`milestone-0.9.0.md`](../backlog/milestone-0.9.0.md)): a Go client generated by `oapi-codegen`
into `sdk/go/`, and a TypeScript and a Python client generated by `tools/sdkgen` into
`packages/api-client/dist/` and `sdk/python/`. Each lands under the repository licence with a
`BUSL-1.1` SPDX header, because a task does not change the licence model
([`CLAUDE.md`](../../CLAUDE.md) § "What you do not decide yourself"). This ADR is where that
decision is put to the owner, with the three questions it decomposes into. Nothing in the
milestone waits on the answer: the packages are generated, tested and usable inside this
repository either way.

Three facts bound the decision:

* **The Change Date applies per version** ([`licensing-editions.md`](../architecture/licensing-editions.md)):
  every release becomes Apache-2.0 four years after it is published. An SDK version therefore
  *does* become permissive — four years after anyone wanted it.
* **The generated types are shared with the first-party clients.** `packages/api-client`'s types
  are what `apps/webapp` compiles against through the sync engine. Whatever is extracted, the
  types stay here too, regenerated from the same document, or the first-party apps would depend
  on a second repository's release cadence.
* **Publication is an account somebody owns** — npm, PyPI, a Go module path resolves to a
  repository — and the milestone deliberately publishes nothing. The licence question is asked
  now because a published package's licence cannot be changed retroactively for the versions
  already fetched, so it has to be right before the first one.

## Options

**A. Apache-2.0 for the three SDKs, kept in this repository under `sdk/` with their own
`LICENSE` files, published from here.** The Change License ADR-0013 already names, applied early
to the one kind of code whose value is in being linked into other people's products. A directory
can carry its own licence file and SPDX headers; `go-licenses` and the licence gate already read
headers per file. Publication stays one repository, one release workflow, one version
(ADR-0035). What it costs: the BSL's Additional Use Grant would have to say in one sentence that
`sdk/` is excluded, and the licence check that asserts every source file is `BUSL-1.1` learns one
directory's exception.

**B. Apache-2.0, extracted into one repository per language.** What ADR-0027 imagined. Cleanest
for a consumer — `go get github.com/Jersyfi/hubtask-go` fetches a module with nothing but the
client in it, and `pip install hubtask` carries no `BUSL` file anywhere. What it costs: three
repositories, a release step per product release that pushes generated output across them, a
version each that ADR-0035 would have to be amended to permit, and a place where the generated
code and the specification can drift by one release.

**C. Stay under BSL 1.1, extract nothing, publish nothing.** The status quo, made explicit. Honest
about what the SDKs are for now — the reference client the walk uses and a third party's starting
point in a checkout — and it leaves the ecosystem row half kept: a connector package built on an
SDK nobody may ship in production is a connector nobody ships.

**D. MIT.** Equivalent to A in every way that matters here and different from the Change License
ADR-0013 chose; two permissive licences in one repository is one more thing to explain.

## Decision

**Proposed: A.** Apache-2.0 for `sdk/go/`, `sdk/python/` and the generated TypeScript client, in
this repository, with per-directory `LICENSE` files, SPDX headers of `Apache-2.0` on every file
under `sdk/`, one sentence in the Additional Use Grant, and the licence gate's exception written
as the directory. B is the fallback if a consumer's tooling turns out to choke on a module inside
a BSL repository; it is a move of what A produces, which is what keeps it a fallback rather than
a fork in the road.

**Waits on the owner.** Until the status is `accepted`, every SDK file carries `BUSL-1.1` and the
`sdk/` `LICENSE` files are absent; P-02 and P-03 land that way and say so in their pull requests.

## Consequences

* The three SDKs exist, are generated on `make generate`, and are tested against the in-process
  server from `0.9.0` on, whatever the status of this ADR.
* When accepted: `LICENSE` in `sdk/go/`, `sdk/python/` and beside the TypeScript client's
  generated output; `NOTICE` names the split; `licensing-editions.md` §2 gains the sentence; the
  licence check gains the directory; the SPDX headers are rewritten by the generators, which is a
  one-line change in each.
* Publication is a separate decision with a separate owner action each time: an npm scope, a
  PyPI project, and — for Go — nothing, because the module path is the repository.
* The TypeScript *types* stay `BUSL-1.1` and first-party; only the generated client class is
  covered. The client imports the types (`operations` from `dist/schema.d.ts`) rather than
  carrying a second copy of them — P-03 chose that over a self-contained file, because a
  second type generator is a second description of the contract — so an extraction takes the
  client *and* regenerates the types beside it under the SDK's licence, from the same document.
  That is the one place the two licences meet, and it is a regeneration rather than a copy.

## Amendment — 2026-09-16, what P-02 found building the Go client

Two things the cut could not know. The contract names schemas `SyncPullResponse` and
`SyncPushResponse`, and `oapi-codegen` names an operation's decoded answer
`<OperationId>Response` — `syncPull`'s answer collided with its own body. The generated answer
types therefore carry the suffix `Result` (`CreateWorkItemResult`), set in
`sdk/go/oapi-codegen.yaml`, which no schema of the contract uses; a consumer reads
`res.JSON201`, `res.StatusCode()` and `res.Body` on them exactly as before. And the hand-written
half is one file, `hubtask.go`, under sixty lines including its comments: a bearer editor, an
idempotency editor, an `If-Match` editor, and `Check`, which turns a transport error or a non-2xx
answer into a `*ProblemError` carrying the decoded problem document. That is the whole of what
an extraction would carry beside the generated file, which is the size this ADR hoped for.

## Amendment — 2026-09-16, what P-03 found building the other two

`tools/sdkgen` reads the document once and writes both: the TypeScript client into
`packages/api-client/src/client.gen.ts` — committed, the generator being Go and the Node lanes
having none — and the Python package into `sdk/python/hubtask/`. Neither output has a runtime
dependency: `fetch` and `urllib`. The TypeScript client is typed against the `operations` types
`openapi-typescript` generates, which is where the consequence above changed. The Python client
takes a body as a `TypedDict` from `types.py` and answers `dict`s; the query and the headers are
keyword arguments. Both are driven against the in-process server — the TypeScript one by the
package's own test, the Python one by `test/contract` through whatever `python3` the runner has.

## Decision — 2026-09-17, the licence part accepted by the owner

**A, for the licence; the rest stays open.** Decided in
[ADR-0059](./ADR-0059-licensing-phases-and-licensing-start.md) §6, with the scope drawn a little
wider than the proposal above: Apache-2.0 for `sdk/go/`, `sdk/python/`, the generated TypeScript
client and its example in `packages/api-client`, the contract `api/openapi.yaml` (and the
`api/openapi.json` generated from it), the event schemas under `api/events/`, and the n8n
community node package of [ADR-0058](./ADR-0058-connector-packages.md). Not for the first-party
types the project's own apps compile against; the file boundary inside `packages/api-client` is
ADR-0059 Appendix B. The Zapier app is not named and stays under the repository licence.

Two details differ from the consequences written above. The sentence excluding the Apache-2.0
files went into the *Licensed Work* parameter of `LICENSE` rather than into the Additional Use
Grant — the grant says what may be done with the Licensed Work, and the parameter says what the
Licensed Work is, which is where an exclusion belongs. And the Change Date is three years, not
four: the context above misread `licensing-editions.md`, and the number was never four anywhere
else.

**Still open, and deliberately:** the package names (an npm scope, a PyPI project) and whether
any SDK is extracted into a repository of its own. Nothing is created for either; B remains the
fallback it was.

Later the same day the owner closed the one boundary this left ragged: the TypeScript client
moved out of `packages/api-client` into `sdk/typescript/`, a workspace member that generates its
own types from the document and depends on no first-party package — the regeneration the
consequence above described for an extraction, done in place — and the Zapier app joined the n8n
node under Apache-2.0 (ADR-0059, amendment of 2026-09-17). Every SDK now sits under `sdk/`, as
option A first imagined.
