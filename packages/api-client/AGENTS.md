# packages/api-client — generated, and nothing else

TypeScript types generated from `api/openapi.yaml` by `make api-client`, plus the contract document
itself for the website's API reference. Why it holds nothing hand-written is in
[`README.md`](./README.md).

## What must not happen here

* **No hand-written type.** An interface, a hand-built type alias or a runtime export under `src/`
  fails `pnpm lint`. A missing type is missing from the contract: change `api/openapi.yaml`, run
  `make generate` and `make api-client`, and put both halves in one pull request (rule 11).
* **No fetch layer, hand-written or generated.** The first-party fetch layer is the sync engine's
  `Transport` port. The client for third parties is `sdk/typescript`, generated by `tools/sdkgen`
  on `make generate` and typed against its own generation of the document, not against this
  package. A component that imported the SDK could reach past the sync engine's seam, and the
  workspace map lint refuses that edge.
* **No committed output under `dist/`.** It is ignored and reproducible from the specification and
  the lockfile. Beside the types it carries `openapi.json` (copied from the `api/openapi.json` that
  `make generate` writes) and `events.json` (the CloudEvents schemas, gathered by type).
* **No dependency on anything under `apps/`.**
* **No `.go` file** (rule 14).

## How to check a change

```bash
make api-client
pnpm --filter @hubtask/api-client lint
pnpm --filter @hubtask/api-client typecheck
pnpm -r typecheck        # the consumers still agree with the regenerated contract
```
